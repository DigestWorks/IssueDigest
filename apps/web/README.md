# 웹 앱

React Router Framework mode·React·TypeScript의 한국어 이슈 조사 화면입니다. Google 로그인 후 이름이 확인된 자료를 선택해 질문하고, 서버의 AI 조사 진행 상태·저장된 Canvas 결과·인용 원문을 읽습니다. 원문 검색과 기존 자료 열람은 **자료** 메뉴에 유지합니다.

## 이슈 조사

홈의 **이슈 조사**는 보호된 `research/sources`에서 제목·의안번호·제안일·수집일을 읽어 보여 줍니다. 자료 1~3개를 선택해 직접 질문하거나 법안 카드의 **핵심 정리**를 누르면 새 조사가 시작됩니다. 두 동작 모두 명시적 POST이고 요청마다 UUID4를 하나 만듭니다. 화면 로드, 탭 전환, 새로고침, 저장 결과 열람은 모델 호출을 만들지 않습니다. 전송 응답이 불분명할 때 **같은 요청 다시 확인**은 같은 요청 ID를 사용합니다.

진행 중에는 접수→자료 찾기→분석→인용 연결 확인을 표시하고 취소할 수 있습니다. 완료 결과는 서버가 자동 저장하며 **저장한 조사**에서 다른 멤버도 다시 엽니다. 후속 질문은 완료한 조사를 부모로 보내고 선택 자료를 유지합니다. 결과의 **근거 열기**는 저장된 snapshot을 원문·인용 ID와 대조한 뒤 reader로 이동하고, reader는 원문 응답의 저장 인용을 다시 확인해 정확한 위치만 강조합니다. 모델이 만든 HTML을 실행하지 않습니다. 읽기 멤버는 저장 결과와 원문을 읽을 수 있지만 새 조사·취소는 할 수 없습니다.

POST가 503이면 AI 연결 대기 또는 일시 문제를 표시합니다. AI 실행에는 API/worker의 명시적 `ISSUEDIGEST_RESEARCH_ENABLED=1`과 서버 측 모델 키가 필요합니다. 브라우저에 키를 넣지 않습니다. 월 한도, 권한 변경, 자료 부족, 생성 실패, 취소는 각각 안전한 상태로 안내합니다. 실제 키·사용자 세션·운영 배포 검증은 별도입니다.

## 루트에서 실행

Node 24.21.0·npm 11.19.0을 선택합니다. 모든 명령은 저장소 루트에서 실행합니다.

```sh
npm ci
npm run setup
npm run dev
```

`npm run dev` 통합 실행기는 Linux에서 지원·검증했습니다. Windows에서는 `npm run dev:api`와 `npm run dev:web`을 별도 터미널에서 실행하고 각각 직접 종료합니다.

웹은 `http://127.0.0.1:5173`입니다. 웹만 실행하려면 `npm run dev:web`을 사용하고, 다른 터미널에서 `npm run dev:api`로 API를 실행합니다. 확인 요청을 접수하면 확인 중 상태와 중복 클릭 방지를 표시하고 검증된 성공·실패·재시도를 안내합니다. 시간 초과는 기본 5초이며 응답 본문 읽기도 포함합니다.

연결 확인은 같은 출처의 `/api/v1/status`를 `@issuedigest/api-client`로 호출합니다. 인증·도메인·공급자·도구 호출은 API의 책임이며 앱 내부 코드를 직접 가져오지 않습니다.

## 개발 프록시

Vite 서버가 `/api`·`/health`를 `http://127.0.0.1:8000`으로 전달합니다. 다른 API 포트가 필요하면 아래처럼 실행합니다.

```sh
uv run --package issuedigest-api uvicorn issuedigest_api.main:app --reload --host 127.0.0.1 --port 8001 --no-access-log
# 다른 터미널, 저장소 루트
API_PROXY_TARGET=http://127.0.0.1:8001 npm run dev:web
```

`API_PROXY_TARGET`은 개발 서버에서만 읽으며 브라우저 번들에 넣지 않습니다. `VITE_*`에 비밀값이나 공급자 키를 넣지 않습니다. 기본 웹 포트는 중복 사용 시 자동 변경하지 않고 실패합니다.

## 검증과 생산 빌드

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run contract:check
```

`ssr: false`인 Framework SPA 구조입니다. 루트는 빌드 때 미리 렌더링되므로 브라우저 전용 API를 초기 렌더에 사용하지 않습니다. 기본 서버 진입점의 빌드 의존성인 `@react-router/node`·`isbot`도 고정합니다. 별도 웹 서버 앱이나 배포 패키지는 추가하지 않습니다.

운영에 제공할 파일은 `apps/web/build/client`입니다. 정적 호스트·리버스 프록시에서 `/api/*`, `/health/*`를 API로 먼저 연결하고 나머지 앱 경로는 `index.html`로 연결합니다. 개발 프록시는 운영 구성에 포함되지 않습니다. 운영 배포는 아직 하지 않았습니다.

UI 테스트는 실제 화면과 공통 클라이언트를 사용하며 HTTP 경계만 대체해 확인 중·성공·실패·재시도·잘못된 계약을 확인합니다. 데스크톱·모바일·실제 API 중단 스모크 증거는 [진행 기록](../../docs/planning/progress.md)에 별도로 남깁니다. [공식 SPA 안내](https://reactrouter.com/how-to/spa)를 사용했습니다.


## 저장된 근거 링크 열기

Home의 **근거 링크**에 같은 출처의 절대 URL 또는 `/workspaces/:workspaceId/evidence/:snapshotId` 경로를 입력합니다. 두 ID는 UUID4입니다. **근거 링크 열기**는 React Router로 이동하며, 화면은 실제 보호 GET 응답으로 채웁니다. 다른 출처, query, fragment, credential, 다른 경로 형식은 거부합니다. 링크만으로 로그인이나 작업 공간 권한을 얻을 수 없습니다.

화면은 확인된 자료 제목(없으면 종류별 원문명), 공급처, 원문 출처 링크, 수집 시각, 파싱된 텍스트, 실제 페이지 번호, 저장된 인용을 표시합니다. 출처 ID는 펼쳐 보는 세부 정보에만 남습니다. 처음에는 인용을 선택하지 않습니다. 인용을 선택하면 전체 텍스트, PDF의 해당 페이지, 해당 표 셀로 이동합니다. 텍스트는 React text로 표시하며 인용 강조는 code point 위치를 UTF-16 범위로 변환합니다. 인용 선택과 페이지 이동은 추가 GET이나 모델 호출을 하지 않습니다. 인용 위치 일치는 주장 지지의 검증과 다릅니다.

쿠키 인증과 작업 공간 멤버십은 API가 검사합니다. 401은 `/login`으로 안내하고, 404는 자료 또는 권한 없음, 503 및 다른 HTTP 실패는 자료 읽기 미준비 또는 서버 문제로 안내합니다. 형식 오류, 네트워크 실패, 시간 초과도 안전한 문구와 재시도로 처리합니다. 서버 오류 본문은 표시하지 않습니다. 유효한 서버 UUID는 실패 지원 details에만 표시합니다.

경로 ID 변경, 화면 종료, 재시도는 진행 중 요청을 취소하며 이전 원문, 인용 선택, 요청 ID를 제거합니다. 늦은 응답은 화면을 되돌리지 않습니다. 기본 10초 제한은 응답 헤더와 본문을 포함합니다. 성공 자료를 대신하는 예시나 인증 fixture는 production 앱에 없습니다.

클라이언트의 표시 검증은 사용하는 필드의 타입, ID chain, 페이지와 표 셀 참조, 정확한 quote와 인접 문맥을 검사합니다. 서버의 전체 Pydantic 도메인 검증, 인증, 저장 원문의 진위, 해시 무결성, 의미적 주장 지지를 대체하지 않습니다. 상세 경계는 [API 클라이언트 README](../../packages/api-client/README.md)에 있습니다.

구현과 결합 검증을 구분합니다.

- [x] 보호 GET 클라이언트, 표시 검증, 취소와 안전한 오류 상태.
- [x] 실제 원문 읽기, 근거 링크 진입, Unicode 강조, 키보드 선택과 모바일 세로 배치.
- [x] 합성 HTTP·컴포넌트·링크 테스트와 JS lint, typecheck, build, contract 검사.
- [ ] Controller의 전체 합성 PostgreSQL 검사와 독립 리뷰.
- [ ] Controller의 실제 합성 API·브라우저 QA 및 개발 환경 인계.
- [x] Google 로그인 시작 폼·세션 확인·승인된 작업 공간 목록·로그아웃의 UI 연결과 합성 HTTP 검사.
- [ ] 사용자의 실제 자료 읽기·검색 최종 확인·운영 게시. Google 로그인 저장/공동 DB/개발 HTTPS는 연결했으며 공개 앱 배포는 유예합니다.

## 로그인과 작업 공간 자료 목록

홈은 먼저 `/api/v1/auth/session`을 확인합니다. 로딩 중에는 자료가 비었다고 단정하지 않습니다. 401이면 로그인 안내, 서버 오류·시간 초과·네트워크 실패이면 재시도를 표시합니다. 활성 멤버십이 없으면 권한 안내를 보여 주고 자료를 요청하지 않습니다.

`/login`의 **Google로 로그인**은 기본 HTML form으로 고정된 `/api/v1/auth/google/start`에 POST합니다. 제공자 화면은 Google에서 제공하며 승인 계정·검증·세션 발급은 서버가 담당합니다. 화면의 대기 상태는 이중 제출을 막고 뒤로 돌아오면 초기화됩니다. callback의 `denied`, `invalid`, `unavailable`만 고정 한국어 문구로 안내합니다. 성공 callback은 기존 계약대로 홈으로 돌아옵니다. 원래 읽기 링크로 자동 복귀하지 않습니다.

로그인한 홈의 작업 공간 선택은 서버가 검증한 멤버십을 사용합니다. 이름이 없는 계약에서는 공간을 번호로 구분하고 역할을 보여 줍니다. 자료 메뉴의 기존 목록은 `GET /api/v1/workspaces/{workspace_id}/evidence?limit=50`으로 읽고 공급처·출처 ID·수집 시각·원문 첫 160자·인용 수와 **근거 열기**를 표시합니다. 없는 제목이나 AI 결과를 채우지 않습니다. 빈 목록과 최대 50개 제한·추가 자료 존재 여부를 안내합니다. 다른 공간 선택·화면 종료·재시도는 진행 중 목록을 취소하고 이전 목록을 지우며 늦은 응답을 무시합니다.

헤더의 **로그아웃**은 보호 POST를 사용합니다. 성공하면 자료를 지우고 로그인 화면으로 이동합니다. 실패하면 기존 화면을 유지하고 재시도를 안내합니다. 브라우저가 Origin을 제공하며 JS는 토큰·CSRF 값을 만들어 보내거나 브라우저 저장소에 인증 정보를 저장하지 않습니다. 세션·목록·로그아웃의 기본 10초 제한은 헤더와 응답 본문을 포함합니다. 기존 연결 확인·수동 근거 링크는 보조 영역에서 유지합니다.

기본 개발 API는 DB나 OAuth 설정을 읽지 않아 로그인 서비스가 준비되지 않았다고 응답할 수 있습니다. 실제 사용에는 [API runtime 안내](../api/README.md)의 명시적 DB·HTTPS origin·Google client 설정과 운영자의 초대가 필요합니다. 실제 공동 DB·개발 HTTPS와 Google 로그인 바인딩/세션 저장은 확인했습니다. 사용자 자신의 자료 읽기/검색 확인과 main 운영 배포는 후속입니다. 구현 검증은 합성 HTTP·컴포넌트 테스트이며 Controller의 실제 PostgreSQL·HTTPS 브라우저 결합 검증은 별도입니다.

## 원문 검색과 위치 열기

로그인한 홈의 **자료** 메뉴에서 작업 공간을 선택하고 **원문 검색**에 공백으로 나눈 1~8개 단어를 입력합니다. 검색 버튼을 누를 때만 현재 공간에 요청하며 모든 단어가 원문에 포함된 위치를 찾습니다. 첫 화면은 출처·기간 필터를 제공하지 않습니다. 결과는 일치한 **위치** 수로 표시하므로 한 자료에 여러 위치가 있을 수 있습니다. 자료 색인/전체 수와 결과 한도를 표시하고, 미색인 자료·제외 셀이 있을 때만 각 수를 표시합니다. 후보 또는 결과 한도로 일부 위치가 빠질 수 있으면 별도 안내합니다. 일치 위치가 없더라도 미색인 자료나 제외된 셀까지 부재를 뜻하지는 않습니다.

**원문 위치 열기**는 검색 hit를 URL이 아닌 router history state로 전달합니다. 읽기 화면은 보호된 원문을 다시 가져온 뒤 작업 공간·snapshot·문서·버전·표현 ID와 출처 메타데이터, 정확한 quote·문맥·PDF 페이지 또는 전체 표 셀을 대조합니다. 일치할 때만 강조하고 초점을 옮깁니다. 일치하지 않는 상태는 고정 안내를 표시하며 원문은 계속 읽을 수 있습니다. state 없이 직접 URL을 열면 선택 없이 읽습니다. 같은 history 항목을 새로고침하면 검색 state가 유지될 수 있으며, 이때도 원문을 다시 읽고 같은 검증을 거칩니다. 저장된 인용·페이지 선택은 검색 선택을 지웁니다. 검색 선택은 저장된 인용이나 주장 지지 판정이 아닙니다.

공간 변경, 검색어 수정, 로그아웃 시작, 화면 종료에는 검색 결과를 지우고 진행 중 요청을 취소합니다. 실패 후 **같은 검색 재시도**는 마지막 제출을 사용합니다. 합성 화면·클라이언트 검사는 `npm test -- apps/web/tests/search.test.tsx packages/api-client/tests/search-selection.test.ts`로 실행합니다.

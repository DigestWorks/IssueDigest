# 웹 앱

React Router Framework mode·React·TypeScript의 한국어 B2C 브리핑 화면입니다. 질문부터 입력하고 짧은 브리핑·필요한 비교·변화·원문으로 이어갑니다. 현재 자료와 브리핑 기록은 초대된 초기 검증 참여자의 공유 자료 범위로 보호하며 개인 보관함·공개 피드는 아직 없습니다.

## 질문과 브리핑

비회원 질문은 이 탭에 최대30분 임시 보관하고 로그인 후 편집 상태로 한 번 복원합니다. 직접 **브리핑 만들기**를 눌러야 실행됩니다. 질문과 선택적 부모 실행만 전송하며 서버가 현재 접근 가능한 저장 색인에서 최대8개 검색어로 관련 근거를 최대5개 찾습니다. 수동 자료 선택·클라이언트 추천·카탈로그·자료 범위 선택기는 제공하지 않습니다. 기본 메뉴는 **브리핑·브리핑 기록**입니다(D019).

명시 제출마다 UUID4 요청 ID를 만들며 응답이 불분명할 때 **같은 요청 다시 확인**은 같은 ID/입력을 사용합니다. 화면 로드·내비게이션·새로고침·저장 결과 재열람은 모델을 호출하지 않습니다. 빈 근거의 요청 접수부터 자료 찾기→분석→인용 연결 확인을 실제 서버 단계로 표시하며 생성 취소·같은 실행 재접속·완료 실행의 후속 질문을 지원합니다. 관련 근거가 없으면 모델 호출 없이 자료 부족으로 종료합니다. 자료를 직접 고르거나 등록하라는 안내로 되돌리지 않습니다.

완료 결과는 서버가 자동 저장합니다. **브리핑 기록**은 같은 접근 범위의 초기 검증 참여자가 함께 열람하는 기록이며 개인 보관함이 아닙니다. 완료 AI 모듈은 검증된 Canvas로 표시하고 정확 인용은 같은 화면의 원문 창에서 확인합니다. 원문 창을 닫을 때 질문·초점을 유지하며 모델 HTML은 실행하지 않습니다. viewer는 기록/원문을 읽고 생성/취소는 할 수 없습니다.

현재 근거·실행/기록 요청에서401/403/404를 확인하면 Canvas·자료 제목·원문 창·질문 초안을 함께 지웁니다. 이전 실행/계정의 취소되거나 늦은 응답은 새 브리핑을 되살리거나 지우지 못합니다. 네트워크/503 실패에서는 권한 상실을 단정하지 않고 재시도를 표시합니다. 실제 AI 실행에는 서버의 명시 설정/키가 필요합니다. 웹 전체/의미 검색·최신 외부 수집·검증된 AI 모듈 점진 전달·개인 관심/알림·고정 공유·추천은 후속입니다.

## 비회원 공개 브리핑

질문 아래 실제 공개 목록만 편집형 행으로 보여 줍니다. 빈 목록은 생략하고 실패는 독립적으로 재시도할 수 있습니다. `/briefings/:slug`·`/briefings/:slug/versions/:version`은 세션 확인 없이 렌더링하고 실제 기준 UTC 시각/게시일/버전·출처/공공누리 제1유형 조건을 표시합니다. 기존 CanvasView의 요약/접기와 SavedEvidence의 정확 인용·원문 위치/초점 복원을 재사용합니다.

인용 클릭·페이지 재진입·focus/pageshow·visible 복귀는 같은 고정 공개 버전을 GET합니다.404는 브리핑과 열린 원문을 지우고, 일시 오류/503은 재시도를 안내합니다. 이전 경로/버전·닫힌 창의 늦은 응답은 무시합니다. 더 새 버전이 확인될 때만 링크를 표시하며 구판 인용을 새판으로 대체하지 않습니다. 공개 읽기는 private 근거 API·세션/모델/DBOS·비용 예약을 만들지 않습니다. 공개 질문은 표제/사용자 입력만 기존30분 탭 초안으로 홈에 전달하며 parent run이나 URL에 질문을 넣지 않습니다. 로그인 후 직접 생성해야 실행합니다.

첫 출처는 문서별 권리/전체 내용을 검토한 한국정책브리핑 공식 policyNewsView 텍스트입니다. 사진/외부 저작물과 비공개 실행은 공개하지 않습니다. 실제1건 게시/개인 개발 적용·전체 브라우저 인수는 별도 진행 기록으로 확인하며 운영/main은 유예합니다(D020).

## 루트에서 실행

Node 24.21.0·npm 11.19.0을 선택합니다. 모든 명령은 저장소 루트에서 실행합니다.

```sh
npm ci
npm run setup
npm run dev
```

`npm run dev` 통합 실행기는 Linux에서 지원·검증했습니다. Windows에서는 `npm run dev:api`와 `npm run dev:web`을 별도 터미널에서 실행하고 각각 직접 종료합니다.

웹은 `http://127.0.0.1:5173`입니다. 웹만 실행하려면 `npm run dev:web`을 사용하고, 다른 터미널에서 `npm run dev:api`로 API를 실행합니다.

자료·검색·조사는 같은 출처의 API를 `@issuedigest/api-client`로 호출합니다. 인증·도메인·공급자·도구 호출은 API의 책임이며 앱 내부 코드를 직접 가져오지 않습니다. 공용 `/api/v1/status`와 health API는 유지합니다.

## 개발 프록시

Vite 서버가 `/api`·`/health`를 `http://127.0.0.1:8000`으로 전달합니다. 다른 API 포트가 필요하면 아래처럼 실행합니다.

```sh
uv run --package issuedigest-api uvicorn issuedigest_api.main:app --reload --host 127.0.0.1 --port 8001 --no-access-log
# 다른 터미널, 저장소 루트
API_PROXY_TARGET=http://127.0.0.1:8001 npm run dev:web
```

`API_PROXY_TARGET`은 개발 서버에서만 읽으며 브라우저 번들에 넣지 않습니다. `VITE_*`에 비밀값이나 공급자 키를 넣지 않습니다. 기본 웹 포트는 중복 사용 시 자동 변경하지 않고 실패합니다.

## 검증과 생산 빌드

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run contract:check
```

`ssr: false`인 Framework SPA 구조입니다. 루트는 빌드 때 미리 렌더링되므로 브라우저 전용 API를 초기 렌더에 사용하지 않습니다. 기본 서버 진입점의 빌드 의존성인 `@react-router/node`·`isbot`도 고정합니다. 별도 웹 서버 앱이나 배포 패키지는 추가하지 않습니다.

운영에 제공할 파일은 `apps/web/build/client`입니다. 정적 호스트·리버스 프록시에서 `/api/*`, `/health/*`를 API로 먼저 연결하고 나머지 앱 경로는 `index.html`로 연결합니다. 개발 프록시는 운영 구성에 포함되지 않습니다. 운영 배포는 아직 하지 않았습니다.

UI 테스트는 실제 화면과 공통 클라이언트를 사용하며 HTTP 경계만 대체해 확인 중·성공·실패·재시도·잘못된 계약을 확인합니다. 데스크톱·모바일·실제 API 중단 스모크 증거는 [진행 기록](../../docs/planning/progress.md)에 별도로 남깁니다. [공식 SPA 안내](https://reactrouter.com/how-to/spa)를 사용했습니다.


## 브리핑에서 정확 근거 열기

브리핑의 **근거 열기**와 찾은 근거의 인용에서 원문을 엽니다. `/workspaces/:workspaceId/evidence/:snapshotId` 직접 경로도 유지하며 두 ID는 UUID4입니다. 읽기 화면은 실제 보호 GET 응답으로 채우고, 링크만으로 로그인이나 작업 공간 권한을 얻을 수 없습니다. 홈·브리핑 기록에는 연결 확인이나 수동 근거 URL 입력 도구를 표시하지 않습니다.

화면은 확인된 자료 제목(없으면 종류별 원문명), 공급처, 원문 출처 링크, 수집 시각, 파싱된 텍스트, 실제 페이지 번호, 저장된 인용을 표시합니다. 출처 ID는 펼쳐 보는 세부 정보에만 남습니다. 처음에는 인용을 선택하지 않습니다. 인용을 선택하면 전체 텍스트, PDF의 해당 페이지, 해당 표 셀로 이동합니다. 텍스트는 React text로 표시하며 인용 강조는 code point 위치를 UTF-16 범위로 변환합니다. 인용 선택과 페이지 이동은 추가 GET이나 모델 호출을 하지 않습니다. 인용 위치 일치는 주장 지지의 검증과 다릅니다.

쿠키 인증과 작업 공간 멤버십은 API가 검사합니다. 401은 `/login`으로 안내하고, 404는 자료 또는 권한 없음, 503 및 다른 HTTP 실패는 자료 읽기 미준비 또는 서버 문제로 안내합니다. 형식 오류, 네트워크 실패, 시간 초과도 안전한 문구와 재시도로 처리합니다. 서버 오류 본문은 표시하지 않습니다. 유효한 서버 UUID는 실패 지원 details에만 표시합니다.

경로 ID 변경, 화면 종료, 재시도는 진행 중 요청을 취소하며 이전 원문, 인용 선택, 요청 ID를 제거합니다. 늦은 응답은 화면을 되돌리지 않습니다. 기본 10초 제한은 응답 헤더와 본문을 포함합니다. 성공 자료를 대신하는 예시나 인증 fixture는 production 앱에 없습니다.

클라이언트의 표시 검증은 사용하는 필드의 타입, ID chain, 페이지와 표 셀 참조, 정확한 quote와 인접 문맥을 검사합니다. 서버의 전체 Pydantic 도메인 검증, 인증, 저장 원문의 진위, 해시 무결성, 의미적 주장 지지를 대체하지 않습니다. 상세 경계는 [API 클라이언트 README](../../packages/api-client/README.md)에 있습니다.

구현과 결합 검증을 구분합니다.

- [x] 보호 GET 클라이언트, 표시 검증, 취소와 안전한 오류 상태.
- [x] 실제 원문 읽기, 근거 링크 진입, Unicode 강조, 키보드 선택과 모바일 세로 배치.
- [x] 합성 HTTP·컴포넌트·링크 테스트와 JS lint, typecheck, build, contract 검사.
- [ ] Controller의 전체 합성 PostgreSQL 검사와 독립 리뷰.
- [ ] Controller의 실제 합성 API·브라우저 QA 및 개발 환경 인계.
- [x] Google 로그인 시작 폼·세션 확인·승인된 작업 공간 목록·로그아웃의 UI 연결과 합성 HTTP 검사.
- [ ] 사용자의 실제 자료 읽기·검색 최종 확인·운영 게시. Google 로그인 저장/공동 DB/개발 HTTPS는 연결했으며 공개 앱 배포는 유예합니다.

## 로그인과 자료 범위

홈은 먼저 `/api/v1/auth/session`을 확인합니다. 로딩 중에는 자료가 비었다고 단정하지 않습니다. 401이면 질문을 작성할 수 있는 비회원 홈을 보여 줍니다. 우측 계정 메뉴에서 명시적으로 로그인하거나 질문 제출·브리핑 기록/보호 자료 직접 진입 시 로그인 화면으로 이동합니다. 서버 오류·시간 초과·네트워크 실패를 비회원으로 오판하지 않고 재시도를 표시합니다. 활성 멤버십이 없으면 권한 안내를 보여 주고 자료를 요청하지 않습니다.

`/login`의 **Google로 로그인**은 기본 HTML form으로 고정된 `/api/v1/auth/google/start`에 POST합니다. 제공자 화면은 Google에서 제공하며 승인 계정·검증·세션 발급은 서버가 담당합니다. 화면의 대기 상태는 이중 제출을 막고 뒤로 돌아오면 초기화됩니다. callback의 `denied`, `invalid`, `unavailable`만 고정 한국어 문구로 안내합니다. 성공 callback은 기존 계약대로 홈으로 돌아옵니다. 원래 읽기 링크로 자동 복귀하지 않습니다.

서버가 검증한 멤버십의 첫 승인 맥락을 내부에서 사용합니다. 내부 ID·현재 역할·요청 맥락 검사는 유지하고 범위를 고르는 UI는 제공하지 않습니다. 레거시 `?view=sources`는 기본 질문 화면으로 취급합니다. 같은 맥락의 기록을 조회하며 공유 이력을 개인 이력으로 표시하지 않습니다.

헤더의 **로그아웃**은 보호 POST를 사용합니다. 성공하면 자료를 지우고 로그인 화면으로 이동합니다. 실패하면 기존 화면을 유지하고 재시도를 안내합니다. 브라우저가 Origin을 제공하며 JS는 토큰·CSRF 값을 만들어 보내거나 브라우저 저장소에 인증 정보를 저장하지 않습니다. 세션·브리핑·로그아웃의 기본 10초 제한은 헤더와 응답 본문을 포함합니다.

기본 개발 API는 DB나 OAuth 설정을 읽지 않아 로그인 서비스가 준비되지 않았다고 응답할 수 있습니다. 실제 사용에는 [API runtime 안내](../api/README.md)의 명시적 DB·HTTPS origin·Google client 설정과 운영자의 초대가 필요합니다. 실제 공동 DB·개발 HTTPS와 Google 로그인 바인딩/세션 저장은 확인했습니다. 사용자 자신의 자료 읽기/검색 확인과 main 운영 배포는 후속입니다. 구현 검증은 합성 HTTP·컴포넌트 테스트이며 Controller의 실제 PostgreSQL·HTTPS 브라우저 결합 검증은 별도입니다.

## 검색/인용 기반 reader 계약

수동 검색 화면은 제거했습니다. 보호 검색 API와 `searchEvidence`/`resolveSearchSelection` 계약은 서버 검색과 정확 원문 검증을 위해 유지합니다. 검색 hit가 router state로 들어온 reader는 보호 원문 GET 후 workspace/snapshot/document/version/representation·출처 메타데이터·정확 quote/문맥·PDF 페이지/표 셀을 대조해야 강조합니다. 위치 일치와 저장 인용·주장 지지를 구분합니다. 직접 URL은 인용 선택 없이 읽으며 저장된 인용·페이지 이동은 추가 모델 호출 없이 처리합니다.

## 브랜드·테마·로그인 진입

홈·로그인·원문 화면은 [생성 로고와 프롬프트 기록](public/brand/README.md)을 사용합니다. 테두리 없는 우측 테마·계정 SVG 아이콘은 접근성 이름·툴팁·키보드·44px 영역·포커스를 유지합니다. 테마는 시스템 선호를 기본으로 하고 명시적 선택은 `issuedigest.theme.v1`에 저장합니다. 테마 값만 localStorage에 보존하며 저장 접근이 거부되어도 현재 화면 전환은 가능합니다. 공개 게시 자료는 준비 중이고 기존 자료·조사는 계속 보호합니다. 질문 초안은 기존 제한된 sessionStorage에 보존해 로그인 후 편집 상태로 복원하며 AI를 자동 실행하지 않습니다. [수용 기준·검증](../../docs/changes/brand-theme-entry.md)을 따릅니다.

## 브리핑 화면 디자인

앱의 기본 색상·글꼴·조작 영역은 `app/styles.css`, 실제 브리핑 렌더러의 앱 전용 표현은 `app/briefing.css`에서 관리합니다. 홈과 공개 읽기는 같은 760px 본문 폭을 사용하며, 완료된 비공개 브리핑은 질문 제목→요약→접힌 상세와 정확 근거→후속 질문 순서로 읽습니다. 상세는 기존 native details, 원문은 기존 native dialog와 정확 인용 검증을 사용합니다. 기록은 초기 검증 참여자의 공유 이력이라는 설명을 유지합니다.

한국어 제목과 본문은 기기에 설치된 `Apple SD Gothic Neo`, `Noto Sans CJK KR`, `Noto Sans KR`, `Malgun Gothic`, 일반 sans-serif 순서로 사용합니다. 한국어 serif/Batang fallback은 없습니다. 새 글꼴 파일·외부 폰트 요청·의존성을 추가하지 않았으며 별도 폰트 배포 라이선스도 필요하지 않습니다. 기존 영문 브랜드 워드마크만 serif를 유지합니다.

밝은 화면의 중립 흰색과 어두운 화면의 차콜색에 작은 jade 강조를 사용합니다. 버튼과 펼침 조작은 최소44px, 입력은 모바일 확대를 피하는16px, 긴 한국어/인용은 줄바꿈을 허용합니다. 테마·계정·원문 초점 복원과 reduced-motion 지원은 동일 토큰을 사용합니다. 실제320/390/1440 화면과 밝고 어두운 테마의 독립 인수 결과는 컨트롤러가 진행 기록에 별도로 남깁니다.

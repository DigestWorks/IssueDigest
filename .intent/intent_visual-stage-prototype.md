# 시각화 스테이지 프로토타입

## 문제

IssueDigest의 핵심 정체성은 답을 **잘 보여주는 것**이다. 제품은 글을 길게 쓰는 대신, AI가 내부 온톨로지를 탐색하는 과정과 그 결과를 시각적으로 제시한다. 지역이 있는 데이터는 팔란티어 제품처럼 3D 인터랙티브 지도 위에 보여 준다.

이 표현이 실제 화면에서 어떻게 보이고 동작하는지 아직 아무것도 만들어지지 않았다. 데이터 수집과 에이전트 연결보다 먼저, 제품의 시각적 표현을 만들어 확인하고 방향을 정해야 한다.

## 원하는 결과

데스크톱 브라우저에서 실행되는 프론트엔드 프로토타입이 있고, 다음이 동작한다.

**디자인 원칙: 색상은 데이터에만 쓴다**
- 배경, 패널, 버튼, 텍스트, 지도 바탕, 경계선 등 데이터가 아닌 요소는 무채색이다.
- 깊이감은 흑백 대비, 명도 변화, 빛, 그림자로만 표현한다.
- 색은 지역별 값, 차트 계열, 그래프 노드 유형처럼 데이터를 나타내는 부분에만 쓴다.

**화면 구성**
- 좌측은 채팅, 우측은 시각화 스테이지다.
- 스테이지는 3D 공간이다. 볼류메트릭 라이트(빛내림), 파티클 효과, 피사계 심도 블러가 적용된다.

**온톨로지 탐색 시나리오**
- 질문을 보내면 탐색 단계마다 노드와 엣지가 스테이지에 추가된다.
- 현재 탐색 중인 노드로 초점이 이동하고, 나머지는 피사계 심도 블러로 흐려진다. 탐색 순서는 엣지를 따라 이동하는 파티클로 표시된다.
- 노드는 물리 시뮬레이션으로 배치되고, 드래그하면 연결된 노드가 반응한다.

**3D 지도 시나리오**
- 지역 질문(예: 서울시장 선거 지지율)을 보내면 3D 지도가 나타나고 카메라가 서울로 이동해 확대한다.
- 자치구 면이 값에 따라 색으로 칠해지고 압출 높이로 올라온다.
- 사용자는 확대·축소, 회전, 기울이기, 이동을 할 수 있다.
- 지도 표현은 `docs/design/3d-map-concept.md`를 따른다.

**결과 시각화**
- 답변이 끝나면 차트, 타임라인, 주장 비교 같은 결과물이 스테이지에 등장 애니메이션과 함께 배치된다. 모든 다이어그램은 등장 애니메이션을 가진다.
- 채팅의 답변 텍스트는 짧고, 주장을 선택하면 스테이지 초점이 그 근거 노드나 지역으로 이동한다.

**구조**
- 스테이지는 정해진 이벤트 형식(노드 추가, 초점 이동, 지도 표시, 결과물 배치 등)을 받아 그린다. 프로토타입은 미리 작성한 시나리오 이벤트를 재생하고, 이후 실제 에이전트가 같은 이벤트를 보내도록 연결한다.

## 영향 범위

- 새로 만드는 것: React Router + TypeScript + shadcn 프론트엔드 앱, 스테이지 이벤트 형식, 샘플 시나리오
- 참고하는 것: `docs/design/3d-map-concept.md`, `docs/research/2026-10-11-poc-feasibility.md`, `agent-chat-framework` 채팅 컴포넌트
- 결정 권한: 민재

## 제약

- 프론트엔드 스택은 기획 결정을 따른다(React Router, React, TypeScript, shadcn). 3D 렌더링·물리·후처리 효과 라이브러리와 지도 경계 데이터는 spec에서 공식 문서와 라이선스를 확인해 정한다.
- 샘플 데이터는 화면에 샘플임을 표시한다. 실제 인물·정당 이름에 만든 수치를 붙이지 않고, 후보 A·B·C처럼 가상의 이름을 쓴다.
- 시각 효과가 데이터 판독을 가리지 않아야 한다. `prefers-reduced-motion`이 켜져 있으면 애니메이션과 효과를 줄인다.
- 외부 파일 다운로드(지도 경계 데이터 등)는 실행 전에 파일·출처·크기를 알리고 허락을 받는다.

## 범위 밖

# 지도 기반 디자인 스타일 재정의

## 문제

3D 지도(`/map`, `stage/schematic/map/*`)는 여러 번의 피드백을 거쳐 IssueDigest 에서 가장 완성도 높은 화면이 되었다.
현재 스타일 가이드(`/style`, `design/guide.ts`, `docs/design/style-guide.md`)는 지도 이전에 정한 규칙(흰 배경, 무채색 UI, 주황 금지, 무광 기호 노드 등)이 그대로 남아 있다.
지도에서 확정한 표현과 충돌하는 규칙이 같이 있어 다음 화면을 만들 때 기준으로 쓸 수 없다.

## 원하는 결과

지도에서 확정한 시각 언어를 IssueDigest 전체의 디자인 스타일로 다시 정의한다.

- 스타일 정의: 지도에서 뽑은 원칙을 장(章) 단위로 다시 쓴다.
  - 장면: 어두운 모드 기본과 밝은 모드, 바닥 조명, 중심에서 옅어지는 격자
  - 선: 가는 선과 불투명도 단계, 맨 위 선 강조, 측정 주석(꺾쇠·좌표 눈금·축척·출처)
  - 색: 데이터 색은 답과 관련된 일부에만 쓰고 나머지는 중립색, 주황은 선택·초점에만
  - 부피: 수평 층 묶음(홀로그램), 선택 시 층 간격 확장
  - 효과: 선택 기준 아웃포커스, 층 색 번짐, 화면 색수차. 발광·광원 물체·글리치 없음
  - 글자, 화면 고정 주석(HUD), 모션(가운데에서 펼쳐지는 등장), 조작(클릭 선택·배경 해제)
- 토큰 정리: 지도 코드 안의 상수(층 간격, 효과 값, 모션 시각 등)를 디자인 토큰으로 옮겨 다른 화면이 같은 값을 쓴다.
- `/style` 페이지: 새 스타일로 다시 만든다. 규칙마다 실제 컴포넌트 견본을 둔다. 지도 이전 규칙은 지우거나 폐기 기록으로 옮긴다.
- 결정 기록(`style-guide.md`)과 정체성 기준(「출처가 붙은 조사 기록」)은 유지하고 새 원칙과 연결한다.

## 범위 밖

- 홈 스테이지(온톨로지 그래프, 채팅 패널)에 새 스타일 적용. 이번 정의를 기준으로 다음 작업에서 한다.
- 실제 데이터 연결, 에이전트 연결.

## 결정 (2026-10-11 민재)

1. 범위는 스타일 정의·토큰·`/style` 까지다. 홈 스테이지 적용은 다음 작업이다.
2. 제품 기본 모드는 어두운 모드다. 밝은 모드는 전환해서 쓴다.
3. 원칙 「색상은 데이터에만 쓴다」를 「데이터 색은 답과 관련된 부분에만, 주황은 선택·초점에만」으로 바꾼다.

# 조사 기능 개발 실행

현재 적용 결과·개발 주소·실제 AI 연결 상태는 [진행 기록](../docs/planning/progress.md)을 따른다. [작업 명세](../docs/changes/research-journey.md)가 수용 기준이며, 이 문서는 실행 경계와 복구 주의사항이다. main/운영 배포는 D013에 따라 유예한다.

## 앱에서 하는 일

1. **이슈 조사**에서 실제 자료를 최대 3개 선택하고 질문하거나 법안의 **핵심 정리**를 누른다.
2. 요청 접수 → 관련 자료 찾기 → 자료 분석 → 인용 연결 확인을 표시한다. 취소·실패·연결 대기·월 한도를 구분한다.
3. AI가 질문에 맞는 요약·비교·타임라인을 선택한다. 서버가 허용된 구조와 인용을 대조한 결과만 표시한다. 자료에 없는 날짜·효과·수치·관계는 생성 범위가 아니다.
4. **근거 열기**는 해당 버전의 저장된 원문과 인용 위치를 연다. 위치 일치는 주장의 참·거짓 판정이 아니다. AI 해석은 별도로 표시한다.
5. 원문을 보고 돌아와도 작성 중인 질문과 선택 자료를 유지한다. 초안은 사용자·공간·조사별 앱 메모리에만 두며 로그아웃·계정/권한 변경·새 조사 때 지운다. 완료 결과는 자동 저장한다. **저장한 조사**와 새로고침은 저장된 결과를 읽으며 모델을 호출하지 않는다. 후속 질문은 이전 결과와 현재 선택을 제한된 맥락으로 사용한다.

최근 기본 정보 법안의 미수집 이력을 ‘실제 이벤트가 없다’고 해석하면 안 된다. 과거 법안 제안 내용·처리 이력은 별도 스냅샷으로 추가하고 과거 기록임을 표시한다. 전문·최신 상태·AI 해석과 구분한다. 원본 MySQL과 참조 자료에는 쓰지 않는다. 정기 수집·법안 변경 자동 감지는 이번 수동 질문 흐름의 완료 범위가 아니다.

## 명시 초기화와 권한

- PostgreSQL migration `0005_research_journey`: 자료 제목 sidecar·조사 실행·진행 이벤트·월 예약 테이블. 기존 불변 근거·인증 데이터를 보존한다.
- DBOS의 `dbos` 스키마는 제공된 migration 소유자로 `DBOS.migrate(owner_url, application_role=existing_app_role)`를 별도 실행한다. 기존 앱 역할에는 필요한 테이블 DML만 부여하며 public/dbos의 CREATE를 주지 않는다.
- 워커는 `run_migrations=False`로 시작한다. 앱 import/startup에서 migration·모델 호출·자료 등록을 하지 않는다.
- 적용 전에 서버 외부 full/app 백업을 확보한다. 앱 범위 복원은 별도의 소유 loopback 검증 DB에서만 수행한다. 실제 DB의 reset·테스트·downgrade·복원을 수행하지 않는다.
- 자료 추가는 기존 비공개 계획 등록 CLI의 offline → check → apply → repeat 순서로 진행한다. 표시 제목은 별도 sidecar이며 기존 snapshot·원문 hash를 바꾸지 않는다.

정확한 SDK/CLI 구성과 환경변수는 [워커](../apps/worker/README.md), [API](../apps/api/README.md), [저장 패키지](../packages/storage/README.md)를 따른다. 접속값·키·실제 계정·질문·원문은 문서/로그/Git에 기록하지 않는다.

## AI 연결과 비용

서버에 `OPENAI_API_KEY`를 안전하게 공급하고 워커를 시작한 뒤 API의 `ISSUEDIGEST_RESEARCH_ENABLED=1`을 명시한다. 두 설정은 별개다. 키가 없으면 활성화하지 않으며, POST는 예약·모델 호출 전에 연결 대기로 거부한다. 예시나 합성 모델을 실제 앱의 fallback으로 쓰지 않는다.

모델은 `gpt-5.4-mini`, Responses API의 `store=False`다. PydanticAI 2.56.0/DBOS 3.2.0을 고정한다. 월 글로벌 예약 USD10, 건당 USD0.25 예약, 최대40건이며 현재 공간의 동시 진행은1건이다. 이는 실제 청구액 정산이나 전체 서버 운영비 상한을 뜻하지 않는다. 실패·취소·응답 유실 예약은 자동 반환하지 않아 보수적으로 제한한다. 현재 도구 없는 조사는 한 번의 요청·최대 출력2500토큰·입출력24000토큰·요청시간60초로 제한하며 제공자 자동 재시도는 끈다. 질문·부모 맥락·제목·UUID·JSON까지 직렬화한 prompt는 전송 전17180 UTF-8바이트로 제한한다. 현재 고정 지시/스키마2272바이트·제공자 framing 여유2048·최대 출력2500을 포함한 보수적 한도다. 인용은 정확한 원문을 자르지 않고 source별32개·총100개/5자료·인용 본문12000자 안에서 선택한다. 실제 모델 토큰은 응답 뒤 별도로 기록하며, 응답 뒤 UsageLimits만 사전 비용 제한으로 사용하지 않는다.

같은 request ID/입력의 재확인은 중복 실행을 만들지 않는다. DBOS checkpoint 이후의 재실행은 저장 결과를 재사용한다. 제공자가 접수했지만 응답을 checkpoint에 남기기 전에 유실되는 구간의 정확히 한 번 과금은 보장하지 않는다. 취소·권한 변경 뒤에는 결과를 게시하지 않는다.

답변의 보조 free-text 메시지는 화면에 중복 게시하지 않고 검증된 주장/모듈만 정식 결과로 저장한다. 자료 부족·추가 질문의 설명은 유지한다. 선택 snapshot을 모델 입력에 명시해 관련 자료를 목표 법안과 혼동하지 않도록 한다. 생성 후 검증에서 실패해도 이미 확인한 토큰 사용량은 실패 상태에 기록한다. 제공자 응답 자체를 받지 못해 사용량을 모르는 경우의0기록은 무료 청구를 뜻하지 않으며 예약을 유지한다.

## 검증 증거를 구분하기

- 단위/계약/실제 PostgreSQL·DBOS 중단 복구 검사는 합성 전용 DB를 사용한다.
- 실제 자료 복원본 + 별도의 합성 신원 + 실제 HTTP/DBOS + 합성 FunctionModel 브라우저 검사는 앱의 연결·저장·인용·취소를 검증한다. 실제 모델의 추론 품질이나 청구 검증이 아니다.
- 실제 모델 검증은 승인된 키와 제한된 요청으로 따로 기록한다. 실제 사용자의 세션을 임의 발급하거나 재사용하지 않는다.
- 개발 HTTPS에서 정적 빌드 일치·미인증401·API/헬스·쿠키/Origin 경계를 확인한다. 이 확인만으로 사용자의 로그인 뒤 여정이나 운영 출시가 완료되지는 않는다.

# 관리자 요청 상태 · 2026-10-13

**실제로 전달한 요청은 pgvector 한 항목이다.** 이전 문서의 앱 계정·백업·운영/도메인은 제안이었으며 전달·승인된 요청이 아니다. 모든 항목이 전달됐다는 진행 기록은 정정한다.

## pgvector · 완료

- 동료 보고: PostgreSQL18.6 유지, pgvector0.8.7 설치·issuedigest DB 활성화, 개발자/앱 계정 벡터 연산·HNSW 검색 검증. Dockerfile/Compose/초기화SQL·이미지 빌드·DB 백업 반영, 재시작 없이 적용.
- 개발자 직접 확인: 읽기 전용 transaction에서 PostgreSQL18.6·vector0.8.7/public 설치와 L2/코사인 거리 연산 정상 확인.
- 별도 프로젝트 로그인 계정1개도 catalog에서 확인했다. 비superuser·비DB소유자·DB CONNECT 가능이다. 해당 계정으로 로그인하거나 역할 상속·테이블 권한을 검증한 것은 아니다. public 앱 테이블은0개다.
- HNSW 실행·컨테이너 재생성 유지·이미지 빌드·백업/복원은 동료 보고이며 직접 재실행/복원을 하지 않았다. 확장 준비와 실제 한국어 검색 품질·제품 연결 완료를 구분한다.

## 나머지 제안 · 미전달, 개발의 선행 조건에서 제외

| 항목 | 필요한 이유 | 지금 할 일과 필요한 시점 |
| --- | --- | --- |
| 앱 계정 분리 | 스키마를 변경하는 개발 계정과 자료를 다루는 실행 계정의 권한을 분리 | 별도 계정이 이미 있으므로 추가 생성 요청은 불필요. 실제 앱 연결 때 기존 계정의 비밀 설정·상속/권한을 확인하고 필요한 테이블 권한을 개발자가 정리 |
| 정기 백업·복원 | 재수집 가능한 원자료와 달리 사용자의 조사 기록·메모·공유 결과는 재생성하기 어려움 | 앱 테이블이 아직 없어 지금의 개발 차단 항목은 아님. 보존할 사용자 작업을 저장하기 전에 기존 백업의 주기·범위·서버 밖 사본/복원 가능 여부를 확인. 새 유료 저장소나 관리자 전용 계정을 필수 방식으로 정하지 않음 |
| 서버 자원 | 검색·Neo4j·worker의 공존 부하를 판단 | 새 서버/전용 자원 배정을 지금 요구하지 않음. 개발자가 현재 사용량·자료 규모·검색/worker 부하를 먼저 실측, 부족할 때만 구체적으로 요청 |
| 월 비용 | 사용자 확정 월10만 원 상한 검증 | 기존 서버 전체 청구서 대신 IssueDigest가 실제 부담할 추가 비용/분담액만 운영 전 확인. 단순 사양/부하는 개발자가 조사 가능하나 비용 분담은 소유자의 확인 사항 |
| 도메인·웹서버 | 두 사용자가 실제 앱에 접속할 주소·TLS·보호 접근 연결 | 구현에는 불필요. 실제 앱을 두 사용자에게 제공할 때 DNS/기존 프록시 연결 범위를 좁혀 요청. 전용 도메인·별도 서버가 운영의 유일한 방법은 아님 |

권한 분리 근거: [PostgreSQL privileges](https://www.postgresql.org/docs/18/ddl-priv.html). 백업 방식·복원 근거: [PostgreSQL SQL dump](https://www.postgresql.org/docs/18/backup-dump.html). 이 제품에 필요한 시점·구성은 위의 설계 판단이며 지금 세 요청을 모두 보내야 한다는 결론이 아니다.

관리자에게 추가 메시지를 보내지 않는다. 접속값·키는 계정 전용 비밀 설정에 두고, 운영 DB 마이그레이션·권한 변경·새 백업/유료 서비스·DNS 변경도 실행하지 않았다. 다음은 개발자가 수행할 자료/인용·검색 구현과 준비된 앱 계정의 연결 확인이다.

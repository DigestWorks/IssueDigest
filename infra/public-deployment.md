# 공개 앱 배포 상태

2026-10-13 한국 시간. 동료의 배포 인수인계를 읽고 서버와 외부 HTTPS 응답을 확인했다. **DNS와 HTTPS는 준비됐으며 앱은 아직 게시하지 않았다.**

| 항목 | 확인 상태 |
| --- | --- |
| 서비스 주소 | `https://issuedigest.projects.ai.kr` DNS 정상, 인증서 검증을 유지한 외부 HTTPS 요청 성공 |
| 공개 웹 | HTTP 503. 앱 대기 상태이며 화면 제공 성공이 아님 |
| 공개 API | `/health/live`와 `/api/v1/status` HTTP 502. 운영 API 미실행 |
| 운영 서비스 | API 서비스 활성화 설정은 있으나 inactive, 현재 릴리스 없음 |
| 초기 TLS 재시도 | 조회 시 활성 타이머 없음. HTTPS 성공과 함께 확인했으며 인증기관 상세 로그·갱신 실행은 직접 검증하지 않음 |
| 자동 배포 | 최신 `main`의 `.github/workflows/production.yml`과 `infra/production/` 확인. 앱이 없는 현재 main은 검사·배포를 건너뜀 |
| 개발자 권한 | 공용 저장소·릴리스 디렉터리 쓰기 가능. 운영 비밀 설정 접근과 관리자 권한은 기존 제한 유지 |

## 코드와 배포 경로

개발은 기존 개인 worktree에서 계속한다. 공용 checkout과 릴리스는 다른 작업자·배포에 영향을 주므로 이번 확인에서 수정하지 않았다. 최신 `main`은 `6d0884e`이며 개발 브랜치는 `feat/pdf-quote-candidates`다. 두 계열의 읽기 전용 병합 미리보기에서 충돌 표시는 없었다. 실제 통합 커밋 생성·통합 후 검사·병합·배포는 아직 수행하지 않았다.

자동 배포는 `main`의 앱을 고정 도구와 lockfile로 검사하고 합성 PostgreSQL에서 테스트한다. 이후 서버에서 정적 웹을 빌드하고 후보 API를 검사한다. 운영 API 포트는 내부 `18190`, 후보 포트는 내부 `18191`이다. 개인 개발 포트 `15173`·`18090`과 구분한다. 웹·API 확인 실패 시 이전 릴리스 복구를 시도하는 코드가 있으나 실제 첫 게시와 복구는 미검증이다.

운영 템플릿을 저장소에서 바꿔도 관리자 소유 설치 파일은 자동 갱신되지 않는다. 기본 앱은 DB 없이 시작하며 운영 DB migration, 로그인, 자료 연결을 자동 실행하지 않는다. 후보 API는 운영 환경 파일을 읽지 않으므로 향후 실제 앱 설정 연결 시 후보·운영 설정 일치도 검증해야 한다.

## 첫 배포의 남은 작업

1. 기존 앱 코드와 최신 main 배포 설정을 함께 검토할 통합 변경을 준비한다.
2. 통합 코드의 전체 검사를 통과하고 병합 승인을 확인한다. 사용자가 요청하지 않은 main 병합은 실행하지 않는다.
3. 병합 후 Actions와 공개 웹·API 응답을 확인한다. 현재 화면은 빈 자료 안내·연결 확인까지이며 자료 탐색·AI 제품 화면은 후속이다.
4. 실제 로그인·운영 DB·자료 연결과 릴리스 복구·보존·사용자 데이터 백업을 별도로 검증한다.

배포 설정 근거: [main 자동 배포 설명](https://github.com/DigestWorks/IssueDigest/blob/main/infra/production/README.md), [production workflow](https://github.com/DigestWorks/IssueDigest/blob/main/.github/workflows/production.yml). 서버 내부 인수인계는 읽었으나 접속 정보·내부 문서 전체·비밀 설정을 공개 기록에 복사하지 않았다. 코드 fetch와 읽기 확인만 했으며 운영 서비스·DB·DNS·Nginx·인증서 설정은 변경하지 않았다.

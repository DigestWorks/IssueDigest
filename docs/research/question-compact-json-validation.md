## 공식 근거와 한계

[OpenAI JSON mode 설명](https://developers.openai.com/api/docs/guides/structured-outputs#json-mode)은 JSON 생성 지침 부재 시 공백 반복의 가능성을 설명한다. [strict function calling](https://developers.openai.com/api/docs/guides/function-calling#strict-mode)은 schema 준수를 위한 별도 기능이다. 현재는 이미 strict tool이므로 일반 JSON mode 경고를 이번 실패의 입증된 원인으로 취급하지 않는다. 명시적 완결/공백 지시 후보가 관측에 도움이 되는지 검증하는 단계다. 공백 감지기를 완화하거나 유효 JSON만으로 의미/진실을 인증하지 않는다.

## 전체 검사·실제 결과

전체 Python9,670개(app1,535/agents5,643/storage 등2,492)+JS915개, 총10,585개와 린트/포맷·타입·빌드/OpenAPI를 통과했다. 세 격리DB에 모든 Python testpath를 한 번씩 배분했으며 검사 동안546개 non-Markdown 파일은 불변이다. 실제 호출 전 동결 일치·독립 검토와 모의 성공도 확인했다. SDK 실제 결과·필수 명제의 관계 보존과 나머지 미평가 기준은 별도로 기록한다. 한 번의 결과를 일반 신뢰도나 인과효과로 표시하지 않는다.

새 실제1회는 native 모델 완료·도구 인자 JSON/DTO 검증까지 통과했지만 evidence_contract에서 전체 거부됐다. 명제3개·참조23개 중 같은 짧은 수치 표현을 쓰는2개 참조가 원문에 두 번 나타났다. 나머지21개는 유일했다. 원래 supporting 근거 안에서는 해당 표현이 한 번 나오지만 현재 resolver는 quote 전체에서 유일해야 한다. 문맥을 써서 과거 응답을 수리하거나 v4 성공 영수증으로 바꾸지 않았다. 독립 결과 검토도 같은 최초 거부 지점과 문맥 관측을 확인했다.

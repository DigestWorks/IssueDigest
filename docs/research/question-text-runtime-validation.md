# 정확 텍스트 참조 내구 실행 · 검증

2026-10-27. [계약](../changes/question-text-runtime.md). 저장된 계획 버전과 새 분석 SDK를 내구 실행·최종 생성·SQL 저장/재열람에 연결한다. 합성 검증, 실제 모델 내용 검토, 개인 개발 적용을 구분한다.

## 계약·회귀

저장소 TDD와 독립 검토에서 migration0013의 기존v2 보존·정확한 열/제약 사전 검사·모호한 스키마 무변경 거부·v3가 남은 downgrade 거부를 확인했다. 이전 migration은 변경하지 않았다. 조합/최종 생성의 관련178개와 사전 고정한 v2 prompt/지침/canonical 영수증 bytes 일치를 확인했다. 새 v3 영수증은 실제 버전을 유지하며 혼합/위조/해시·원문·질문 불일치를 거부한다.

실행 연결의 관련283개는 두 profile의 native ANSWER→최종 SQL 저장·재열람 일치, 재접수 추가 호출0, 설정 변경 후 부분 재개, 잘못된 workflow의 상태 변경/송신 차단, 취소/권한 재검사와 journal 복구를 포함한다. 태스크별 독립 검토와 백지 컨텍스트 전체 검토에서 차단 결함이 없었다.

## 전체 검사

최종 Python9,604개(app1,535/agents5,577/storage 등2,492)와 JS915개, 총10,519개를 통과했다. 세 격리 DB에 모든 Python testpath를 중복 없이 나눴다. Python 린트·포맷·타입, 프론트 린트·타입·빌드와 OpenAPI 검사를 통과했다.

최초 JS 실행은914/915였다. busy 해제와 React Router 이동 완료가 별도이므로 기존 테스트의 즉시 이동 검사가 경합했다. 수정 전 해당 파일10개는 단독 실행에서 통과했고, 실제 이동 완료를 기다리도록 단일 테스트를 강화한 후 전체915개와 독립 검토를 통과했다. 최초 실패를 숨기거나 성공 분모에 합산하지 않았다. Python 전체 검사 동안 제품 bytes는 불변이며, 병렬 검사 후 달라진 파일은 이 테스트 하나다.

기준541개 non-Markdown 파일 중 의도한19개만 변경되고522개는 동일하다. 새 migration/검사 파일을 포함한 전체 검사 freeze는544개다. 과거 다섯 검증 묶음319개 파일의 manifest를 재검증했다. 이전 실제 응답·실패/비용과 생성 SDK bytes는 보존한다.

## 제한 실제 인수

비공개 원문·질문·사전 기준과 제품/의존성 해시를 고정했다. 외부 호출 없는 native 모의에서 분석→최종 생성→저장/재열람·재접수 추가0을 확인했다. 별도 독립 검토 및12개 오프라인 검사 후 새 실제 인수를 한 번 수행했다. 분석1/최종1 이하, 무재시도·고정 모델/출력·원문 한도와 전체600초 종료를 적용했다.

실제는 분석1회에서 연속 공백 정체로 실패했다. SQL reason=whitespace/status=failed, stream_closed=true를 확인했으며 최종 생성/작업은0이다. 수집한 마지막 인자 delta에는258자 연속 공백이 있고 모델 완료 이벤트·최종 usage는 관측되지 않았다. usage 미관측을0비용으로 취급하지 않으며 분석 예약0.50달러와 송신 의도/실패를 보존한다. 원래 응답은 잘라 고치거나 재시도하지 않는다. 최종 생성·내용 의미·앱 인수는 실패 관측으로 인해 수행하지 못했다.

새 native 요청의 JSON body는 직전 실제 성공한 SDK 요청과 정확히 동일했다. 실행 연결에 따른 prompt/원문/질문 변경은 관측되지 않았다. 한 번의 성공과 한 번의 실패로 생성의 안정성·원인을 일반화할 수 없으며, 이번 결과를 최종 생성 성공 또는 품질 개선으로 표시하지 않는다. 원응답·닫힘 metadata·실행 journal·SQL·DB dump와 사전 기준을 비공개 보존한다.

## 적용 경계

공동 DB/서비스는 아직 변경하지 않았다. 새 profile은 서버 opt-in으로 새 계획에만 적용하며 기본은 기존v2다. 개발 계정의 schema 변경 권한과 현재 실행0을 읽기 전용으로 확인했다. 개인 개발 적용에는 공동 DB의 백업/복원 검증과 migration·설정 전환·앱 확인이 남는다. v3 데이터가 생긴 뒤에는 이전 binary로 되돌리는 대신 두 버전을 읽는 새 코드에서 새 접수만v2로 전환해야 한다. main·운영 배포와 GitHub Actions 재활성화는 하지 않는다.

# 전용 DB·기존 수집 자산 실측

2026-10-12 UTC 읽기 조사, 테이블 집계 시작 08:49 UTC. 관리자 안내를 실제 접속·SQL 집계·파일 읽기로 확인했다. 접속 주소·계정·비밀 설정 값·원문·개인정보는 이 공개 기록에 포함하지 않는다. 수집 DB는 SELECT 전용이며 수정·수집 재실행·전용 DB 마이그레이션은 하지 않았다.

## 준비된 것과 남은 것

| 항목 | 직접 확인 | 다음 조건 |
| --- | --- | --- |
| IssueDigest 전용 PostgreSQL | 18.6, public 관계 0개, 기본 plpgsql만 설치. 연결·DB CREATE·public CREATE 권한 확인 | 앱 연결 설정·명시적 마이그레이션·런타임 최소 권한은 후속 |
| pgvector | 설치된 확장과 설치 가능한 확장 목록 모두 vector 없음 | 관리자가 해당 PostgreSQL 환경에 확장 패키지/이미지를 준비해야 함. 단순 CREATE EXTENSION으로 해결할 상태가 아님 |
| 비밀 설정 | 전용 DB helper 동작, 설정 파일 권한 600 확인. 설정 키 PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSFILE/DATABASE_URL | 값은 서버의 개인 설정에서만 사용. SQLAlchemy용 연결 형태·PGPASSFILE 적용을 구현 시 검증 |

| 코드·파일·실행 기록 | 코드 스냅샷 517파일, 원문/산출물 파일 읽기 가능, 실행 이벤트 354개 | 코드/상태는 스냅샷, data는 읽기 전용 실시간 mount. 실행 중 코드·현재 수집 성공과 동일시하지 않음 |

| 운영 | 전용 DB 제공·자료 접근은 해결 | 전용 자원·월 분담 비용·외부 백업/복원·런타임 계정 분리·인증 공급자는 남음 |

현재 기본 API는 여전히 DB 미연결 상태로 자료 조회를 거부한다. 접속 확인을 제품 앱 연결 완료로 표시하지 않는다. 합성 테스트 DB reset/rollback 절차를 이 전용 DB에 실행하지 않는다.

data 루트에 별도 여론조사 목록·PDF 점검 JSON/CSV 4파일도 있다. legacy-data의 PDF에는 연구·용역 문서가 섞여 있으므로 법안 전문 1,000건으로 표시하지 않는다.

- PDF 첫 1,024바이트 점검: pdfs 751개에서 PDF 헤더 확인, **23개는 헤더 없음·2KiB 미만**. legacy-data PDF 1,000개는 헤더 확인. 전체 파싱·페이지·진위 검증은 아니다. 헤더 없는 파일은 첫 이관에서 제외한다.
- parsed JSON 840개 중 registration_number가 있는 객체 609개, 중복 포함 등록번호 문자열 324종. 나머지는 다른 구조로 별도 분류한다. JSON 읽기 오류는 없었다.
- 이 609개 중 pdf_path가 있는 결과는 286개. PDF basename 대조로 274개에서 파일 후보를 찾았고 12개는 없었다. 후보가 여러 개였던 결과 49개는 274개에 포함된다. 파일명 대조는 원문 동일성 증명이 아니다.
- 출처 URL이 있는 286개는 모두 www.nesdc.go.kr 도메인. DB의 305개 조사와 파싱 파일·원문 파일의 정확한 대응은 아직 검증하지 않았다.
- 인용 가능 판정에는 등록번호 + 실제 파일 해시 + 출처 + 페이지/표 위치를 확인한다. 기존 수치·파싱 결과만 복사해서 검증된 인용으로 표시하지 않는다.

## 최신성과 재사용 경계

- 실행 상태 스냅샷: run_started 122 / run_finished 112 / step_finished 120, run ID 122개. 이벤트 날짜 2026-05-19~2026-07-17. 종료 이벤트만으로 성공 여부를 확정할 수 없고, 종료가 없는 10개를 현재 장애로 단정하지 않는다.
- Bill 최근 modified_date는 `2026-10-12 17:49:29.198545`, 제안일 상한은 2026-07-10. 오늘 수정된 행이 있다는 사실과 최신 법안 수집 완료는 다르다. 현재 실행 스케줄·누락 범위는 추가 조사 대상이다.
- BillSearchDocument 최근 rebuilt_date `2026-07-11 12:52:41.637574`. 체크포인트 4개의 기준일은 2025-12-05~2026-05-06, 수정일은 2026-06-24~2026-07-10이다.
- 코드 스냅샷 기준 `9e969d33cf8c184f78181a15cd9687f78155f461`. 기존 코드의 의원/선거 ID·조사 등록번호·정규화·수집 재시도·체크포인트 규칙을 선별 재사용한다. 이 커밋이 현재 운영 실행 버전이라고 확인하지 않았다.
- 스냅샷의 election-and-poll-storage 문서와 스키마를 대조했다. 기존 poll option은 최신 파싱 결과로 교체되는 구조이므로 과거 조사 버전이 완전 보존됐다고 가정하지 않는다. MySQL upsert·런타임 DDL·고정 경로는 PostgreSQL 불변 버전/명시적 migration 계약에 맞춰 분리한다.
- 뉴스·청원·통계는 이번 허용 테이블 목록에 없다. 연결 코드 존재는 확인된 적재가 아니다. 추가 접근이 필요한지, 아직 저장되지 않은 것인지 별도 확인한다.

## 다음 구현 순서

1. 전용 DB 대상·백업 방식·런타임 권한을 확인하고 명시적 앱 연결/마이그레이션을 준비한다. 자동 migration이나 기존 DB 수정은 하지 않는다. pgvector는 검색 적용 전 관리자 준비가 필요하며 확장 미설치가 원문 계약 준비를 막지는 않는다.
2. 읽기 전용 자료 연결기의 추출 기준·원천 ID·파일 대응·검증 제외 이유를 정의한다. 첫 이슈는 아직 미정이다. 기존 조사 PDF와 법안 공식 링크를 후보로 두고 원문 대응이 정확한 자료 30~50건을 선별한다.
3. 원문 bytes·해시·파싱 위치·인용을 기존 SourceDocument/DocumentVersion/ParsedRepresentation/EvidenceBundle 계약으로 연결한다. 중복·변경·원문 누락·가짜 PDF·과거 AI 결과를 구분한다.
4. 실제 보호 조회와 두 사용자의 같은 자료 재열람을 연결한 뒤 검색·실행 저장/복구·AI 생성 화면을 검증한다. 자료 이용 조건·첫 질문 20개·권한 정책도 함께 확정한다.

동료에게 남은 확인은 pgvector 패키지 준비, 외부 백업·보관 기간·복원 방식, 전용 자원·월 분담 비용, 런타임 계정 분리, 새 도메인 연결 담당/경로다. 새로운 legacy 쓰기 권한은 필요하지 않다.

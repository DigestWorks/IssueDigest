# 기존 법안 제안 내용·처리 이력의 재사용

2026-10-15. 기존 MySQL과 참조 파일은 읽기 전용으로 조사했다. 실제 추가 적용 여부·최종 건수는 [진행 기록](../planning/progress.md)을 따른다. 개별 원천 ID·DB 접속값·원문·등록 계획은 비공개에 보존한다.

## 확인한 범위

| 대상 | 확인 | 사용 경계 |
| --- | --- | --- |
| 먼저 연결한 22대 법안8건 | 제안일 2026-03-30~2026-06-22, 해당 법안과 연결된 수집 처리 이력0건 | 기본 정보만 사용. 실제 처리 이벤트가 없다는 의미가 아니며 현재 상태·전문·영향을 추정하지 않음 |
| 21대 고등교육 관련 법안2건 | 제안일 2023-09-05/2023-09-25, 기존 원본 제안 내용400/422자·처리 이력4/3건 | 국회 원문과 대조한 과거 제안 내용·날짜/단계만 별도 추가. 최신 법안이나 전문으로 표시하지 않음 |
| 기존 정부 공식 자료1건 | 공식 HTML의 현재 추출 표현이 기존 저장 표현과 동일, 기존 인용3개 위치 일치 | 공식 제목을 표시용 메타데이터로 추가. 기존 스냅샷을 덮어쓰지 않음 |

기존 AI 요약·생성 제목·태그·과거 AI 산출물은 이 등록의 근거로 사용하지 않았다.

## 원문 대조

국회 의안 상세 화면은 공개 상세 페이지에서 본문 조각을 별도 요청하는 구조다. 공식 화면이 사용하는 요청과 CSRF 연결을 따라 원문 본문을 읽었으며, 두 제안 내용은 공백을 정규화해 대조했다. 수집된7개 날짜와 대응 단계 문구가 공식 본문에 존재함을 확인했다. 이는 법안 전체 처리 과정·모든 날짜/단계의 의미·현재 효력까지 검증했다는 뜻이 아니다.

각 과거 법안은 제목·의안번호/제안일·제안 내용·개별 수집 이력을 보존한 별도 불변 텍스트 스냅샷으로 준비했다. 두 자료의 정확 인용은 총13개다. 앱에서는 제목에 **21대 과거 기록**을 붙이고 공급처·본문에도 범위를 표시한다. 기존 자료9건의 hash와 기존 계정·초대·권한은 변경하지 않는다.

자료 제목은 `SourcePresentation` sidecar에 저장한다. 기존 SourceDocument/EvidenceBundle 필드를 바꾸거나 UUID를 표시 이름으로 쓰지 않는다. 알려진 기본 정보 profile은 실제 법안명을 해석하며, 운영자가 공식 출처와 대조한 제목은 별도의 검증 profile로 공급한다.

## 남은 작업

현재 법안의 최신 이력 수집·정기 갱신·변경 감지·자동 알림과 전문/PDF 전수 연결은 후속이다. 이번 조사는 사용자 질문을 트리거로 저장된 근거를 분석하는 흐름이다. 최근 법안의 내용이 부족하면 자료 부족을 표시해야 하며 과거 법안의 내용으로 최신 법안을 설명하면 안 된다.

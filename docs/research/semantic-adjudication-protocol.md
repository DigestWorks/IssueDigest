# 역할·정보 보존·중요도 판정 기준

2026-10-23 한국 시간. [원문 참조 계약](../changes/role-reference-implementation.md)의 다음 인수 설계다. 이번 작업은 문서·무호출 연구이며 spec-driven-workflow의 문서 예외를 적용한다. 실행 코드458개와 기존 실제642개·설계121개 증거를 동결한다. 새로운 SDK·앱·자동 판정·공급자 호출·운영 변경은 만들지 않는다. 전체8,452검사/PR92 CI 통과는 구조 증거로만 재사용한다.

## 목적과 범위

브리핑에서 중요한 것은 역할 이름 자체보다 수치가 누구의 어떤 범위·시점·조건을 말하는지 왜곡 없이 설명하는 것이다. 그러나 다른 역할에 같은 이름이 있다는 이유로 잘못된 연결을 허용해서도 안 된다. 역할 분류, 원문 문자 참조, 의미상 정보 보존, 질문에 대한 중요도를 독립 축으로 기록한다. 기존 주요6/8·대조7/9 역할 점수를 바꾸거나 새 기준으로 과거 만점을 만들지 않는다.

이번에 사전 고정하는 분석 대상은 기존 역할 불일치10관계(J4/K6)와 공개 합성 경계8개다.10관계는 같은 원문을 공유하는 J의2수치/K의2수치에 속하므로 독립 표본10개가 아니다. G의 쟁점·사람 재판정과 미채점237관계·후보 밖 recall은 그대로 열린 과제다. 기존 자료는 이미 본 개발 자료이며 holdout이나 독립 사람 정답이 아니다.

## 판정 단위와 증거

한 단위는 **해당 수치에 대한 원문 명제**다. 검토 전에 수치·대상/범위·관계·시점/조건·양화 표현·상태·근거 span을 기록한다. 나열의 한 구성원과 전체 집단, 신청과 선정, 예산과 관측, 운영 주체와 수혜 대상을 섞지 않는다. 출처가 말한 내용과 세계의 사실을 구분한다. 자료가 주장한다는 것을 확인한 결과를 독립 사실 확인으로 표현하지 않는다.

원래 generation의 연결된 binding/context/event와 직접 relation·scope kind·증감/상태를 원문 전체와 함께 읽는다. 검토용 reconstruction은 원래 코드의 결과와 비교할 뿐 새 정보/역할을 채우지 않는다. 다른 수치·연결되지 않은 context·broad c/support에 문자가 등장한 것만으로 해당 수치에 보존된 것으로 보지 않는다. 의미상 같은 뜻이라고 판단하려면 두 표현의 대응과 **같은 수치에 대한 연결·범위·조건·양화**가 유지됨을 근거로 남긴다. 문자열 포함이나 역할 모델의 S/E 선택만으로 판단하지 않는다.

## 네 축과 상태

| 축 | 기록할 상태 | 판단 범위 |
| --- | --- | --- |
| 역할 조건 | 기존 역할 조건 충족/불충족/유보 | 과거 기준·점수 그대로. 새 허용 역할로 소급하지 않음 |
| 문자 참조 | 기존 exact/containing/partial/no-reference | strict report 관측 그대로. 의미 점수로 변환하지 않음 |
| 의미 보존 | explicit / equivalent / partial / not_represented / contradicted / undetermined | explicit은 명제의 필수 요소와 연결을 명시 보존. equivalent는 표현 차이에도 같은 명제임을 설명 가능. partial은 일부만 보존. not_represented는 원문 명제가 명확하고 원래 연결 전체를 읽어도 표현되지 않음. contradicted는 반대·잘못된 범위/상태를 표현. 애매하거나 증거 부족이면 undetermined |
| 중요도 | required / contextual / optional / undetermined | required는 명시 조사 질문/작업 요구를 답하는 데 필요하거나 생략하면 그 답이 달라짐. contextual은 해석에 도움. optional은 요구에 직접 관련 없음. 질문/요구가 없거나 판단 근거가 부족하면 undetermined |

explicit/equivalent도 원래 명제가 틀렸을 가능성을 제거하지 않는다. not_represented는 검토한 명제·원래 추출 범위에 한정하며 전체 자료 누락률을 뜻하지 않는다. primary 참조가 있어도 역할/범위 오배정이면 contradicted/partial일 수 있고, no-reference라도 원문 다른 표현을 명시 선택해 같은 명제를 보존했다면 근거를 남겨 equivalent일 수 있다. partial은 전체 명제 보존 성공으로 세지 않는다.

## 사전 적용 규칙

1. 먼저 원문 명제와 적용 수치를 고정하고 관련성/모호성을 기록한다. 의미 판정에 맞춰 원문 명제의 범위를 좁히지 않는다.
2. 원래 extraction과 모든 연결을 읽고 의미 보존 상태·위치 대응·짧은 판단 이유를 기록한다. 판단이 갈리면 두 해석과 undetermined를 남긴다. 독립 검토자의 이견을 다수결 정답으로 지우지 않는다.
3. 중요도는 명시 질문/사전 작업 요구를 별도로 인용해 판정한다. 현재 저장 generation 자료에는 사용자 조사 질문을 추가하지 않는다. 질문이 없는 이번10관계에서 중요도를 자동 required로 채우거나 ‘중요 누락’ 점수를 내지 않는다.
4. 실제 응답·원문·gold·비용·역할/참조 보고서를 수정하지 않는다. 뒤늦은 판단은 별도 버전의 development annotation으로 보존한다. 무호출 재검증과 새 모델 요청을 구분한다.
5. 확정 사람 판정은 사람이 실제로 검토·기록한 뒤에만 표기한다. 에이전트의 독립 검토는 개발 분석의 재검토이며 사람 판정·사용자 승인·정답 확정이 아니다.

## 분모·인수와 다음 구현

모든 분석 단위에서 상태별 건수와 유보를 함께 남기며, 기존 역할 점수와 합산하지 않는다. 질문 없는 표본의 중요도 미판정을 제외하고 품질100%처럼 보이지 않는다. 이번10관계는 오류 탐색용이며 정확도/중립성/의미 recall의 분모가 아니다. 독립 분석 간 일치는 일관성 관측이지 진실 인증이 아니다.

후속 인수는 사람 판정과 별도의 미관측 원문·실제 질문을 응답 생성 전에 고정해야 한다. 원문 전체에서 질문에 필요한 명제를 먼저 찾고, 기존 후보에 없는 관련 명제도 포함해 후보 단계 누락/생성 누락/역할 불일치/유보를 구분한다. 현재47후보 안의271관계를 전체 recall로 부르지 않는다. 판정 비용·시간·이견을 기록하고, 중요도가 확정된 명제와 모호한 명제를 분리한다. 이 인수·앱 전체 예산/권한/복구 전에는 자동 hard 누락/수리·앱 배포를 하지 않는다.

저장용 의미 판정 계약이 필요하면 이번 기준과 관측 이견을 먼저 검토한 뒤 별도 strict DTO/TDD를 설계한다. 문자 참조 DTO에 의미 승인 필드를 덮거나 의미를 interval로 추론하는 구현은 만들지 않는다.

## 사전 고정 후 개발 분석

기준 commit aaff147 이후 기존 원문과 원래 generation의 전체 binding/context/event/scopes/직접 relations를 읽었다. 원래 SDK·참조 보고서도 읽기 전용 대조했다. J/K의10관계에 별도 provisional development annotation을 기록했으며 기존 원문/역할 gold/점수/결과를 수정하지 않았다. 원문·원래 generation·역할 보고서·참조 보고서 hash와 해당 수치의 원래 연결·근거·판단 이유는 비공개로 보존한다.

| 대상 | 명제 한정 | 개발 분석 | 중요도 |
| --- | --- | --- | --- |
| K · 2수치×3명칭 = 6관계 | 세 명칭이 해당 대상 집단의 예시라는 한정. 세 항목만으로 집단 전체를 구성한다는 주장이 아님 | explicit 제안. 같은 수치의 entity에 원래 비배타적 나열과 ‘등’이 남고 상위 모집단 연결도 유지됨. S/E 역할 기준은 그대로 불충족 | 6개 모두 undetermined |
| J · 2수치×2명칭 = 4관계 | 선정된 두 지역의 정체성. 신청 전체 범위나 선정 수치 자체의 정확성을 재판정하지 않음 | not_represented 제안. 원문은 명시하지만 해당 수치의 원래 대상은 일반 명칭이며 전체 원래 선택 연결에도 두 지역 정체성이 표현되지 않음 | 4개 모두 undetermined |

K의6관계를 ‘의미 정답6건’으로 세지 않는다. 좁은 명칭/집단 연결 명제만 읽은 개발 제안이며 원래 수치/비율/시점/사실성 전체를 인증하지 않는다. J의4관계를 ‘중요 누락4건’으로 세지 않는다. 질문 없는 자료의 중요도는10개 모두 미판정이며, 중요 누락 분모/점수는 산출하지 않는다. 기존 주요6/8·대조7/9와 원래 generation 비분쟁1/4·G유보·이전 검수2탐지/6미탐/추가3유보·실제 사용량/비용은 그대로다.

명칭4관계/6관계는2개 문서와4개 수치의 반복 연결이다. 독립 표본 수나 일반 정확도를 추정하지 않는다. 질문을 새로 만들어 중요도를 유리하게 바꾸지 않았으며 추가 모델 호출0·SDK/앱/서버 변경0이다. 독립 개발 검토는 후속 영수증에 기록하며 사람 adjudication·미관측 인수를 대체하지 않는다.

# 영속 근거 작업·DBOS 검증

2026-10-26 KST. [명세](../changes/durable-evidence-worker.md)의 내부 저장·실행 연결 검증이다. 실제 앱·기본 worker·main은 변경하지 않는다. 실제 모델 호출·제공자 과금/의미 품질·브리핑 인수의 증거는 아니다.

## 구현 범위

신규 `EvidenceJobRepository`는 정확한 원문/질문/모델·서버 지정 예약 금액을 별도 작업에 저장한다. 기존 월 예약 pool의 10USD/40회 합산 제한을 공유하며 어떤 종료 상태에서도 예약을 돌려주지 않는다. 예약 금액은 실제 청구 상한이 아니다.

`execute_evidence_job`은 현재 권한·원문을 확인하고 송신 의도를 먼저 커밋한 뒤 빌린 async client로 guarded-v2를 한 번 호출한다. `register_evidence_workflow`가 별도 DBOS workflow/step을 등록하며 호출자가 DBOS 설정·시작을 맡는다. import·등록만으로 DB/모델 작업을 실행하지 않는다. 완료 결과는 unreviewed이며 브리핑/Canvas로 자동 전환하지 않는다.

## 검증 방법

전용 로컬 PostgreSQL·합성 원문·실제 AsyncOpenAI/모의 HTTP SSE·설치된 DBOS를 사용했다. 제공자 호출과 운영 서버/DB 변경은 0회다. 기존 실행 파일을 고정하고 신규 테이블은 해당 테스트에서만 정리한다.

초기 저장소/worker 부재에 대한 실패를 확인한 뒤 구현했다. 보완 후 집중 검사 57개와 신규 파일의 Ruff/형식/mypy를 통과했다. 초기 독립 검토에서 완료 취소 응답과 잠금 역전 2건을 발견했다. 실제 실패 7건을 재현하고 수정 후 같은 검사와 집중 검사를 통과했다. 수정 재검토와 최종 전체 검토는 C0I0M0·미해결0이다. 실행abfbe26 기준 신규57/새전체9,572개(Python8,752+JS820)·정적 검사/빌드/OpenAPI·실패/skip/warning0를 통과했다. 초기 중단한 전체 실행은 별도 보존하고 통과로 세지 않았다.

- 저장·입력: 원문 hash 일치, 정확한 UUID/질문/모델/Decimal 예약, 현재 세션·역할·자료 범위, 멱등성, 이전/새 작업의 합산 예산과 동시 마지막 예약.
- 송신·복구: 동시 claim, 송신 의도 후 중단, claim 응답 유실, 완료 커밋 후 응답 유실, 완료 재독해에서 추가 HTTP 없음.
- 결과·사용량: 취소/권한 상실/원문 삭제·변조·제목 변경 뒤 결과 거부와 관측 사용량 보존, 미관측 None, 초과/큰 정수 보존, 취소 전파, 저장 결과 hash/의미 재검증.
- DBOS: 고정 workflow ID·이름·무재시도 step, 완료 재진입, step checkpoint 뒤 중단·재개 시 캐시를 사용하면서 현재 권한을 다시 검사. 각 모델 작업의 모의 HTTP는 한 번이다.
- 마이그레이션: 신규 테이블만 upgrade/downgrade하고 기존 snapshot 행·metadata를 보존한다.

## 한계와 다음 연결

서비스에서 작업을 제출하는 경로·브리핑 변환·다중 자료 orchestration·운영 예약 정책 인수와 개발 배포는 남아 있다. 기존 UI에 새 경로를 활성화하지 않는다. 합성 DBOS/HTTP 검증으로 실제 제공자의 중단·청구·의미 품질을 보장하지 않는다.

송신 의도 후 응답이 없으면 재호출하지 않고 indeterminate로 둔다. 실제 송신 직전에 중단돼도 예약과 불확실 상태가 남을 수 있다. 관측 사용량 저장도 실패하면 실행 오류를 드러내며, DB 복구 후에는 미관측/불확실 상태로 처리한다. SQL receipt hash는 서명이 아니며 소비자는 현재 원문에 대한 worker의 심층 검증을 사용해야 한다.

## 선택과 영향

1. 기존 모델/가격/결과를 바꾸지 않고 별도 내부 작업을 만든다. 이전 복구 계약을 보존하지만 서비스 요청·브리핑·배포 연결은 후속이다.
2. 송신 의도를 먼저 저장하고 모호한 실행은 재호출하지 않는다. 중복 비용을 막지만 실제 호출이 없던 작업도 불확실 상태로 남을 수 있다.
3. 기존 월 예약 pool을 공유하고 서버가 예약 금액을 명시한다. 합산 제한을 유지하지만 실제 청구 상한이 아니므로 운영 비용 정책 인수가 필요하다.

4. 기존 사용자 행 잠금의 역전을 막도록 새 작업 SQL transaction에 전용 advisory gate를 둔다. AI 호출 동안에는 잠금을 보유하지 않지만 짧은 DB 처리의 동시성이 줄어 부하 인수가 필요하다.

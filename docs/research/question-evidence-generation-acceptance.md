# 질문별 근거 생성 · 실제 모델 인수

2026-10-23 한국 시간. [새 SDK](../changes/question-evidence-generation.md)의 실제 전송·완료와 질문별 의미 보존을 구분해 확인한다. 문서·제한 연구로 spec-driven-workflow의 문서 예외를 적용한다. 기존466개 non-Markdown 파일과 원래 원문·기준·과거 결과·비용·최신 SDK65개 증거를 동결한다. 공개 실행 코드는 바꾸지 않으며 기존9,026QA를 재사용한다. 앱/worker/main 배포·새QA 자원은 만들지 않는다.

## 응답 전에 고정한 범위

이전 [개발 원문](https://www.korea.kr/news/policyNewsView.do?newsId=148973453)의 전체 본문을 새 SDK에 그대로 전달한다. 기존 개발 질문4개/필수 명제12개는 바꾸지 않는다. 이번은 그중 신청 자격·기관 승인·종류별 신청 수 제한을 묻는 질문1개(Q2), 기존 필수 명제3개(P5/P9/P10)를 선택한다. 다른 질문의9명제는 이번 질문의 미평가로 남기며, 전체12분모를 삭제하거나 이번3개로 제품 전체 성능을 주장하지 않는다. 수치형뿐 아니라 자격·전제와 분배/열린 경계를 함께 관찰하기 위한 개발 질문이며 사용자 질문·holdout·사람 정답이 아니다.

모델은 앞선 평가와 같은 `gpt-6.1-sol`/reasoning low/standard(default)다. 새 SDK 전체20,000/출력1,800·30초/no-store·요청1회/SDK·transport 재시도0을 유지한다. 전체 원문/정확 질문·지침·실제 strict 도구·모델 설정의 모의 전송을 확인하고, 원문/기준/루브릭/SDK/전송 body hash를 실제 응답 전에 고정한다. 새 namespace의 소진 잠금을 먼저 생성하고 실패·미완료·거부 후에도 다시 보내지 않는다. 원문 축약·한도 상향·모델/자료 교체·자동 보정은 없다. 기존 runner와 소진 잠금은 실행/수정하지 않는다.

## 사전 의미 판정

- P5: 신청기관이 대규모·중규모 각각 최대1곳을 신청한다는 의미가 같은 명제의 수치·상한·분배 대상과 신청 상태에 연결돼야 한다. 선정 계획의 개수로 대체하지 않는다.
- P9: 광역자치단체와 명시된 법률상 공공기관이라는 신청 자격의 주체·범위를 보존해야 한다.
- P10: 공공기관이 상위기관의 승인을 받고 신청한다는 주체·승인 주체·선행 조건을 연결해야 한다.

선택된 명제의 좁은 의미 필드와 그에 직접 연결된 정확 인용 참조를 읽는다. 전체 입력 본문이나 무관한 출력에 단어가 있다는 것만으로 보존으로 세지 않는다. explicit/equivalent/partial/not_represented/contradicted/undetermined를 구분하고 partial은 완전 보존 성공이 아니다. 상대 날짜·불명확한 주체/지표 등은 uncertain으로 유지하며 추론으로 채우지 않는다.

HTTP 응답/모델 완료/SDK 반환/구조 왕복/의미 판정을 각각 기록한다. SDK 거부 응답의 읽을 수 있는 부분 JSON도 성공으로 전환하지 않는다. 원래 요청·응답·known usage와 송신 불확실성은 비공개로 보존하고 키·헤더·비공개 원문/질문은 공개하지 않는다. usage를 기록하되 실제 청구서·미확인 캐시 TTL/비용·월 비용을 추정값으로 확정하지 않는다. 결과 뒤에 기준을 고치거나 재호출하지 않는다.

독립 검토도 개발 비맹검 검토이며 사람 판단·진실·중립성·일반 B2C 품질 인증이 아니다. 실제 모델 완료와 질문별 의미를 관측한 뒤에만 다음 표현/앱 인수 작업을 판단한다.


## 실제 요청과 미완료

새 namespace의 실제 요청1회·HTTP200응답1회를 확인했지만 raw status는`incomplete`, 이유는`max_output_tokens`였다. SDK는 거부하고 저장 SDK 결과를 만들지 않았다. 경과29.685초이며 timeout이 아닌 출력 상한 미완료로 구분한다. 실제 송신 body는 응답 전의 model-specific mock과 같았다. 기존 runner나 이번 시도를 재실행하지 않았다.

관측 usage는 입력2,318/출력1,800/합계4,118로 SDK known usage와 일치한다. 출력에 포함된 reasoning1,512를 추가 가산하지 않는다. 차이288은 비추론 출력의 나머지이며 필요한 출력 크기나 완료까지 부족한 양이 아니다. cached read0/cache write2,192도 보존하고 과금 TTL/실제 요금이 미확인이므로 비용을 확정하지 않는다.

이번 질문의 필수3명제는 모두 SDK 미완료에 따른 미평가이며 의미 성공0/3이나 구조 성공으로 표시하지 않는다. 다른 질문의9명제도 미평가로 두고 원래12명제를 유지한다. raw 부분 tool JSON을 수리하거나 의미 성공으로 전환하지 않았다. 입력 수용은 관측했지만 완료한 strict 출력·저장 DTO 왕복·질문별 의미는 아직 인수하지 않았다.

## 다음 판단

전체 요청 예산20,000의 사전 비교를 통과했지만, 추론을 포함한 출력1,800 상한으로 미완료됐다. 사전 비교에는 전체 입력/지침/도구 schema/프레이밍과 출력 예약이 포함되며 관측 usage의 입력+출력 제한과 별개다. 이전 수동 출력450~1,331참고tokens는 추론을 포함하지 않아 실제 충분성을 보장하지 못한다. 필요한 새 한도나 더 낮은 추론 설정의 성공은 이번에 측정하지 않았다. 경과가 현재30초 한도에 가까워 출력 용량을 늘릴 때 지연시간도 함께 검토해야 하며, 더 긴 요청의 성공은 확인하지 않았다. 현재 SDK·이번 제한/실패/usage를 보존하며 다음은 추론을 포함한 출력 용량과 전체 요청 비교를 별도 사전 계획으로 검토한다. 이번 시도의 예산을 올려 성공할 때까지 다시 보내지 않고 앱 연결은 보류한다.


## 검토와 보존

독립 검토에서 전체 요청 예산을 입력 전용 한도로 읽을 수 있는 Minor1건을 지적했다. 입력/지침/도구 schema/프레이밍/출력 예약의 사전 비교와 관측 input+output 한도를 구분해 고쳤고 수정 범위 재검토 C0/I0/M0이다. 사전 기준 hash10개·원래466실행·최신 SDK65증거·과거 실제642/설계121 및 후속 원문/계약 증거는 유지했다. 새 코드가 없어 기존9,026QA를 재사용하며 새 전체QA·서버자원·앱/worker/main 배포는 없다. 문서/개인정보 검사 후 PR과 계획판에 인계한다.

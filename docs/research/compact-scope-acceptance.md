## 실행·판정·비용

실제 최대 **7요청**, 실패 포함·단계당1회·retry/repair/fallback0이다. 순서는 G/H/I 검수 각1회, J 생성→검수, K 생성→검수다. 생성 실패/빈 선택/예산 부족이면 해당 후속 검수는 무호출/적용 불가로 기록하고 다른 요청으로 대체하지 않는다. 과거 G/H/I 생성 비용은 이번 추가 비용에서 제외하고 검수 잔여 예산 계산에만 사용한다. J/K는 새 관측 생성 usage에서 검수 잔여를 차감한다.

[OpenAI 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol)의 GPT-6.1 Sol/low·Responses·30초/no-store·caller 모델을 유지한다. 생성+검수 total20,000/output2,500, 검수 출력은 잔여 중최대1,000이다. 사전 envelope는 G/H/I검수10,001/9,703/9,514, J/K생성18,587/16,761이다. 동적 후속 검수의 정확한 전송은 원래 생성 반환 후 결정적으로 재구성하고, 원문/gold/코드·지침·schema·한도를 바꾸지 않는다. 전체 전송 body를 mock HTTP로 확인한 뒤 실제 송신과 비교한다. 소진/중복 실행을 거부하는 별도 비공개 실행 기록을 쓴다.

생성의 구조 반환/거부·필수 수치/역할 의미 충족을 나눠 기록한다. 검수의 구조 반환/거부·필수 오류 탐지/누락·잘못된 hard 진단/불확실·미완료를 나눠 기록한다. 알려진 실패를 문제없음으로 내보내면 오탐 없는 성공이 아니라 미탐이다. 올바른 경고가 있어도 필수 오류를 전부 잡지 못하면 부분이다. 검수 상태를 의미 정답으로 삼지 않고 원문/사전 기준과 수동 대조한다. 원래 generation을 수정하거나 오류를 고친 응답을 새 성공으로 세지 않는다.

원래 실제 응답이 없거나 반환 거부이면 해당 의미/탐지 판정은 미판정이다. no_issues_flagged는 네 역할의 무경고이며 진실·중립·전체 수치 선택·사람 검토 인증이 아니다. 단문/4문단의 출력 완료는 최대 record/장문 충분성을 보장하지 않는다.

raw usage·cache read/write·reasoning(출력에 포함)·tier·지연을 남긴다. [공식 standard 요율](https://developers.openai.com/api/docs/pricing) 입력$2/cache$0.10/30분write$2.50/출력$10 per1M을 참고하며 입력에 포함된 cached/write를 중복 가산하지 않는다. 실제 청구·환율은 미검증이다. 송신 가능하나 usage불명인 실패를0/무료로 세지 않는다. 이번 상한의 보수적 참고 금액은 요청마다 total20,000을 모두 출력으로 가정해도$1.40 이내이며 실제 SDK 출력 제한은 더 작다. 월10만 원 운영 한도를 확대하지 않는다.

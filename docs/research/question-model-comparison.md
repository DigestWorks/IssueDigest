# 근거 생성의 모델 비교 · 준비와 결과

2026-10-27. [계약](../changes/question-model-comparison.md). 기존SDKv5와 입력/지침/출력 schema를 유지하고 분석 요청의 model만 바꾸는 제한 비교다. 실제 최종 브리핑/저장·서비스 전환은 이번 범위가 아니다.

## 비교 선택

기준 요청은 이전v5/gpt-6.1-sol 실제 실패의 원래 body다. 후보는 gpt-6-astra다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)에서 동일 Responses/streaming/strict function calling·structured outputs/low 추론 지원을 확인했고, 해당 키의 Models 읽기 요청은200으로 모델 ID를 반환했다. 이 읽기는 생성 호출이 아니다. 고정 날짜 snapshot이 제공되지 않아 요청/반환 모델 ID와 시각을 기록한다.

입력·schema·지침·출력4,000·추론low·공백256·service default·저장/배경 끔·무재시도를 유지한다. 후보 선택은 더 높은 가격을 감수한 원인 분리 실험이며 운영 채택을 뜻하지 않는다. [당시 공식 단가](https://developers.openai.com/api/docs/pricing)는 입력10/출력50달러(백만token당)로 Sol의 입력2/출력10달러보다5배 높다. 월10만 원 원칙은 유지하고 예약1달러·분석 최대1회로 제한한다. 예약·상한 가정과 실제 사용량/청구액은 구분한다.

## 사전 검증

전송 JSON에서 model 외 차이를 네트워크 전에 거부하고, SDK/제품·실제 의존성과 입력·사양을 동결한다. supervisor 종료·cleanup과 원요청/영수증/원응답/닫힘 metadata에 묶인 모의 완료를 확인한 뒤에만 실제 키를 읽도록 한다. 모의 fixture는 이전 완결 인자를 사용하지만 기존 실행의 실패를 재라벨하지 않는다.

첫 독립 검토에서 private 비교 도구의 JSON 숫자/불리언 동등 검사·직접 child 실행/최적화 모드·의존성 동결·모의 아티팩트 결합·프로세스 정리 보완점을 발견했다. 수정 전 실패 재현·수정 후40개 검사와 독립 재검토를 통과했다. 초기 합성 모의 자료를 재생성 과정에서 지운 절차상 실수는 private 보고에 남겼으며, 그 자료는 최종 승인 근거로 사용하지 않는다. 과거 유료 시도와 이전 아카이브는 모두 보존한다.

## 결과 상태

고정 코드/실제 의존성·원문/질문/기준과 검토 사양을 동결하고 supervisor 모의 전체 경로·원응답/영수증/닫힘 해시 결합·독립 아티팩트 검토를 통과한 뒤 새 실제 분석을 한 번 수행했다. 요청/반환 model은 모두gpt-6-astra였고 parsed JSON은 기준v5 요청과 model 외에 일치했다. 모델 완료 이벤트·usage·SDKv5 수용·정확 참조 재구성·local JSON 저장 후 재검증 동등과 정상 cleanup을 확인했다. 분석1회·최종0이며 실패 뒤 재호출한 실험이 아니다.

명제3개/참조20회(고유 원문 위치14개)를 수용했다. 별도 AI 개발 검토에서 사전 필수3단위의 대상 범위·선행 승인·각 대상별 상한 보존3/3을 확인했고, 나머지9단위는 미평가다. 알려진 한 원문/질문의 curated 판정으로 사람/맹검·일반 품질/중립성 인증이 아니며, 원문 진술을 검증된 사실로 승격하지 않는다. 실제 SDK 영수증의 unreviewed 상태는 바꾸지 않았다.

사용량은 입력2,412/출력1,348(추론125 포함)이며 입력 중 cache_write_tokens2,276·cached_tokens0이 관측됐다. [공식 캐시 문서](https://developers.openai.com/api/docs/guides/prompt-caching#cache-lifetime)에 따라 TTL 생략은30m이고 write단가는 일반 입력에 더하는 할증이 아닌 총단가다. 일반 입력136×10/백만 + cache write2,276×12.50/백만 + 출력1,348×50/백만 = **0.09721달러 추정**이다. 단순 일반 입력 단가만 적용한0.09152달러는 관측된 cache write를 반영하지 않아 청구 추정으로 쓰지 않는다. 예약1달러/보수 상한0.70달러·가격식 추정·실제 청구서는 서로 다르다.

완료 이벤트 뒤 SDK가 stream을 닫아 end_of_stream=false이지만 capture 잘림/쓰기 실패 없이 close 성공을 기록했다. 이를 물리 EOF 또는 제공자 취소 보장으로 표시하지 않는다. 원요청·원응답/usage·새 영수증·재열람·동결/사전 승인·별도 결과 검토를 비공개 보존했다. 기존 열 묶음696개와 제품/검사552파일을 보존했다. 실제 shared SQL 저장·내구 실행/최종 생성·앱 인수는 아직 없다.

## 해석 경계

같은 body에서 모델만 바꿔도 이전 시도와 시각·제공자 내부 상태·alias 해석이 다르므로 단일 결과가 공백 정체의 원인을 증명하지 않는다. 구조 수용 한 번으로 신뢰도·중립성·전체 의미 품질이나 운영 비용 적합성을 인증하지 않는다. 모델 변경으로 문제를 고쳤다고 단정하거나 자동 fallback/재시도·운영 전환을 추가하지 않는다.

## 다음 단계

후보 모델의 실제 내구 분석→최종 브리핑→SQL 저장/재열람을 소유 격리 DB에서 별도 제한 인수한다. 이번 standalone 영수증을 다른 실행의 journal/유료 호출로 재라벨하지 않는다. 그 뒤 현재 앱 적용에는 DB 백업/복원·migration·실제 화면 확인이 필요하다. 높은 단가·한 표본만으로 기본 모델을 채택하지 않으며 비용과 생성 안정성은 계속 분리 검증한다.

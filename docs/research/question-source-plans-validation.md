# 질문별 자료 선택 영속 계획 검증

2026-10-26 KST. [명세](../changes/question-source-plans.md)에 따라 질문만으로 기존 저장 색인의 자료를 선택하고 같은 요청의 선택을 보존하는 내부 계약이다. API/UI·다자료 AI 실행·브리핑 표시·개발 활성화는 후속이며 실제 제공자 호출·운영 서버/DB 변경은 0회다.

## 구현

`QuestionPlanRepository.submit`은 현재 권한을 확인하고 기존 문자 기반 검색에서 최대5자료를 선택한다. 질문·순서·원문과 제목의 hash를 저장한다. 같은 사용자/요청은 검색하지 않고 저장한 선택과 현재 권한·원문을 재검증한다. 입력 변경·원문 삭제/변경·저장 행 변조는 재선택 없이 거부한다. `get`도 현재 읽기 권한과 최초 작성자의 현재 쓰기 권한을 확인한다. hash는 손상 탐지이며 서명이 아니다.

저장 계획의 get/재접수에서도 기존 `_presentation`의 지연 복구를 허용한다. presentation 행만 없고 canonical 원문이 존재하면 기존 경로로 presentation을 재구성하며, 재구성한 원문/presentation의 hash가 저장값과 일치할 때만 원래 계획을 반환한다. 원문이 없거나 변경됐거나 재구성한 presentation hash가 다르면 계속 거부한다. presentation만 삭제한 경우의 별도 집중 검사는 비차단 후속으로 남기며 이번 검증 통과 항목으로 세지 않는다.

검색어가 없거나 색인 결과가 없으면 명시적 no_match를 저장한다. 이후 자료가 추가돼도 같은 요청은 바뀌지 않으며 새 요청에서 검색한다. 이는 제한된 저장 검색 결과이며 현실에 근거가 없다는 뜻이나 의미 관련성 인증이 아니다.

별도 metadata와0011 migration으로 새 테이블만 추가한다. 기존 작업 SQL gate를 권한 잠금보다 먼저 획득해 잠금 순서를 유지한다. AI·예약·research run·evidence job·queue 생성은 없다.

## 검증

신규 집중 검사62개를 합성 PostgreSQL에서 통과했다. 실제 저장 색인·현재 세션/역할·원문/제목 hash·동일 요청 동시성·검색 재호출 금지·negative cache·raw/rehashed 변조·기존 예산/run/job 무변경을 확인했다. 실행9ecdce0/기존 검사 보완14e1585·전체9,657개(Python8,837+JS820)·Ruff/format/mypy·타입/빌드/OpenAPI가 통과했고 실패/skip/warning0이다. 태스크 검토 C0I0M1·전체 검토 C0I0M2 후 문서 보완f11df42의 재검토 C0I0M0이며, 표시 정보 단독 삭제 집중 검사는 비차단 후속1개다. 실행 파일은 전체 검사 시작 이후 바꾸지 않았다.

새 migration을 추가하자 기존0010 검사가 최신 head 전체를 downgrade하고0010까지만 복구하는 가정이 실패했다. 실제 RED를 확인한 뒤 동일 연결/트랜잭션에서0010 revision의 실제 upgrade/downgrade만 검사하도록 기존 검사1개를 수정했다. version stamp나 schema 우회 없이 최신 테이블/version을 유지한다. 전체 migration 경로는 별도 검사한다. 원래485파일의 사전 hash를 보존하고 이 예외 외484파일·이전52증거의 동일성을 확인한다.

## 판단·비용·후속

1. 기존 문자 검색을 사용해 추가 AI 비용을 없앴다. 의미 관련성·자료 완전성은 보장하지 않는다.
2. 요청별 선택과 no_match를 고정했다. 새 자료 반영은 새 요청이 필요하다.
3. 작업 SQL gate를 공유했다. 잠금 순서를 유지하지만 검색 중 다른 작업이 기다릴 수 있어 운영 부하 인수가 필요하다.
4. 기존 migration 검사1개를 해당 revision 작업에 한정했다. 검사 파일 수정 비용이 있으며 기존484파일 보존과 전체 경로 검증을 별도로 유지한다.
5. 동일 hash의 표시 정보 복원을 유지한다. 표시 정보 삭제만으로는 실패하지 않으며, 이 경우만의 집중 회귀 검사는 후속으로 남는다.

선택한 여러 자료를 영속 AI 작업으로 연결하고 결과를 브리핑으로 변환하는 경로는 아직 연결하지 않았다. 현재 앱·기본 worker·main은 유지한다.

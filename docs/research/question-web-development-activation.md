# 질문·브리핑 개발 서버 적용 결과

2026-10-27. [적용 계획](../changes/question-web-development.md)의 개인 개발 전환을 완료했다. 개발 주소는 https://dev.issuedigest.projects.ai.kr/ 이며 제품 소스는 검증된9170e06이다. main 병합·운영 공개 배포는 아니다.

## 실제 확인

- 같은 서버 OpenAI 키로 고정 모델 gpt-6.1-sol 조회 성공. 운영 점검에서 생성 요청은 보내지 않았다.
- 기존0009에서0012로 명시 마이그레이션하고 별도 question DBOS schema를 준비했다. 기존 소유 역할을 사용하며 앱은 새3테이블 SELECT/INSERT/UPDATE만 갖는다. DELETE/TRUNCATE/TRIGGER/REFERENCES 및 DB/public/전용 schema CREATE는 허용하지 않는다. 기존 역할·기존 객체 권한·default privileges는 보존했다.
- 기존 API와 worker를 정상 종료하고 새 소유 API/단일 executor를 시작했다. 전용 질문 경로를 켜고 처리하지 않는 옛 생성 접수는 껐다. 기존 읽기는 유지한다.
- 자신의 내부 프록시만 새 정적 빌드로 전환했다. 이전 hashed assets도 보존하고 SSE buffering을 끄며 upstream의 no-buffer 헤더를 전달한다. 외부 프록시/DNS/TLS는 바꾸지 않았다.
- 외부 HTTPS home·health·status·공개 브리핑200, guest session과 유효 UUID4의 보호 목록401, 새 index가 참조하는6자산200을 확인했다. 내부에서는 새 전체 자산의 응답 바이트를 빌드와 비교했다. 공개 목록 바이트도 전환 전과 같다. 비회원 점검 응답은 쿠키를 발급하지 않았다.
- 기존 DB/OAuth/origin 설정이 새 프로세스에서 같음을 확인했다. 실제 사용자 쿠키를 추출하거나 로그인 세션을 만들지 않았다.

## 보존·복원

전후 full/app 백업을 서버 밖 비공개로 보존했다. 별도 PostgreSQL18.6에 전 백업의23테이블, 후 백업의26테이블을 복원해 각각 source audit와 일치했다. 전후 기존23테이블의 정규화 row hash/count는 동일하다. 비교에서 auth_sessions.last_activity_at만 제외하므로 세션의 모든 timestamp가 불변이라고 주장하지 않는다. 이전 DBOS 전체 행도 보존하고 새 작업은0이다. 자신이 만든 복원 컨테이너·익명 volume만 제거했다.

## 중간 실패와 수정

최초 역할 선택은 기존 버전 테이블 SELECT가 없어 DDL 전에 중단됐다. 실제 기존 소유 역할의 권한을 읽기 전용으로 확인한 뒤 재시도했다. 생성된 새 테이블의 default grant가 DELETE까지 포함해 검사가 멈췄고, 새3테이블의 DELETE만 회수했다. 기존/default 권한은 수정하지 않았다.

정상 종료 중 프로세스 정보가 사라지거나 비어지는 경합을 전환 도구가 실패로 처리해 API가 일시 중단됐다. 기존 프로세스의 종료를 확인하고 저장한 설정·빌드·후보 프록시를 재검증해 새 실행을 이어갔다. 마지막 비회원 검사의 임시 ID는 UUID4가 아니어서422였으며 유효 UUID4의401로 다시 확인했다. 원래 실패 기록과 별도 재개 기록은 비공개로 보존했다. 실패를 없애기 위해 데이터를 지우거나 마이그레이션을 되돌리지 않았다. 각 보완은 독립 검토를 거쳤다.

## 남은 확인

실제 Google 계정의 기존 브라우저 세션과 질문→자료 분석→최종 생성→저장 브리핑을 사용하는 실사용 검증이 남는다. 모델 조회·서버 응답 성공을 생성 권한·문장 의미 품질·중립성 통과로 간주하지 않는다. 인증된 외부 SSE의 실제 전송 품질도 이번 비회원 점검으로 입증하지 않았다. 기존 제품537파일은 이전 전체10,327개 검사 검증본과 바이트가 동일하며 문서/운영 작업을 이유로 전체 제품 검사를 반복하지 않았다.

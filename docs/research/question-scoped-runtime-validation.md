# 근거 범위 참조의 생성·내구 실행 · 검증

2026-10-27. [계약](../changes/question-scoped-runtime.md). 새 scoped converter를 생성 SDK v5와 저장된 계획·실행 큐·최종 브리핑·SQL 저장 읽기에 연결했다. 코드/모의 인수와 실제 생성·내용 의미·앱 인수를 구분한다.

## 구현·회귀

v5는 지원 문장은 인용 전체에서 유일하게, 나머지 참조는 같은 명제의 지원 범위 안에서 유일하게 결정한다. 저장된 canonical 영수증도 위치만 제거한 별도 DTO를 다시 구성해 같은 결과인지 검증한다. 기존 생성2/3/4·원문·질문·schema·transport와 최종 생성 지침은 바꾸지 않았다. 신규 SDK71개와 관련214개를 통과했다.

migration0014는 두 테이블의 열·제약을 모두 검사한 뒤 실행 버전을2/3/5로 확장한다. 과거 migration이 현재 Table metadata를 사용하는 이력 때문에 metadata CHECK는 기존2/3 baseline을 유지하고 최신 DB는 명시 migration으로만 구성한다. 독립 검토에서 SQL 문자열 리터럴 안의 cast처럼 보이는 문자를 지우던 사전 검사를 발견했다. 수정 전 신규7개 실패와 수정 후 관련146개 통과를 보존했고 재검토를 통과했다. unknown/중복/NOT VALID 제약·잘못된 열은 DDL 전 거부하며 v5행이 있으면 downgrade를 거부한다.

새 내구 workflow만 v5를 사용하고 기존v2/v3 workflow·슬롯·identity를 보존한다. 계획의 버전으로 부분 재개를 고정하며 혼합·잘못된 workflow는 상태 변경/송신 전에 거부한다. 모의2/3/5에서 ANSWER→최종 SQL 저장/재열람 일치·재접수 추가0을 확인했다. 관련181개·내구 실행287개·잘못된 버전15개와 사전 고정한 v2/v3 최종 전송 bytes 일치를 확인했다. 실험v4는 실행에 연결하지 않았다.

## 전체 검사·독립 검토

Python9,876개(app1,553/agents5,795/storage 등2,528)와 JS915개, 총10,791개를 통과했다. 모든 Python testpath를 격리 DB 세 곳에 중복 없이 나눴으며 Python/프론트 린트·타입·빌드·OpenAPI 검사도 통과했다. 검사 중 실행 파일552개의 bytes를 보존했다. 기준548개 중 의도한20개만 변경되고528개는 동일하다. 태스크별 독립 검토와 전체 백지 컨텍스트 검토를 통과했으며, 전체 검토자는 별도 오프라인538개도 실행했다.

실제 검증 도구도 독립 검토했다. 모의 성공이 cleanup 전에 기록되던 문제와 최종 SQL/reader 동등 검사를 보완했다. 수정 전6개 실패·수정 후21개 통과와 독립 재실행을 기록했다. supervisor 종료0·cleanup·동결 코드/입력/의존성·모의 요약/시도 해시를 함께 검증한 뒤에만 실제 호출을 허용한다.

## 제한 실제 결과

동일 원문·질문·사전 기준, 제품/도구/의존성401개 파일을 고정하고 소유 격리 PostgreSQL18.6·migration0014·합성 계정으로 실행했다. native 모의에서는 분석→최종 ANSWER→SQL 저장/재열람 동등·재접수 추가0을 확인했고 별도 아티팩트 검토를 통과했다. 실제는 고정 모델, 분석/최종 각0.50달러 예약, 요청 최대2·무재시도·전체600초 종료 조건으로 한 번만 수행했다.

실제 분석1회는 연속 공백 한도를 넘어 reason=whitespace/status=failed로 중단됐다. 최종 생성/작업은0이고 완성 분석 영수증도 없다. stream close 성공과 원응답을 보존했으나 완료 이벤트·최종 사용량은 관측하지 못했다. 사용량 미관측을 무료로 해석하지 않으며 원래 예약·송신 의도와 실패를 유지한다. 원래 응답을 자르거나 수리하거나 재호출하지 않았다. 실제 최종 저장·의미 필수3단위/전체12단위·앱 인수는 통과하지 않았다.

별도 독립 결과 검토에서도 공백 run257(한도256)의 재현과 고정401파일·실제 전송 입력 일치를 확인했다. 완성된 JSON 이전의 formatting 정체이며 scoped 참조 변환의 거부가 아니다. 필수3단위와 나머지9단위는 미평가다.

원응답·실행 journal·SQL·실제/모의 DB dump와 사전 기준을 비공개 보존했다. 호스트의 오래된 pg_restore가 dump 목록을 읽지 못한 최초 오류를 남겼고, 같은 PostgreSQL18 컨테이너의 도구로 목록 검증을 완료했다. 이 문제는 AI 호출/생성 실패와 별개다.

## 적용 경계·다음 작업

공동 DB·현재 개발 서비스·사용자 세션·main/운영은 변경하지 않았다. 기본 버전은v2이며 새v5는 서버 opt-in만 허용한다. Verify foundation은 disabled_manually다. 이전 여덟 묶음561개 기록과 과거 실제 실패/usage를 보존했다. 자신의 QA4개와 익명 volume를 정리하고 실제/모의 dump를 남겼다.

다음은 관측된 생성 정체를 별도 계약과 오프라인 재현으로 좁히는 작업이다. 이번 구조/모의 성공을 실제 생성 안정성으로 취급하지 않는다. 새로운 실제 인수와 최종 내용/저장·앱 검증 후 백업/복원·공동 migration·개인 개발 전환을 진행한다. v5행 생성 뒤 이전 binary로 되돌리는 대신 새 다중 버전 코드에서 새 접수만v2로 전환하는 복구 경계를 유지한다.

## 설계 제안 · 아직 확정하지 않음

- 질문을 기본 입구로 두고 최근 이슈 훑기를 함께 제공한다. 미리 자료를 선택해야 하는 단계는 필요할 때 조사 범위를 좁히는 보조 기능으로 검토한다.
- 이슈 하나의 맥락·주장·근거·변화·질문을 이어서 볼 수 있게 한다. ‘작업 공간’, UUID 등의 내부 용어를 대표 이름으로 사용하지 않는다.
- 첫 결과는 간단한 브리핑부터 시작하고, 관련 주장과 반응·원문을 이어서 탐색하는 구성을 제안한다. 결과 분량·채팅 비중·첫 화면 배치는 인터뷰 중이다.
- 원문에서 특정 문구가 발견됐다는 것, 당사자가 그렇게 주장했다는 것, 해당 주장이 독립 근거로 뒷받침된다는 것은 다르다. 저장 인용/현재 canonical 참조 검증만으로 ‘사실 검증 완료’ 배지를 붙이지 않는다. 주장 지지 판정은 별도 평가·설계가 필요하다.
- 중립성은 출처·시점·불확실성의 명시로 설계한다. 기계적인 찬반50:50 배분·AI의 무근거 진실 점수·자료 부족을 거짓으로 판정하는 동작은 제안하지 않는다. 확인된 모순을 다루는 표현과 기준은 추가 논의한다.
- 여론조사는 질문·대상·방법·조사일·표본/오차·출처를 함께 본다. 인지도·찬반·정당 지지도는 별도 항목이다. 언론 보도량·논점과 온라인 반응은 국민 전체의 여론 추정치로 합산하지 않는다.
- 온라인 반응의 수집 가능성·플랫폼 약관/재게시·표본 편향·개인정보·중복/조직 활동 영향과 수치화 가능 범위를 조사해야 한다. 아직 데이터 연결 완료로 표시하지 않는다.
- 최근 이슈 선정은 수집 범위/기간/관측 지표·갱신시각을 드러내야 한다. 임의로 고른 카드에 ‘현재 가장 화제’라고 표시하지 않는다. 선정 기준·다양성·개인화 여부는 후속 인터뷰다.
- Generative UI는 질문과 근거에 따라 브리핑·비교·타임라인·조사 결과·출처를 조합하는 역할로 제안한다. 사용자의 위치·선택·이전 결과를 잃는 전면 재배치는 피하고 생성 중/완료/오류/자료 부족을 식별 가능하게 만든다. 차트·관계·이미지는 의미 있는 근거가 있을 때만 사용한다.
- 시각 방향은 읽기 쉬운 본문·명확한 정보 위계·절제된 색상과 근거 열람을 우선하는 조사 화면을 제안한다. 실제 컬러/서체/밀도/모션·화면 시안은 인터뷰 후 비교하며 확정하지 않았다.

- 첫 결과의 분량: 30초 요약→확장 / 2~3분 브리핑 / 촘촘한 비교.
- 상호작용: 결과 중심 동적 화면 / 채팅 중심 / 결과와 대화 병렬.
- 이해한 뒤 행동: 후속 탐색 / 관심 이슈 저장·변화 추적 / 동료 공유·의논.

## 현재 화면에서 개선할 점 · 기존 검증 화면·코드 기준

- 자료 목록과 질문이 항상 병렬인 구조는 질문 우선 진입과 맞지 않는다. 입력 전에 자료를 고르는 부담을 줄여야 한다.
- 현재 결과는 모듈별 긴 목록이어서 이슈 전체 맥락·쟁점·미확인 부분을 먼저 파악하기 어렵다. 질문에 대한 간단한 브리핑과 상세 탐색의 위계를 마련한다.
- 모바일 비교표의 열이 좁아 긴 한국어 문장을 지나치게 잘라 보여준다. 작은 화면에서는 주장별 읽기·필요한 항목끼리 비교하는 방식으로 재구성할 수 있다.
- ‘AI 해석’과 원문 링크가 항목마다 반복돼 밀도가 높아진다. 출처와 해석 구분은 유지하면서 필요한 위치에서 상세를 여는 방식을 비교한다.
- 새 UI가 최근 이슈·사실 확인·여론 탐색을 지원한다고 보이려면 수집 범위와 근거 평가도 함께 구현해야 한다. 디자인만으로 없는 데이터를 채우지 않는다.

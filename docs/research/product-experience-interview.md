## 설계 제안 · 아직 확정하지 않음

- 이슈 하나의 맥락·주장·근거·변화·질문을 이어서 볼 수 있게 한다. ‘작업 공간’, UUID 등의 내부 용어를 대표 이름으로 사용하지 않는다.
- 브리핑형 기본 결과 화면, 30초 요약과 결과 중심 상호작용은 사용자 선호로 정해졌다. 관련 주장과 반응·원문을 이어서 탐색하는 구체적인 조작은 제안 단계다. AI가 필요한 탐색·비교·시각화를 선택하는 방향은 사용자 답변으로 정해졌다.
- 원문에서 특정 문구가 발견됐다는 것, 당사자가 그렇게 주장했다는 것, 해당 주장이 독립 근거로 뒷받침된다는 것은 다르다. 저장 인용/현재 canonical 참조 검증만으로 ‘사실 검증 완료’ 배지를 붙이지 않는다. 주장 지지 판정은 별도 평가·설계가 필요하다.
- 중립성은 출처·시점·불확실성의 명시로 설계한다. 기계적인 찬반50:50 배분·AI의 무근거 진실 점수·자료 부족을 거짓으로 판정하는 동작은 제안하지 않는다. 확인된 모순을 다루는 표현과 기준은 추가 논의한다.
- 여론조사는 질문·대상·방법·조사일·표본/오차·출처를 함께 본다. 인지도·찬반·정당 지지도는 별도 항목이다. 언론 보도량·논점과 온라인 반응은 국민 전체의 여론 추정치로 합산하지 않는다.
- 온라인 반응의 수집 가능성·플랫폼 약관/재게시·표본 편향·개인정보·중복/조직 활동 영향과 수치화 가능 범위를 조사해야 한다. 아직 데이터 연결 완료로 표시하지 않는다.
- 최근 이슈 선정은 수집 범위/기간/관측 지표·갱신시각을 드러내야 한다. 임의로 고른 카드에 ‘현재 가장 화제’라고 표시하지 않는다. 최근 주목 이슈와 개인화된 이슈의 혼합은 사용자 선택이며, 개인화 입력·혼합 기준·다양성·이유 표시는 후속 설계다.

## 모바일 결과 화면 비교 · 브리핑형 선택

2026-10-16. 같은 가상 정책 내용을 사용하는 두 결과 화면을 대화 안에서 비교했다. 사용자는 “브리핑이 더 자연스럽습니다”라고 답했다. 브리핑형을 기본 결과 화면으로 선택했으며 운영 앱 변경·새 AI 기능 구현 완료를 뜻하지 않는다.

| --- | --- | --- |
| 브리핑 | 30초 요약과 자료로 확인한 내용·엇갈리는 주장·미확인 내용 | 궁금한 항목에서 비교·반응·근거를 열고 읽던 화면으로 복귀 |
| 탐색 | 짧은 전체 요약과 주장·근거 비교 | 같은 이슈 안에서 쟁점 비교·여론·변화를 전환 |

브리핑형 기본 구성은 사용자 선택이다. 질문에 따라 비교·변화 등의 상세 모듈을 여는 구체적인 전환 방식, 주장·근거 비교를 첫 상세 모듈로 고르는 것은 설계 제안이다. 시안의 색상·서체·세부 조작 전체가 승인된 것으로 해석하지 않는다.

두 시안에서 근거 열기·닫기, 관심 이슈 저장 상태, 재방문 시 바뀐 내용 표시, 여론조사/언론/온라인 반응 구분, AI 동작 설명을 비교한다. 실제 AI 호출·수집·영구 저장·알림은 연결하지 않는다. 가상 문서는 화면 구조와 근거의 해석 범위를 검토하기 위한 것으로, 실제 이슈·사실 판정·여론 수치로 사용하지 않는다. 질문 입력부터 생성 진행·실패·취소까지의 흐름과 PC 조사 화면은 후속 시안 범위다.

생성 중 경험은 근거를 확인한 내용부터 표시하고 나머지는 조사 중으로 구분하는 방식으로 사용자가 선택했다. 이어 제시했던 ‘각자 저장/두 사람 공동 목록’ 질문은 B2C가 아닌 두 동료의 작업을 전제했으므로 철회한다. 해당 질문에 대한 사용자 선택은 없으며 공동 목록을 기본 요구사항으로 채택하지 않는다. 첫 화면에서 빠진 정보와 읽기·탐색을 방해하는 구체적 요소, 컬러/서체/밀도는 이후 구체화한다.

### B2C 이용 흐름 · 묶음 인터뷰 답변

서로 독립적인 다섯 항목을 선택형 UI로 한 번에 질문했고 다음 답변을 받았다.

- 비회원은 브리핑을 읽을 수 있고 AI 질문부터 로그인한다. 로그인 전 작성한 질문을 보존해 인증 후 이어가는 동작은 설계 제안이다.
- 홈은 최근 이목이 집중되는 이슈와 개인화된 이슈를 혼합한다. 공통 이슈와 관심 이슈를 반드시 별도 목록으로 나누는 안은 채택하지 않았다. 입력 신호·혼합 비율·갱신·평가·이유 표시는 아직 미정이다.
- 공유 당시의 브리핑과 근거를 보존하고 최신판도 안내한다. 공유본의 생성 시각·근거 시점 표시, 개인 질문·기록의 공개 제외와 공유 취소·접근 범위는 세부 설계가 필요하다.
- 읽기·AI 질문·저장·공유에 집중하고 공개 댓글은 두지 않는다. 반응·투표도 이번 선택으로 추가하기로 결정한 것은 아니다.
- 중요 변화 알림의 첫 채널은 서비스 안의 알림함이다. 이전에 답한 새 사실·공식 결정·정정의 우선순위와 함께 적용한다. 이메일·휴대폰 푸시는 첫 채널로 선택하지 않았다.

개인 관심 이슈와 조사 기록을 비공개로 두고 명시적으로 선택한 브리핑만 공유하는 것을 기본 설계 가설로 둔다. 서비스 이용자의 반응을 국민 전체의 여론으로 해석하지 않는다. 이 인터뷰는 현재 개발 앱의 접근 제한을 해제하거나 공개 배포·알림 발송을 실행하는 작업이 아니다.

### B2C 후속 묶음 · 답변 대기

서로 독립적인 네 항목을 선택형 UI로 질문했다. 답변 전의 추천은 설계 제안이며 확정 사항이 아니다.

- 개인화 입력: 직접 선택한 관심사부터 시작할지, 열람·저장 또는 질문 이력까지 사용할지.
- 첫 공개 서비스 범위: 국내 정치·정책 / 국내 시사 전반 / 국제 이슈 포함.
- AI 자료 탐색 범위: 연결 출처 우선 후 외부 웹 확장 / 연결 자료만 / 웹 전반 탐색.
- 초기 AI 이용 정책: 무료 횟수 제한 후 검증 / 기본 무료·심화 유료 / 유료 구독 중심. 미정 응답도 가능.

위 답변 후 홈→로그인→생성 중→브리핑→상세 근거→관심 이슈·알림함→고정 공유본의 화면 흐름을 연결하는 시안으로 확인한다. 추천 알고리즘·외부 도구 실행·과금은 UI만으로 구현 완료로 표시하지 않는다.

### 점진적 브리핑 표시 · 사용자 선택과 설계 제안

사용자는 확인된 내용부터 읽고 나머지를 조사 중으로 표시하는 방식을 선택했다. 전체 조사 완료 후 한 번에 표시하는 방식은 기본으로 삼지 않는다. ‘확인’은 해당 내용의 근거를 확인했다는 의미이며, 인용 문자열이나 출처가 존재한다는 이유만으로 주장 전체의 진실성을 검증했다고 표시하지 않는다.

설계자는 조사 중인 영역과 자료 부족으로 마친 영역을 구별하고, 추가 조사로 기존 문장이 수정되면 변경을 표시하며 읽던 위치를 유지하는 방식을 제안한다. 이는 아직 세부 동작에 대한 사용자 선택이 아니며, 타이핑 중인 모델 출력을 검증 없이 사실 영역에 바로 노출한다는 결정도 아니다. 실제 부분 결과 생성·근거 확인·전달 방식과 실패/취소 처리는 구현 설계와 검증이 필요하다.

## 기본 구성 선택과 남은 설계 가설

모바일의 이슈 브리핑을 기본 결과 화면으로 삼는 방향은 사용자 선택이다. 질문에 따라 깊은 탐색 화면을 여는 구체적인 전환은 설계 가설이다. 질문/최근이슈→30초 요약→사실·주장·미확인 구분→필요한 비교/변화/반응/원문 탐색→관심 이슈 저장→재방문 시 최신 전체 요약의 변경 표시를 잇는다. PC는 본문/근거를 병렬로 두는 구성을 검토한다. 관심 이슈·지속 갱신·알림·최신 이슈 발견은 현재 구현이 아니며 새 데이터·저장/평가/비용 정책이 필요하다.

사용자 참고 사례를 그대로 복제하는 결정은 하지 않았다. 설계자는 이를 AI의 도구/화면 표현력, 단순한 조작/명확한 상태, 타이포·여백·일관된 전환의 마감이라는 기준으로 해석한다. 카드·배지·기술 설명·장식의 양을 늘려 풍부함을 표현하지 않는다. 실제 근거와 질문에 필요한 시각 모듈을 구성하며 모바일 표는 읽기 단위로 재구성한다. 작은 화면에서 읽던 위치/선택/이전 결과를 잃지 않도록 한다. 구체적 시각안·색/서체·레이아웃은 아직 승인하지 않았다.

최근 이슈는 여러 매체의 새 보도 관측을 기준으로 설계하되, 동일 배포기사의 재전재를 중복 관심도로 세거나 보도량을 국민 인지도/찬반으로 해석하지 않도록 한다. 수집한 매체 범위·기간·갱신 시각과 선정 근거를 밝혀야 한다. 개인화된 이슈와 혼합하는 홈 구성은 사용자 선택이다. 중요 변화 알림은 서비스 내 알림함을 첫 채널로 선택했으며 중요도 기준·도달 지연·설정·비용은 후속 설계다. 아직 모니터/알림을 생성하지 않았다.

현재 조사 실행은 저장 자료의 제한된 검색과 구조화 모듈 선택으로, 자율 웹 탐색·외부 도구 조합·관심 이슈 추적을 완료한 상태가 아니다. 새 자율 경험에는 승인 출처 도구·현재 권한·도구별 진행/실패·근거/예산·저장/재시작을 이어야 한다. 기존 단일 호출 한도를 임의로 늘리거나 브라우저/임의 코드 실행을 이번 인터뷰로 승인받았다고 해석하지 않는다.

## 현재 화면에서 개선할 점 · 기존 검증 화면·코드 기준

- 자료 목록과 질문이 항상 병렬인 구조는 질문 우선 진입과 맞지 않는다. 입력 전에 자료를 고르는 부담을 줄여야 한다.
- 현재 결과는 모듈별 긴 목록이어서 이슈 전체 맥락·쟁점·미확인 부분을 먼저 파악하기 어렵다. 질문에 대한 간단한 브리핑과 상세 탐색의 위계를 마련한다.
- 모바일 비교표의 열이 좁아 긴 한국어 문장을 지나치게 잘라 보여준다. 작은 화면에서는 주장별 읽기·필요한 항목끼리 비교하는 방식으로 재구성할 수 있다.
- ‘AI 해석’과 원문 링크가 항목마다 반복돼 밀도가 높아진다. 출처와 해석 구분은 유지하면서 필요한 위치에서 상세를 여는 방식을 비교한다.
- 새 UI가 최근 이슈·사실 확인·여론 탐색을 지원한다고 보이려면 수집 범위와 근거 평가도 함께 구현해야 한다. 디자인만으로 없는 데이터를 채우지 않는다.

- 사용자가 이전에 요청한 AI 동작 설명은 필요한 위치의 도움말로 유지하는 방향이다. 화면의 주 문구는 질문·근거·결과·변화로 쓰고 DBOS/내부ID/수집 구현 설명은 선택적으로 연다. 생성 시작/진행/부분 또는 전체 완료/자료 부족/실패는 도움말 없이도 알아볼 수 있어야 한다.

## 데이터·구현에 미치는 영향 · 설계자 판단

첫 수집 연결기는 법안 제안 내용이지만 서비스의 주 화면을 법안 목록으로 한정하지 않는다. 사용자 과제에는 최신 뉴스·공식 발표·당사자 발언·여론조사가 핵심 입력이다. 읽기 확인한 legacy 법안41,004건의 제안일 상한2026-07-10만으로 현재 이슈 선정·국민 인지/선호를 채웠다고 표시하지 않는다. 이슈 발견·출처별 관점/주장 추출·상호 대조·조사 문항 연결이 별도 필요하며 실제 수집 가능성과 이용 범위부터 확인한다.

## 이후 확인할 주제

첫 화면의 이슈 선정·질문 진입, 결과 화면 우선순위와 출처 표시, AI 생성 화면의 자유도·수정·취소·되돌리기, 개인 관심 이슈/변화 추적·알림, 외부 공유/기록, 대표 단말·정보 밀도·가독성/접근성, 시각 취향과 피하고 싶은 사례, 실패/불확실성 표현, 이용량 제한·수익 모델, 사용자가 직접 평가할 완료 기준. 독립적인 항목은 선택형 UI로 묶고, 앞선 답변에 의존하는 항목만 후속 질문으로 진행한다.

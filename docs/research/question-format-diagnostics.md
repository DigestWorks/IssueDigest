# 생성 정체의 비교 진단

2026-10-27. [진단 범위](../changes/question-format-diagnostics.md)·[직전 실제 결과](question-scoped-runtime-validation.md). 추가 API 호출 없이 이전 세 원응답과 송신 내용을 비교했다. 생성 코드·한도·과거 실패는 바꾸지 않았다.

## 확인한 결과

| 원래 실행 | 출력 관측 | 동일 guard 재생 | 모델 완료·최종 usage |
| --- | --- | --- | --- |
| v3 내구 실행 | 수치 상한 연산자 뒤 공백 반복 | 문자열 밖 연속257에서 거부 | 미관측 |
| v4 compact JSON | 완결된 JSON | 공백 한도 거부 없음 | 관측 |
| v5 범위 참조 실행 | 같은 수치 상한 연산자 뒤 공백 반복 | 문자열 밖 연속257에서 거부 | 미관측 |

두 실패는 같은 명제/조건의 연산자 `lte`를 생성한 뒤 발생했다. 실제 송신 schema는 이 값을 허용하며 그 값 객체에는 다른 필수 필드가 없다. v4 원응답에는 같은 위치의 객체를 닫고 다음 조건으로 진행한 완결 예가 있다. 따라서 이 위치가 schema상 명백한 막다른 길이라는 근거는 없다. 이 관측은 제공자 내부의 생성 원인이나 실패 출력 전체의 유효성을 증명하지 않는다.

세 요청의 parameter schema·질문·인용 내용은 같다. 지침·tool 이름·input_format은 함께 달라졌으므로 한 변수의 효과를 비교한 실험이 아니다. v4는 모델 응답이 완결됐다는 뜻이며, 기존 SDK는 반복 참조 때문에 그 실행을 거부했다. 기존 실패를 성공으로 바꾸지 않는다.

실패는 참조 변환 전에 일어났다. 이번 자료로 scoped 변환의 실제 수용 여부나 내용 의미를 판정할 수 없다. 공백 guard는 관측된 이상 응답을 중단한 것이며 한도를 늘려 생성 안정성 문제를 해결했다고 보지 않는다. 두 실패의 최종 사용량·제공자 최종 상태는 미관측이고 예약0.50달러는 실제 청구액이 아니다.

## 검사·보존

비공개 재현 도구의7개 검사는 여러 줄 SSE, 잘린 이벤트/문자열, 마지막 구분자 없는 이벤트, 이스케이프된 따옴표·괄호, 문자열 내부 공백, 중첩 배열 경로를 포함한다. 원래 delta 경계로 기존 guard를 재생하고 완성된 예만 별도 JSON으로 읽었다. 실패한 JSON을 수리하거나 일부 내용에 의미 점수를 부여하지 않았다.

독립 결과 검토에서 spec/진단 품질 PASS·차단 문제0을 확인했고 검토자도7개 검사를 재실행했다. 이전 아홉 검증 묶음678개 파일을 원래 manifest와 대조했다. 제품 코드·DB·앱·main/운영·Actions 설정은 변경하지 않았다. 제품 코드 변경이 없으므로 직전 전체10,791개를 이번 신규 검사로 다시 합산하지 않고 진단 검사7개와 구분한다.

## 다음 생성 전략의 기준

같은 요청에 지침만 추가하는 버전 증가는 중단한다. 생성부의 모델/전송 방식/출력 구조를 구분해 한 번에 한 변수만 바꾸는 비교 계획을 먼저 고정한다. 동일 원문·질문·출력 의미 계약·안전 한도·무수리/무재시도는 공통 조건이다. 비교마다 모델 완료/구조 수용, 정확 참조, 내용 의미, 최종 저장, usage 관측을 따로 기록한다.

현재 자료만으로 특정 대체 모델이나 schema 단순화를 해결책으로 채택하지 않는다. 후보 선택은 현재 사용 가능한 모델·지원 형식·예산을 확인한 뒤 결정하고, 원본을 유지하는 왕복 검증과 실패 경계 모의를 먼저 수행한다. 새 유료 실험은 별도 동결·사전 검토·호출 상한으로 진행한다. 이번에는 호출0·개발 사이트 변경0이며 실제 생성 안정성·최종 브리핑·앱 인수는 남는다.

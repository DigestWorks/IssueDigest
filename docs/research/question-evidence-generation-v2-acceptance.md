## 응답 전 고정

[v1 실제 미완료](question-evidence-generation-acceptance.md)와 같은 전체 개발 원문·질문Q2를 사용하고, 원래 질문4개/필수12명제·Q2필수3명제(P5/P9/P10)·루브릭을 bytes/hash 그대로 복사한다. 새 v2의 출력4,000/요청 timeout60·총20,000·독립 profile/input/tool/지침을 검증한다. 모델은 같은 `gpt-6.1-sol`/reasoning low/standard(default)로 고정한다. 전체 원문/정확 질문을 줄이지 않고 strict tool1개/no-store·요청1회·SDK/transport 재시도0을 유지한다. timeout60은 요청 설정이며 전체 wall-clock SLA가 아니다.

실제 송신 전 원문/기준/루브릭/현재468코드·실제 모의 body/지침/도구/설정과 이 프로토콜을 hash로 고정하고 새 namespace의 소진 잠금을 먼저 만든다. v1의 미완료/사용량·잠금은 유지하며 v2에서 한 번만 송신한다. 미완료·형식/의미 실패·네트워크 오류 후 재시도/보정·한도 상승·모델/자료 교체는 없다. 이전 runner와 소진 namespace를 실행/수정하지 않는다.

## 사전 판정과 분모

- P5: 신청기관이 대규모·중규모 각각 최대1곳을 신청한다는 의미. 같은 명제의 수치/상한/분배 대상·신청 상태가 맞아야 하며 선정 계획 개수로 바꾸지 않는다.
- P9: 광역자치단체와 명시 법률상 공공기관이라는 신청 자격의 주체·범위를 보존한다.
- P10: 공공기관이 상위기관의 승인을 받고 신청한다는 주체·승인 주체·선행 조건을 연결한다.

선택된 명제의 좁은 의미 필드와 직접 연결된 정확 인용만 판정한다. 전체 입력이나 무관한 출력에 단어가 있다는 것만으로 성공으로 세지 않는다. explicit/equivalent/partial/not_represented/contradicted/undetermined를 구분하고 partial은 완전 보존 성공이 아니다. 불명확한 주체/지표·상대 시간은 uncertain으로 유지하며 추론으로 보충하지 않는다. 기존 질문Q2의3필수와 다른 질문9명제를 구분하고 전체12분모를 유지한다. 다른 질문은 미평가이며 전체 서비스 성공을 주장하지 않는다.

HTTP/모델 완료/strict SDK 반환/현재 Source·질문에 대한 저장 DTO 왕복/의미 판정을 따로 기록한다. SDK 거부 응답의 부분 JSON은 수리하거나 의미 성공으로 전환하지 않는다. 유효하지만 빈 부족 응답도 의미 성공이 아니다. 원래 요청·응답·raw usage와 SDK knownusage·송신 불확실성을 비공개 보존하고 키/헤더·비공개 원문/질문은 공개하지 않는다. 추론은 출력에 포함되며 추가 가산하지 않는다. 실제 청구서·캐시 과금 TTL·비용 증가율을 확인하지 않고 금액으로 확정하지 않는다.

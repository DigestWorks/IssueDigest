## 응답 전 고정한 단위·분모

질문에 필요한12명제를 원문 위치·적용 질문·단위/범위·목표 상태·관계와 함께 비공개 고정한다. 그중8개 수치 명제에10개 숫자 anchor가 필요하고, 나머지4개는 신청 자격·기관 승인·법적 지위·후속 절차라는 비수치 명제다. 중요도 required는 이 개발 질문에 한정한다. 기존 질문 없는J/K의 중요도10유보를 바꾸지 않는다.

수치 후보 검출은 각 명제의 **모든** 고정 numeric anchor가 같은 원문 위치의 현재 후보에 포함됐을 때만 해당 명제를 검출로 센다. 범위/날짜가 두 숫자로 나뉘면 한쪽만으로 성공시키지 않는다. 날짜의 월/연도를 추정하거나 좌석과 수용 인원을 합치지 않는다. 검출 자체는 조건/의미/질문 답변 정확성의 승인이 아니다.

비수치4명제는 전체 질문에 필요하지만 numeric-candidates-v2의 수치 탐지 대상 밖이다. 이를 수치 false negative4건으로 세지 않으며, 후보 검출8/8이 나와도 전체12명제 recall100%로 확대하지 않는다. 비수치 명제를 읽을 원문 기반 도구/최종 설명 경로가 별도로 필요하다.

## 사전 입력 한도와 실행 규칙

현재 balanced v2의 전체 본문·후보·원래 지침/동적 schema/예산을 그대로 사용한다. 전체total20,000/output1,800·30초/no-store·요청1회/재시도·수리0 경계를 바꾸지 않는다. 전체 원문 preflight가 거부되면 provider를 호출하지 않고 차단을 남긴다. 원문 축약·절단·제외·한도 상향·더 쉬운 기사 교체로 성공시키지 않는다. 이번 source의 preflight 거부를 이미 확인했으므로 유료 요청을 시도하지 않으며 실제 추출 의미12명제는 모두 미판정으로 둔다. 원래 G~K/과거 소진 runner도 재실행하지 않는다.

입력 한도는 UTF-8 prompt/지침·max(raw/normalized schema)·framing·출력 예약의 보수적 envelope다. 실제 tokenizer 토큰 수나 청구 usage로 부르지 않는다. 모델을 호출하지 않은 차단을 의미 실패나0원짜리 성공 응답으로 세지 않는다. 순수 후보 검출·입력 차단·추출 의미 미판정을 구분한다.

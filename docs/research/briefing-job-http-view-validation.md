# 저장 브리핑 조회·읽기 화면 검증

2026-10-26 KST. [명세](../changes/briefing-job-http-view.md).

이미 접수된 최종 브리핑의 상태/결과/취소를 인증 HTTP와 독립 읽기 화면에 연결했다. 질문 전송 전체경로를 완료하거나 기존 질문 버튼을 전환한 것은 아니다. 비공개 URL `/workspaces/:workspaceId/briefings/:jobId`는 내부 링크 대상이며 ID를 사용자에게 입력하도록 요구하지 않는다. 서버 반영·공개 게시·main 병합·기본 worker 활성화·실제 제공자 호출은 하지 않았다.

## 검증

신규55개 포함 전체10,126개(Python9,272+JS854), lint/format/type/build/OpenAPI 통과, 최종 실패/skip/warning0. 원래 전체 실행의 worker1,115개(runtime/test 동일), API 선행 전체 agents5,423개, 나머지 Python2,735개를 검사했다. API1개 중복을 제외한 수집 node 합집합9,272개가 전체 목록과 일치한다(수집 때 무작위 UUID 이름11개만 정규화, 정규화 후에도 고유9,272개). 단일 중단 없는 root 성공으로 표현하지 않는다. 실행 `5af8a9d37e74654263027619cff7fc477eae9b2d`와 같은 runtime/test bytes로 검증했다. API21/기존worker30와 클라이언트·화면34의 집중 검사·독립 태스크/전체 검토를 수행했다.

실제 전용 SQL·모의 native SSE에서 현재 요청자/원래 작성자·모든 원문·최종 분석/영수증·알려진 사용량을 검증하고 조회 시 예약/모델 호출이 늘지 않음을 확인했다. projection은 의존 관계와 미반영 관련 근거까지 원래 순서로 보존하며 HTML을 실행하거나 AI 서술을 독립 확인 사실로 승격하지 않는다. 정상/불충분/취소/중단 상태, body/query/Origin/UUID·비공개 헤더·offloop·변조·Unicode 인용 범위를 확인했다.

Task1 검토의 취소 requestBody 문서/의존 근거 검사 두 경미 사항을 보완했다. Task2 검토의 잘못된 배열 enum 수용과 원문 조회 도중 job 권한 변경 두 중요 사항을 회귀 검사로 수정했다. 지연 원문·focus 권한 상실·unmount 뒤 body 완료 검사도 추가했다. 수정 RED5실패→GREEN34통과 후 최종 독립 검토 미해결0이다. 추가 전체검사에서 발견한 기존 numeric/selection reload 테스트 두 곳은 원래 namespace를 finally에서 복원해 격리했고 기존 세 노드 RED1실패→GREEN3통과 및 관련231개와 전체 agents5,423개를 확인했다. 초기 중단 로그를 보존했다. 후속 전체 실행은 기존 API 경로 기대 목록이 새 두 경로를 누락해 실패했으며 세 목록에 정확히 두 경로씩만 추가했다. 분리 검사는 기존 수치 모델 클래스의 로딩 순서 실패로 중단했으며 원래 전체 실행도 두 번째 selection reload 격리 실패로 중단했다. 두 reload 격리 후 모든 agents5,423개·나머지 영역과 worker 불변 증거를 합집합으로 확인했다. 환경의 상대 ignore 옵션이 worker를 제외하지 못해 해당 중복 실행은 중단하고 나머지 경로를 명시했다.

헤드리스 실제 브라우저에서 합성 응답만 사용해1280px 비교2열,390px1열, 두테마·가로넘침0·정확 원문 창/Escape/초점복원·reducedmotion을 확인했다. JS/콘솔 오류0, GET4·mutation0·provider0이다. 결과 화면은 원래 응답의 실제 모듈만 렌더링한다. 이 브라우저 검사는 실제 계정/원문/유료 모델 품질 인수가 아니다. 검사 스크린샷은 저장소 밖에 보존하며 제품에 예시 결과를 넣지 않았다. 사용자의 열린 탭은 변경하지 않았다.

기존 실행494개·이전39증거는 byte-identical이며, 허용된14개 수정은 API/공통 검증 추출·workspace dependency·생성 계약·경로/클라이언트 exports에 한정한다. 실행/접수/소유권 함수 AST와 기존 잠금 패키지 버전을 보존했다. 기존 preflight 테스트는 실제 추출 위치의 monkeypatch 대상 한 표현식만, 오류 계약은 job_id literal 하나만 바꿨다.

## 판단과 비용

1. 저장 결과 조회·취소부터 연결했다. 기존 질문 제출을 새 코어로 전환하는 전체 orchestration은 남는다.
2. 검증을 agents로 추출해 공유한다. 중복 구현은 피하지만 기존 worker 회귀 검사가 필요하다.
3. 의존·미반영 근거까지 표시한다. 설명 맥락을 보존하는 대신 응답량과 검증량이 늘어난다.
4. 비공개 결과 링크를 공개 게시와 분리한다. 비회원이 읽는 B2C 공개 브리핑 기능을 확장한 것은 아니다.
5. conflict/unavailable/malformed 검증 실패 시 이전 화면을 정리한다. 철회로 단정하지 않지만 일시503에도 재조회가 필요할 수 있다.
6. 추출된 private preflight 테스트 대상과 job_id 오류 경로만 좁게 수정했다. 두 기존 파일 예외를 별도로 회귀 확인한다.
7. 요약/비교/타임라인을 의미에 맞게 구분했다. 임의 정당/찬반 이름은 붙이지 않으며 모바일/테마 배치 검사가 추가로 필요하다.
8. 클라이언트 테스트 이름을 기존 발견 규칙의 .test.tsx로 맞췄다. test 간 side effect import는 제거했으며 발견 규칙을 바꾸면 확장자를 함께 관리해야 한다.

9. 기존 경로 기대 집합 세 곳에 새 경로만 추가하고 변경 없는 worker 결과 재사용을 시도했다. 분리 검사 실패로 이 단축은 채택하지 않았다.
10. 기존 수집 순서의 전체 검사를 다시 수행한다. 분리 실행의 클래스 재로딩 차이를 피하는 대신 검증 시간이 늘어난다.

11. 기존 수치 import 테스트가 reload한 namespace를 finally에서 복원한다. 실제 분석 검증을 완화하지 않으며 오래된 테스트 한 곳의 격리 수정·RED/GREEN·재검토 비용이 든다.

12. 같은 재로딩 문제를 가진 기존 selection 테스트도 동일하게 격리하고 전체 agents 검사를 먼저 수행한다. 기존 검증 조건은 유지하며 수정 예외와 검증 시간이 하나 더 늘어난다.

13. 최종 검증은 변경 없는 worker·전체 agents·나머지 영역의 node 합집합으로 확정한다. hash·전체 목록·무작위 UUID 이름을 별도 확인하는 비용이 들며 단일 root 성공을 주장하지 않는다.

실제 모델 의미 품질·질문부터 생성까지의 통합·사용자별 소유/공개 게시·운영 복구/비용·개발 서버 반영은 이번 인수 범위가 아니다. 최종 PR/Sites·임시 자원 정리는 진행 기록을 따른다.

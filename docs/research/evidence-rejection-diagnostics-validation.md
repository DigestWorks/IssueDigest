2026-10-27. [계약](../changes/evidence-rejection-diagnostics.md). 제품의 결과 수용 조건을 바꾸지 않고 내부 오류/서버 로그에 고정 단계만 추가한다. 실제 모델 결과의 의미 품질 개선이나 과거 output 실패 원인 발견으로 표시하지 않는다.

## 구현·회귀

transport에서 입력·stream·JSON 파싱/값·DTO schema·출력 객체 무결성을 구분한다. source SDK는 native 영수증/usage/출력 타입·원문 무결성·근거 계약·생성 영수증 단계를 구분하고 하위 단계를 보존한다. 단계가 없던 호출은 None으로 호환하고 알 수 없는 입력은 None으로 정규화한다. worker는 변조된 값도 다시 allowlist로 검사해 unavailable로 대체한다.

worker의 고정 이벤트와 단계는 일반 콘솔 메시지와 구조화 extra에 함께 남는다. 본문·원 예외 message·ID·키·동적 field path·exc_info는 새 로그에 넣지 않는다. handler가 예외를 내도 원래 오류 인스턴스와 SQL 실패/usage 기록을 유지한다. 기존 앱의 모든 로그 시스템을 새로 설계하거나 원응답을 수집하는 기능은 아니다.

JSON/DTO 거부, source wrapper 하위 단계, 정상 완료 뒤 닫기 실패, 출력 거부와 닫기 실패의 동시 발생을 검사했다. 정상 완료 뒤 닫기 실패는 stream이며 기존 거부 단계가 있으면 보존한다. 주입한 비밀 모양 문자열·목록 값·없는 단계·고장난 로그 handler의 안전성을 확인했다. TDD red/green과 집중211개·보완 transport132개 검사를 비공개에 보존했다.

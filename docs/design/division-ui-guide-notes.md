# The Division UI 스타일 가이드 검토

- 작성일: 2026-10-11
- 자료: Ubisoft Massive 「Tom Clancy's The Division — User Interface Style Guide」 유출본 이미지. VGLeaks 게시물(2014-11-19, https://vgleaks.com/how-to-play-my-game-by-ubisoft-the-division-user-interface-style-guide/)과 연결된 imgur 이미지 27장을 열람했다.
- 이 문서는 내용을 요약해 IssueDigest 기준으로 다시 정리한 것이다. 원문 문장, 이미지, 아이콘, 글꼴은 가져오지 않는다.
- 적용 기준: IssueDigest 디자인 원칙(흰 배경, 색상은 데이터에만, 깊이는 명도·그림자로 표현)을 우선한다.

## 가이드 요약

| 장 | 내용 |
| --- | --- |
| 핵심 원칙 | 단순함(장식 제거, 단순한 기하 도형과 깨끗한 선, 글 대신 공간 배치로 정보 전달), 즉시 이해, 기능성(요소마다 분명한 목적), 일관성 |
| UI 구분 | 화면 평면에 붙는 Meta UI를 줄이고, 3D 공간에 놓이는 Spatial UI를 거쳐, 세계 안에 있는 것처럼 보이는 Diegetic UI를 목표로 한다 |
| 부피로 생각하기 | z-깊이는 이해와 초점을 돕는 목적으로만 쓴다. 너무 많은 요소를 깊이 방향으로 흩거나 반투명 요소를 겹치면 판독성이 떨어진다. 겹쳐 쌓기는 목록·누적을 나타낼 때만 쓴다 |
| 프로그램 생성 디자인 | 프로그램이 상황에 따라 그리는 그래픽이므로 수학적이고 단순한 도형·부피, 점과 선으로 영역과 방향을 만든다. 어떤 상황·조명에서도 작동하는 유연한 양식 |
| 행동 인포그래픽 | 형태를 채우는 대신 가벼운 선으로 동작·범위·관계를 보여 주는 공학 도면 양식. 선 굵기와 불투명도로 위계를 준다 |
| 불완전한 소프트웨어 | 정보는 한 번에 나타나지 않고 순서대로 불러오는 것처럼 나타난다. 가끔 깨짐(글리치)과 색수차를 쓴다. 홀로그램 빛이 아니므로 발광 효과는 쓰지 않는다 |
| 시각 재료 | 점: 위치·대상·시점을 나타내는 노드, 거리에 따라 크기가 달라진다. 선: 이동·공간·거리·연결. 지형에 가려진 선은 사라지지 않고 투명도를 낮춘다. 실선(지형을 따라가는 선)과 점선(가상의 선)을 구분한다 |
| 색 | 주색은 강조용 주황 하나와 기본 상태용 흰색. 주황은 초점을 만들 때만 아껴 쓴다. 보조색(적대·회복·아군)은 맥락을 줄 때만 쓴다. 그래프와 도식은 먼저 흰색과 불투명도만으로 설계하고 마지막에 강조색을 더하는 작업 순서를 권한다 |
| 글자 | 한 글꼴 가족의 굵기 네 단계. 가는 굵기는 크게 쓸 때만, 중간 굵기는 공간 속 글자에, 굵은 굵기는 숫자 강조에 쓴다. 굵기별 최소 크기가 있다. 카메라에 대해 35°보다 기운 글자는 읽을 수 없으므로 쓰지 않는다 |
| 글자 층 | 공간 속 글자는 본문 층(앞), 그림자 층(약간 뒤, 어두운 반투명), 잔상 층(멀리 뒤, 아주 옅게) 세 층으로 만든다. 복잡한 배경 위에서는 흐림 배경판이나 반투명 배경판을 깐다 |
| 셰이더 | 형상의 모서리를 따라 선을 그리는 방식(edge tracing)으로 강조하고, 같은 방식으로 맥박처럼 번지는 효과를 만든다 |
| 아이콘 | 단색, 단순화, 그라디언트 없음, 화면 5% 크기에서 읽힘. 가는 선을 피하고 하나의 덩어리로 보이게 한다 |
| 카메라 | 정보는 카메라에 보이되 주인공(캐릭터)을 기준으로 배치하고 기울인다. 화면 고정 UI는 카메라에 느슨하게, 공간 속 UI는 세계의 위치에 단단히 붙이고 카메라 쪽으로 돌려 읽히게 한다 |

## IssueDigest 적용 항목

현재 구현과 비교해 바꿀 항목이다. 위에서부터 영향이 큰 순서다.

### 1. 공간 속 글자의 35° 규칙

- 현재: 결과 패널과 지도 라벨이 카메라 각도에 따라 연속으로 기울어, 중간 각도(약 45°)에서 글자가 비스듬히 누워 읽히지 않는다. 지면에 눕힌 구 이름은 카메라가 낮으면 읽히지 않는다.
- 적용: 글자가 있는 면은 카메라 시선에 대해 35° 안쪽으로만 기울인다. 결과 패널은 눕힘·세움 두 상태 사이를 짧게 전환하고 중간 상태에 머무르지 않는다. 지면 라벨은 카메라가 낮아지면 세워진 라벨로 바뀐다.

### 2. 실선과 점선으로 근거 종류 구분

- 가이드의 실선(실제 지형을 따라가는 선)과 점선(가상의 선) 구분을 근거 종류 구분에 쓴다.
- 적용: 원천 데이터에 명시된 관계는 실선, 모델이 추론한 관계는 점선으로 그린다. 기획 문서의 「명시된 관계와 모델 추론 구분」 요구와 같은 내용이다.

### 3. 순서대로 나타나는 등장

- 현재: 노드가 크기 변화로 한 번에 나타난다.
- 적용: 점 → 선 → 글자 순서로 나타난다. 점이 먼저 찍히고, 선이 출발점에서 도착점으로 그려지고, 글자가 마지막에 나타난다. 지도는 외곽선이 그려진 뒤 면이 차오른다.

### 4. 모서리 선 강조

- 현재: 선택한 구와 노드를 고리로 표시한다.
- 적용: 선택한 형상의 모서리를 따라 선이 그려지는 방식으로 강조한다. 지도에서는 선택한 구의 외곽선과 압출 모서리가 검게 그려지고, 한 번 바깥으로 번지는 선이 나간다.

### 5. 불투명도 단계로 위계 설계

- 가이드의 작업 순서(먼저 흰색과 불투명도만으로 설계)를 흰 배경 기준으로 바꿔 적용한다. 먼저 검정과 불투명도만으로 위계를 만들고, 데이터 색은 마지막에 데이터 값에만 더한다.
- 적용: 불투명도 단계를 토큰으로 정한다. 예: 초점 100%, 관련 66%, 배경 정보 33%, 맥락 11%. 노드·선·라벨이 이 단계만 쓴다.

### 6. 가려진 선은 옅게

- 현재: 지도 블록이나 다른 형상 뒤로 지나가는 선은 그대로 가려진다.
- 적용: 가려진 구간은 사라지지 않고 불투명도를 낮춰 보인다. 탐색 경로를 끊기지 않게 읽을 수 있다.

### 7. 공간 속 글자의 층

- 적용: 지도 위 라벨처럼 색이 있는 면 위에 놓이는 글자에는 약간 뒤에 반투명 흰 층을 깔아 판독성을 확보한다(흰 배경 기준이므로 가이드의 어두운 그림자 층을 밝은 층으로 바꾼다). 복잡한 배경 위 수치에는 반투명 배경판을 쓴다.

### 8. 행동 인포그래픽 양식의 주석

- 적용: 지역·노드에 수치를 붙일 때 가는 지시선과 짧은 눈금, 작은 수치 글자로 주석을 단다. 형태를 채우지 않고 선으로 관계와 크기를 표시한다.

### 9. 글자 굵기 체계

- 적용: Pretendard 한 가족에서 굵기를 역할별로 고정한다. 가는 굵기는 큰 제목에만, 중간 굵기는 공간 속 라벨에, 굵은 굵기는 강조 숫자에 쓴다. 공간 속 글자의 최소 크기를 정한다.

## 제외 항목

- 주황 강조색: IssueDigest는 데이터가 아닌 요소에 색을 쓰지 않는다. 선택과 초점은 검정과 불투명도로 표시한다.
- 글리치와 색수차: 출처와 근거를 신뢰하게 하는 것이 제품의 목적이므로, 화면이 고장 난 것처럼 보이는 효과는 쓰지 않는다.
- 어두운 실사 배경: IssueDigest는 흰 배경을 쓴다.

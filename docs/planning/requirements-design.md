# IssueDigest 요구사항·설계 초안

상태: 검토안. 제품 구현이나 확정 API 스키마가 아니다. 상세 계약은 첫 구현 작업에서 같은 버전으로 고정한다.

## 기능 요구사항과 수용 시나리오

### R1 · 작업 공간과 저장

초대된 두 사용자가 같은 이슈·자료·질문·결과를 저장·열람할 수 있어야 한다. 로그인과 작업 공간 접근을 서버가 확인한다. 공개 Sites 접근은 앱의 자료 접근 권한을 부여하지 않는다.

- 같은 공간의 두 번째 사용자가 저장된 질문·화면·인용 자료 버전을 열면 같은 결과를 본다. 재열람은 모델을 다시 호출하지 않는다.
- 로그인하지 않았거나 해당 공간에 없는 사용자는 자료 URL·다운로드·실행 결과 API에서 거부된다.
- 두 사용자가 같은 이슈 설정을 수정할 때 오래된 버전의 쓰기를 덮어쓰지 않고 충돌을 알린다.

### R2 · 원문·버전·공급처 연결

법안·뉴스·청원·통계 등은 공급처 ID, 원문 URL, 게시/발생 시각, 수집 시각, 콘텐츠 해시와 버전을 구분한다. 원문 인용 위치를 보존한다. API/MCP와 정기 수집이 같은 공급처 연결 코드와 정규화 규칙을 사용한다.

- 같은 자료를 두 번 수집하면 같은 버전이 중복 적재되지 않는다. 수정 원문은 새 버전으로 남는다.
- PDF의 페이지·좌표, HTML/텍스트의 구간을 근거 카드에서 확인한다. 표는 단위·기간·문항/모집단 조건을 보존한다.
- 원문 삭제·정정·이용 범위 변경을 표시하고 검색·관계 투영에도 반영한다. 과거 결과는 당시 인용 버전을 기록한다.
- 호출 실패·페이지 누락·파싱 결측을 상태로 남기고 공급처별 재처리를 할 수 있다.

### R3 · 근거 검색과 관계

검색은 이름·번호·한국어 어휘·의미·기간·출처 조건을 결합한다. 관계는 근거 문서·위치·유효 시점·검토 상태를 가진다. Neo4j는 기준 저장소에서 생성하는 탐색 뷰다.

- 같은 질문·자료로 기본 검색, 벡터/하이브리드 검색, 관계 추가 탐색을 비교한다. 그래프가 필요 없는 질문은 불필요한 탐색을 하지 않는다.
- 관계 경로의 각 연결을 실제 원문에 대조할 수 있다. 단순 동시 등장이나 시간 선후를 인과관계로 표시하지 않는다.
- 검색·Neo4j 투영을 비운 뒤 같은 기준 데이터·버전으로 재구축하고 기대 결과를 회복한다.
- 여론조사의 다른 질문·표본·방법·기간을 숨긴 합산과 청원 동의 수의 전체 여론 해석을 막는다.

### R4 · 조율·도구·화면 명세

하나의 조율 에이전트가 질문·선택한 자료·기존 결과를 보고 제한된 도구를 사용한다. 이미지 생성·편집과 자료 수집은 필요할 때만 실행한다. Decisions는 정해진 선택지에 대한 판단을, Responses는 근거를 이용한 설명·UI 명세 생성을 맡는다. 확신 점수만으로 사실을 판정하지 않는다.

- 질문에 따라 비교표·타임라인·관계도·실제 수치 차트·근거 카드의 수·순서·내용이 달라진다. 생성 요청 전에는 가상 결과를 실제 결과처럼 채우지 않는다.
- 자료에 없는 질문은 필요한 자료·확인 질문을 반환하고 사실·수치를 만들어내지 않는다.
- 허용하지 않은 컴포넌트·액션·근거 ID, 틀린 차원/참조, 잘못된 날짜·단위를 포함한 명세는 표시 전 거부하거나 제한된 횟수로 수정한다.
- UI 명세는 실행 코드가 아니다. 구성·입력값은 서버가 검증하고 자료 접근·행동 권한을 다시 확인한다.
- 외부 원문에 들어 있는 지시가 도구 선택·키 사용·실행 규칙을 변경하지 않는다.

### R5 · 진행·취소·부분 갱신

요청 접수부터 작업 상태를 표시한다. 검증된 모듈부터 점진적으로 보여주며 후속 질문은 관련 부분을 갱신한다. 작업 이벤트는 순번으로 저장하고 재접속 시 이어받는다.

- 모델 응답 전 접수·근거 검색·도구 실행·검증·화면 구성 상태를 본다. 내부 비공개 추론문을 진행 안내로 노출하지 않는다.
- 실패·취소 때 질문과 마지막 정상 결과를 유지하고 이전 결과임을 알린다.
- 새로고침·네트워크 재접속은 같은 실행 ID에 다시 연결한다. 같은 제출 키의 재전송이 새 유료 실행을 만들지 않는다.
- 정렬·필터·기존 노드 선택은 모델 호출 없이 처리한다. 새로운 자료·해석을 요청하면 새 실행과 비용을 기록한다.
- 취소 후 다음 유료 단계를 시작하지 않는다. 이미 공급처에 전송한 호출의 중단·비용 반환은 보장하지 않으며 사용량을 정산한다.

### R6 · 복구·변경·사용량

실행 단계와 도구 결과를 저장해 중단한 작업을 재개한다. 모델·프롬프트·온톨로지·UI 계약·실행기 버전을 기록한다. 유료 외부 호출은 재시도 정책과 중복 위험을 별도로 관리한다.

- 워커 재시작 뒤 저장된 단계는 재사용한다. 완료 여부를 확인할 수 없는 유료 외부 호출은 무조건 재시도하지 않고 보류·재조회·명시적 재실행으로 처리한다.
- 배포 버전이 바뀌어도 실행 중인 작업의 계약·도구 이름을 깨뜨리지 않는다. 기존 작업을 마치거나 버전별 워커로 처리한다.
- 월 비용·실행 횟수·동시 작업·최대 출력과 도구 호출 한도를 서버에서 확인한다. 동시 요청의 예산 예약이 같은 남은 금액을 중복 사용하지 않는다.
- 한도 초과 시 원문·기존 결과 열람을 유지하고 새 유료 실행을 거부한다.
- 원문·기준 DB·작업 이력을 백업하고 별도 환경에 복원한다. 검색·그래프는 복원 기준 데이터로 재구축한다.

### R7 · 이미지 도구

도구는 기존 이미지 검색·선택, 설명 이미지 생성, 크롭·리사이즈를 지원한다. 수치 차트와 사실 다이어그램은 검증된 데이터를 코드로 렌더링한다.

- 생성·외부 이미지의 출처, 이용 조건, 공급자, 생성/편집 요청·버전·크롭 위치를 저장한다.
- 원문 이미지 크롭은 원문·페이지·좌표 참조로 돌아갈 수 있다. 생성 이미지는 설명용 표지를 가진다.
- 이미지가 필요 없는 과제에서는 이미지 생성 호출·과금을 하지 않는다. 이미지 비용도 같은 예산에 포함한다.

## 데이터 계약 초안

| 객체 | 필수 의미 |
| --- | --- |
| Workspace / Membership | 소유·참여 사용자, 역할, 서버 접근 범위 |
| Issue | 주제·범위·선택 기간·연결 문서·설정 버전 |
| SourceDocument / DocumentVersion | 공급처·원천 ID·URL·시각·해시·원문 객체 참조·이용 범위 |
| Chunk / Citation | 문서 버전·페이지/구간·인용문·표 단위/조건 |
| Entity / Claim / Relation | 주체·주장·관계 종류·양 끝 ID·근거·유효 시점·검토 상태 |
| Run / Step / Event | 사용자·제출 키·작업 상태·순번·취소·단계 결과·추적 ID·실행 버전 |
| CanvasRevision | 모듈 명세·원문 버전·질문 맥락·이전 결과 참조·검증 상태 |
| Asset | 원본·파생 이미지 참조·출처·이용 조건·생성/편집 이력 |
| UsageReservation / UsageLedger | 최대 비용 예약·실제 토큰/도구 사용량·환율 기준·실패/재시도 비용 |

파일 원문은 객체 저장소에 두고 실행 이력에는 작은 참조를 남긴다. 사실·주장·추론을 구분한다. 문서 콘텐츠에서 만든 관계는 인용 근거를 보존한다.

## 쓰기·조회 흐름

수집/등록 → 원문·해시 저장 → 파싱·구조화·검증 → 기준 DB 저장 + outbox → 검색·Neo4j 투영.

질문 → 세션·권한·비용 예약 → 범위 판단 → 검색·필요 관계·외부 도구 → 근거 검증 → 설명·UI 명세 → 명세 검증 → 이벤트·화면 저장 → 스트리밍·공유 열람.

투영은 사건 ID·문서 버전으로 멱등 처리한다. 검색·그래프를 각각의 기준 저장소로 직접 수정하지 않는다. 원문 버전과 색인 버전의 차이를 추적하며 갱신 실패를 복구한다.

## 실행기·검색 결정 실험

1. DBOS/PostgreSQL과 Temporal은 같은 수집·모델·도구 흐름으로 중단 후 재개, 도구 중복, 버전 변경, 스트리밍/재접속, 메모리·운영비를 비교한다. 후보 실행기를 두 개 동시에 생산 운영하지 않는다.
2. PostgreSQL/pgvector의 한국어 어휘·정확 ID 결합과 OpenSearch/Nori를 같은 실제 질문·기대 근거로 비교한다. 특정 법안명·동명이인·문항 조건·날짜 필터를 포함한다.
3. 검색·작업 실행은 이 실험으로 생산 목표 엔진을 확정한 뒤 첫 제품에서도 같은 엔진을 쓴다. 임시 엔진으로 제품 기능을 만든 뒤 갈아엎는 계획이 아니다.
4. PydanticAI의 DBOS 통합은 workflow 안에서 실행해야 내구성이 생긴다. 도구·이벤트·모델 호출의 저장 경계를 확인하고 현재 문서에 맞는 통합을 버전 고정한다. deprecated wrapper를 새 코드의 기본으로 쓰지 않는다.

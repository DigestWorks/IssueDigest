# IssueDigest 요구사항·설계

2026-10-19 KST 기준. 질문 중심 B2C 브리핑을 위한 현재 요구와 다음 계약이다. 제품 방향은 [D016·D017·D019·D020·D021](decisions.md)·[사용자 인터뷰](../research/product-experience-interview.md), 현재 화면의 검증 범위는 [브리핑 경험](../changes/briefing-experience.md)·[B2C 정리·장기 세션](../changes/b2c-cleanup-persistent-login.md)을 따른다. R1~R7 식별자는 기존 계약·변경 문서 참조를 위해 유지한다. 목표 요구와 현재 구현 완료를 구분한다.

## 기능 요구사항과 수용 시나리오

### R1 · 접근과 브리핑 기록

비회원은 명시 검토된 공개 복사본을 읽고 질문을 일반 홈 초안으로 이어간다(D020). 공개 읽기는 세션 조회 완료에 종속하지 않으며 모델·DBOS·예산을 만들지 않는다. 기존 초기 검증 자료·질문·저장 실행은 서버 세션과 현재 멤버십으로 보호한다. 브리핑 기록은 같은 자료 범위의 공유 검증 이력이며 개인 소유나 공개 게시를 뜻하지 않는다.

- 공개 목록은 실제 게시된 최신 버전20개 이하만 질문 아래에 표시한다. 빈 목록은 생략하고 요청 실패는 재시도와 구분한다. 공개 고정 버전은 덮어쓰지 않으며 최신 철회 뒤 구판을 자동 최신으로 되살리지 않는다. 인용/재진입/focus/visible 복귀는 같은 버전의 현재 공개 상태와 불변 hash를 확인한다.404는 브리핑과 열린 원문을 정리하고 일시 오류는 복구 가능하게 알린다. 이미 받은 자료의 원격 삭제를 보장하지 않는다.
- 비회원 질문은 이 탭에 제한적으로 임시 보관하고 로그인 후 편집 상태로 한 번 복원한다. 명시 제출 전 모델을 호출하지 않는다. 기존 실행·기록·자료 진입에 질문을 섞지 않는다.
- 기본 화면은 질문·브리핑과 브리핑 기록이다. 단일 자료 범위의 내부 ID·역할 배지를 노출하지 않는다. 서버가 검증한 첫 승인 맥락을 내부에서 사용하고 자료 범위 선택기는 제공하지 않는다. 계정/권한·실행 변경 시 이전 요청·자료·질문 맥락을 섞지 않는다.
- 현재 권한이 없는 사용자는 원문·검색·인용·실행 API에서 거부된다. viewer는 열람만 가능하다. 현재 요청의401/403/404로 접근 상실을 확인하면 기표시 Canvas·제목·원문 창·질문 초안을 함께 지운다. 이전 맥락의 늦은 오류는 새 브리핑을 지우지 않으며 네트워크/503 실패로 권한 상실을 단정하지 않는다.
- 같은 자료 범위의 저장 결과는 모델 호출 없이 질문·화면·당시 인용 버전으로 재열람한다. 개인 관심 이슈/비공개 질문 이력·불변 외부 공유본은 별도 소유·게시·철회 계약을 구현한 뒤 제공한다.
- 세션 최대 수명은14일, 미사용7일이다. 활동으로 절대 만료를 늘리지 않으며 로그인 교체·로그아웃 폐기·현재 권한 검사와 안전한 쿠키를 유지한다. 기존8시간 세션의 만료일은 자동 연장하지 않는다.

### R2 · 원문·버전·공급처 연결

공식 발표·법령/법안·뉴스·여론조사·통계·청원은 공급처 ID·원문 URL·게시/발생 시각·수집 시각·해시·버전·이용 범위를 구분한다. 질문 전에 자료를 등록하는 관리 절차를 기본 사용자 여정으로 요구하지 않는다.

- 공개 첫 지원 출처는 `https://www.korea.kr/news/policyNewsView.do?newsId=<ASCII numeric>`만 허용한다. 문서별 정확 텍스트 SHA·공식 URL·발행일·출처/저작자·공공누리 제1유형 확인 시각/검토자와 사진/외부 저작물 제외를 검토한다. 같은 정부 사이트 전체에 재게시 권리를 추정하지 않는다. 전체 계획 hash를 별도로 확인한 신뢰 게시만 허용하며 내부 검토자/원래 ID/질문은 공개 응답에 싣지 않는다.
- 원문 식별/버전과 파싱 표현을 분리하고 정확한 quote·앞뒤 문맥·PDF 페이지·본문 구간·표 셀/단위/기간/문항 조건을 보존한다. 현재 제한된 HTML/PDF/HWPX 파서의 범위와 원문 이용권·의미 판정을 구분한다.
- 기존 연결기·등록·중복 방지·정확 인용 계약을 재사용한다. 자료 변경·정정·삭제·이용 범위 변경은 과거 인용 버전을 덮어쓰지 않고 검색·향후 게시에도 반영해야 한다.
- 고정 정책뉴스 목록 발견·정확 기사 확보·private capture와 등록 준비 SDK를 구현했다(D021). 운영자가 기사별 공공누리1 텍스트·발행일·출처·본문 SHA·인용·ID를 확인하고 기존 등록/색인 경로로 명시 추가한다. SDK/import/공개 GET/로그인 복원에서 수집·DB 쓰기·모델을 실행하지 않으며 과거 자료를 덮지 않는다. 수집은 공개 게시를 뜻하지 않는다.
- M2의 [반복 확보 이력](../changes/policy-collection-journal.md)을 개인 개발에 적용했다. 명시한 고정 기사1~2개만 bounded poll로 확보하고 PostgreSQL의 별도 내부 이력에 running/성공/실패·정확 capture/비교를 보존한다. 기존 SDK/import와 공개 읽기는 이 작업을 실행하지 않는다. 수집 journal을 EvidenceBundle·검색 자료·공개 게시로 자동 편입하지 않는다. 실제 scheduler 적용은 진행 기록의 검증 증거로 구분한다.
- [수집본 편입](../changes/policy-collection-intake.md)을 개인 개발에 적용했다. 특정 성공 원본의 명시 검토와 기존 parser/정확 인용으로 canonical 자료·표시·검색·receipt를 한 transaction에 저장한다. 같은 의미/승인 인용은 재사용하고 변경·되돌림은 새 버전으로 보존한다. 새 질문은 최신 승인본만 검색하고 구판으로 fallback하지 않으며 과거 고정 근거·원문은 유지한다. 최초 추적은 기준 버전이며 실제 기사 내용 변경으로 부르지 않는다. 공개 게시와 다매체 출처 확대는 별도 단계다.
- [공식 목록 후보 선별](../changes/policy-source-candidates.md)은 기존 discovery 원본을 바꾸지 않고 정확 날짜/발행처 SDK와 오프라인 기간·이전 관측 비교를 추가한다. new는 이전 목록에 없는 ID이며 not_observed는 현재 전체 목록의 미관측이다. 삭제/철회·본문 변경·권리 승인·주목도/순위로 해석하지 않는다. private 보고서의 전체 상세와 집계 stdout을 분리하고 HTTP/DB/모델을 실행하지 않는다.
- 관측된 정확 두 span/부처 링크 metadata만 HTML parser_version3으로 지원하며 숨김/모호한 구조는 거부한다. 기존1/2·본문/권리/인용/hash는 보존하며 AI workflow v3와 별개다. 개별 원문·발행일·공공누리1 텍스트/사진·외부 저작물 제외·8개 정확 인용을 검토한 새 자료1건만 기존 명시 등록/검색으로 개발 추가했다. 자동 수집 확대/승인/공개 게시는 하지 않는다.
- 그 밖의 최신 뉴스·공식 발표·발언·여론조사 확보와 최근 수집 성공/누락·재처리는 후속이다. legacy 법안 건수·파일 시각·연결기 존재를 최신 이슈 관측이나 전면 수집 완료로 표시하지 않는다.

### R3 · 근거 검색과 관계

질문만 제출하면 서버가 현재 권한의 실제 저장 색인에서 관련 근거를 찾는다. 자료 선택·카탈로그·클라이언트 추천·출처 ID 입력은 사용자 여정에 포함하지 않는다. 현재는 제한된 보호 문자 검색이며 웹 전체 탐색·의미·관계 검색은 후속이다.

- 서버가 질문에서 최대8개 검색어를 추출해 기존 보호 문자 검색을 재사용하고 일치도·결정적 동률 순서로 최대5개 근거를 고정한다. 무관한 최신 자료/전체 목록으로 대체하지 않는다. 미색인·검색 후보/결과 한도 때문에 찾지 못한 것을 전체 자료의 부재로 단정하지 않는다. 결과의 정확 인용으로 원문을 열며 일치 위치·저장 인용·주장 지지를 구분한다.
- 새 private v5는 각 inference claim에 실제 같은 인용 배열을 대상으로 자동 SupportReview1개를 둔다. 자료에 기록됨(content/supported)·출처의 주장(attribution/supported)·확인하기 어려움(content/insufficient)만 허용하고 근거 설명은300자 이하로 제한한다. 현재 선택 인용의 AI 평가이며 원문 일치·주장 지지·독립 진실 판정을 구분한다. legacy/v3/v4/v5 혼합·누락·중복·알 수 없는 참조·다른 인용 순서/UTC 마이크로초 시각을 거부한다.
- 새 v5 provider 출력은 answer/insufficient_evidence/clarification_needed의 세 strict tool이며 실제 prompt에 선택된 정확 UUID 인용만 enum으로 허용한다. canonical/API 구조·기존 원문/인용 검증과 v2/v3/v4 재생은 보존한다. v5 독립 지침·사전 예산·실제 부분 충족은 [답변 품질 명세](../changes/briefing-answer-quality.md)를 따른다. 구조 제한으로 의미 품질을 인증하지 않는다.
- 후속 한국어 어휘·이름/번호·벡터·기간/출처 필터는 실제 평가 질문·기대 근거로 비교한다. 질문과 무관한 임의 자료를 기본 선택하지 않는다.
- 관계는 근거 문서·위치·유효 시점·검토 상태를 가진다. 동시 등장·시간 선후를 인과로 바꾸지 않는다. Neo4j는 기준 DB의 투영이며 정정/삭제·재구축·실패 복구를 검증한다.
- 여론조사의 질문·대상·방법·조사일·표본/오차·출처를 함께 확인한다. 언론 보도량·온라인 반응·청원 동의 수를 국민 전체 여론으로 합산하지 않는다.

### R4 · 질문·브리핑·생성 화면

질문부터 입력하고 30초 브리핑을 읽은 뒤 필요한 비교·변화·반응·근거를 연다. AI가 승인된 자료 탐색→비교·시각화에 필요한 도구와 모듈을 선택하는 것이 목표이며 현재 실행은 서버가 찾은 저장 근거와 구조화된 완료 결과다.

- 공개 읽기는 표제·설명·실제 기준 UTC 시각·게시일/버전·출처와 이용 조건, 기존30초 요약/접기·정확 인용 원문 창을 제공한다. 오래된 기준일을 인기/최신 이슈로 포장하지 않는다. 더 새 버전이 확인될 때만 새 버전 링크를 표시한다. 공개 질문은 표제/사용자 입력만 홈에 전달하고 기존 public/private run을 parent로 전송하지 않는다. 로그인 후 편집하고 명시 제출해야 생성한다.
- 새 private v4는 AI 해석 label을 유지하면서 자료에 기록됨·출처의 주장·확인하기 어려움을 작은 펼침 문구/도움말로 구분한다. 설명은 필요할 때 읽으며 독립 사실 검증으로 표시하지 않는다. 과거v1/v2·공개 결과에 새 분류를 추정하지 않고 공개 D020의v1/v2·빈 support_reviews 경계를 유지한다. 자료 부족을 솔직히 표시하고 없는 사실·상충/양측·수치·여론을 만들지 않는다.
- 서버가 허용 모듈·액션·ID·참조·날짜/단위·수치를 검증한다. 모델 HTML/코드는 실행하지 않는다. 표·차트·관계·이미지는 실제 근거가 있을 때 사용한다.
- 근거 창은 본문 위치·선택을 유지하고 닫을 때 실행 버튼으로 초점을 복원한다. 모바일 비교는 읽기 단위로 구성한다. 원문 창을 닫고 후속 질문을 작성해도 같은 완료 브리핑 맥락을 유지한다.
- 테마·계정은 테두리 없는 아이콘으로 표현하되 접근성 이름·툴팁·키보드·44px 영역·초점 표시를 갖춘다. 정상 비회원 홈은 반복 로그인 경고를 두지 않는다.
- 외부 원문의 지시가 도구·키·실행 규칙을 바꾸지 못하게 한다. 자율 외부 탐색 범위는 승인 출처·권한·비용·저장/복구 계약으로 확정한 뒤 연결한다.

### R5 · 진행·취소·부분 갱신

근거를 확인한 부분부터 읽고 나머지는 조사 중으로 표시하는 것이 사용자 선택이다. 현재는 실제 단계 상태와 검증된 완료 결과를 표시하고 결과의 정확 인용에서 원문을 연다. 자동 중복 원문 블록은 제공하지 않는다. 검증된 AI 모듈의 점진 전달은 후속이다.

- 접수·자료 찾기·분석·인용 검증·완료·실패·자료 부족·취소 상태를 구별한다. 비공개 추론문은 노출하지 않는다.
- 새로고침/재접속은 같은 실행 ID에 연결한다. 같은 제출 키의 재전송이 새 유료 실행을 만들지 않는다. 후속 질문은 완료된 부모 실행을 맥락으로 전달하고 근거는 서버가 다시 찾는다. 유효 검색어가 없는 일반 후속 질문만 부모의 검증된 실제 근거를 재사용한다. 새 주제에서 근거를 못 찾으면 모델 호출 없이 insufficient_evidence로 종료한다.
- 권한이 유지되는 실패/취소 뒤 질문과 읽던 원문을 유지하고 새 질문을 명시 제출할 수 있다. 늦은 응답이 더 최근의 실행·선택·닫힌 원문을 되돌리지 않는다.
- 검증된 부분 결과 전달에서는 읽던 위치·이전 결과·변경 표시·부분 실패를 보존해야 한다. 정렬·필터·재열람은 모델 호출 없이 처리한다.
- 취소 후 다음 유료 단계를 시작하지 않는다. 이미 전송한 외부 호출의 중단·비용 반환은 보장하지 않고 실제 사용량을 정산한다.

### R6 · 복구·변경·사용량

D011의 PydanticAI/DBOS와 PostgreSQL 실행·이벤트·단계 결과·사용량 계약을 재사용한다. 월10만 원은 개발·초기 검증 예산이며 B2C 무제한 사용 약속이 아니다.

- 새 요청만v4로 실행하며 기존v2/v3/v4 workflow ID는 원래 등록 이름·application_version의 worker cohort에서 회복한다. worker 중복 기동은 session advisory lock으로 거부한다. 완료된 원래 모델 checkpoint만 재생하고 generating/validating의 완료 불명확 요청은 실패·예약 유지로 끝내며 재호출하지 않는다. 최초v2 업그레이드는 기존 worker가 중지된 상태에서 한다.
- 반복 확보는 연구 worker와 다른 단일 session 잠금으로 중복 실행을 막고 최소 간격/횟수 한도를 적용한다. 마지막 실행의 실패/미완료와 마지막 성공을 구분하고, 다음 명시 poll에서 중단 실행을 마감한다. 상태 조회는 read-only이며 성공 확보의 경과 시각(stale)을 발행일·전체 범위 최신성으로 해석하지 않는다. 유료 모델 작업의 재시도/복구 정책은 바꾸지 않는다.
- 중단 뒤 저장 단계는 재사용한다. 완료 불명확한 유료 호출은 무조건 재실행하지 않는다. 모델·프롬프트·계약·도구·실행기 버전과 요청 ID로 재현한다.
- 계약 변경 때 진행 작업을 마치거나 호환 워커로 처리한다. 서버가 현재 권한·동시 실행·최대 출력·도구 호출·비용 예약/정산을 검사한다. 한도 초과 시 기존 결과·원문 읽기는 유지한다.
- 공개 출시 전 실제 질문 품질·불확실성·지연·동시 예산·운영비와 원문/기준 DB/이력의 외부 백업·별도 복원·검색 재구축을 검증한다. 구현된 부분과 전체 운영 품질을 구분한다.
- 관심 이슈의 중요한 새 사실·공식 결정·정정과 고정 공유본/최신판, 최근 주목도·개인화는 새 데이터·게시/사용자별 저장/동의 계약이 필요하다. 동작 없는 메뉴나 가상 데이터로 완료를 표시하지 않는다.

### R7 · 이미지 도구

이미지 검색·생성·크롭/리사이즈는 근거 탐색 경험에 필요할 때 검토할 후속 도구다. 현재 활성 구현 과제나 첫 브리핑의 필수 조건으로 두지 않는다.

- 도입할 때 출처·이용 조건·공급자·생성/편집 요청·버전·원문 페이지/좌표·비용을 같은 실행 계약으로 기록한다. 생성 이미지는 설명용임을 표시한다.
- 수치 차트·사실 다이어그램은 검증된 데이터로 렌더링한다. 이미지가 필요 없는 질문에서 이미지 호출·과금을 하지 않는다.

## 쓰기·조회 흐름과 검증

현재: 승인 자료 연결/등록 → 불변 원문·정확 인용·기준 DB/outbox → 보호 문자 검색/원문. 질문 → 세션·현재 권한·한도 → 빈 근거의queued 저장 → 현재 권한/잠금 아래 서버 검색·최대5개 근거 고정 → PydanticAI/DBOS v4(기존v2/v3 복구 호환) → 근거/화면 검증 → 저장 완료 결과·브리핑 기록 재열람.

ResearchRequest는 request_id·question·선택적 parent_run_id만 허용하고 snapshot_ids/임의 필드는 거부한다. ResearchRun.snapshot_ids는 서버가 찾은0~5개 근거의 기록이며 완료 결과는1개 이상의 유효 근거를 포함한다. 근거를 고정한 재시도·복구에서 다시 검색하지 않고 과거v1 저장 결과는 그대로 읽는다.

공개 경로: 전체 계획 hash 검토→신뢰 CLI/독립 저장소 명시 게시→익명 목록/고정 버전→같은 버전 재확인/정확 인용→표제/직접 질문만 홈 초안으로 전달한다. 독립 검증·개별 내용/이용 조건 검토 후1건을 명시 게시해 개인 개발 HTTPS에 반영하고 사후 백업 복원을 확인했다.

다음: 질문 시 승인 외부 탐색·근거 평가 품질 확대·검증된 모듈의 점진 전달, 개인 관심/변화·공유·추천 계약을 순서대로 연결한다. 각각 서버 접근·복구·예산·실제 근거로 검증하며 기존 수집/인용/읽기 경계를 지우지 않는다.

미완료 작업은 [작업 목록](tasks.md), 코드/브라우저/운영 증거는 [진행 기록](progress.md)에 둔다. 이전 설계 전개는 Git 이력(재편 전 `d6d05f3`)과 `docs/changes/`에 보존한다.

현재 지침/검색의 추가 경계는 [D022](decisions.md)와 [한국어 근거 품질 명세](../changes/korean-evidence-quality.md)를 따른다. v4는 기관의 발표 수치·주장을 귀속하고 목표·실적·전망을 구분한다. 같은 대상·기간·단위의 검증 가능한 단순 대소 관계만 설명하며 강제 계산·인과·양측을 만들지 않는다. v3/v4 review는 각 실행의 고정 식별자·method_version과 정확히 일치해야 한다. 과거 지침·schema·유료 checkpoint 순서는 보존한다. 실제 모델 의미 품질과 원래20문항은 별도 평가다.

2026-10-20 KST 기준. IssueDigest는 질문에서 시작해 이슈의 맥락·쟁점·변화를 이해하는 B2C 브리핑 서비스다. [D016·D017·D019·D020·D021·D022](decisions.md)과 [제품 경험 인터뷰](../research/product-experience-interview.md)가 제품 방향의 원본이다. 이 문서는 현재 구현과 다음 구현을 구분한다. 두 사람의 공동 자료 검증을 최종 제품 구조로 확대하지 않는다.

## 제품 여정

1. 궁금한 질문을 입력하거나 실제 게시된 공개 브리핑을 읽는다. AI 질문은 홈 초안으로 이어가 로그인 후 편집·명시 제출한다. 최근 주목 이슈는 별도 관측 데이터가 필요한 후속이다.
2. 30초 요약으로 시작해 자료로 확인한 내용·엇갈리는 주장·미확인을 구분한다. 근거를 확인한 부분부터 보여 주고 나머지는 조사 중으로 표시한다.
3. 질문에 필요한 비교·시간 변화·반응·원문을 같은 맥락에서 열고 읽던 위치로 돌아온다. AI는 승인된 자료 탐색과 도구를 통해 필요한 표현을 선택한다.
4. 관심 이슈를 저장하고 중요한 새 사실·공식 결정·정정을 서비스 안 알림함에서 확인한다. 재방문 시 최신 전체 브리핑의 변경 부분을 본다.
5. 공유 당시 브리핑과 근거를 보존한 링크를 제공하고 최신판도 안내한다. 개인 질문·이력의 공개 범위는 별도 계약으로 다룬다.

이 여정 전체가 구현된 것은 아니다. 최근 이슈·개인화는 실제 관측 데이터와 이용 이력 정책이 필요하다. 공개 댓글은 제공하지 않는다. 질문·열람을 정치 성향이나 특정 주장 지지로 해석하지 않는다.

## 현재 구현과 경계

질문 우선 홈, 비회원 질문→로그인→편집 상태 복원, 명시 생성, 현재 권한의 저장 색인에서 서버가 질문에 맞는 최대5개 근거 검색/고정, 검증된 완료 브리핑과 정확 인용의 원문 열기, 후속 질문·취소·재접속·자동 저장/재열람을 연결했다. 헤더는 테두리 없는 테마·계정 아이콘이고 기본 메뉴는 브리핑·브리핑 기록이다. 질문만 제출하며 자료 선택·카탈로그·클라이언트 추천·자료 범위 선택기는 제공하지 않는다. 결과의 정확 인용에서 원문을 연다. 새v9은 검색/관련성 선택 뒤에도 근거가 없으면 최종 생성 없이 자료 부족으로 끝낸다. 법안 기본 정보는 출처 한 종류이며 법안 전용 시작 행동은 제공하지 않는다.

과거 v1 완료 브리핑에서 seed 뒤에 추가된 근거도 현재 권한과 정확한 원문 연결·본문 동일성을 재검증해 기존 응답의 근거 ID로 열 수 있다. 이 호환 해석은 읽기 응답에만 적용하며 저장 결과·원문·이벤트를 변경하지 않는다. 일반 후속 질문은 부모의 실제 근거 전체를 고정하고, 새 v2/v3/v4/v5 근거 불일치는 안전하게 거부한다.

현재 자료와 브리핑 기록은 초대된 초기 검증 참여자의 공유 자료 범위에 속한다. 개인 보관함이나 공개 피드가 아니다. 공개 브리핑은 독립 게시 저장소와 명시 권리/전체 내용 검토한 불변 복사본으로 분리했다(D020). 실제 목록·고정 버전/최신판 안내·정확 인용 재확인·일반 질문 초안을 연결했다. 첫 지원은 개별 확인된 한국정책브리핑 공공누리1유형 텍스트이며 사진/외부 저작물과 기존 private 실행은 공개하지 않는다. 독립 인수·개별 내용/이용 조건 검토 후1건 명시 게시와 개인 개발 HTTPS 반영·사후 백업 복원을 확인했다. 추천·개인 저장·변경 알림·사용자 고정 공유본은 후속이다. 생성 중에는 실제 단계 상태를 표시하며 검증된 AI 부분 결과 전달은 후속이다. 현재 AI의 해석을 UI가 확인된 사실로 승격하지 않는다.

v10 수치 설명·호환 실행은 구현했으나 실제 의미 인수에서 부분2·미충족1·적절한 자료 부족1을 기록해 개발 반영을 보류했다. 개발 앱은 `ab6654e`/v9, main/운영 유예(D013)다. 기존3문항과 신규 다중주제1은 각각 한 번씩 실제4앱/12요청으로 평가했고 성공까지 재호출하지 않았다.

[현재 명세](../changes/briefing-numeric-clarity.md)와 [진행 기록](progress.md)에서 구현/합성 검사·실제 의미 인수·개발 적용을 구분한다. 이전 v9/v8의 실패·부분 판정·전후 백업/복원·복구 판단은 진행 기록에 남겼다. 이번 수치 문장 개선을 완료 마일스톤으로 표시하지 않는다.

## 내부 검색 평가 · 완료 기반

내부 계획 검색 비교 SDK와 `issuedigest-evaluate-planned-retrieval` CLI를 추가했다. 원래 검색과 실제 original-first round-robin 계획 검색을 같은 strict job/corpus·읽기 전용 REPEATABLE READ transaction에서 비교한다. 필수 family·사람이 명시한 무관 자료·미판정을 구분하며 `judged_precision`은 판정된 relevant/(relevant+irrelevant)만 사용한다. 미판정은 분모에서 빠지므로 전체 precision이 아니다. 기록된 계획/운영자 작성 계획의 출처를 따로 보존하며 provenance 자체를 자동 인증하지 않는다.

기검토 공개 텍스트3건·이전v8 고정 질문3개와 실제 기록된 planner7 검색어를 그대로 재현했다. 원래 후보0/2/3→계획후1/3/3이며 이전 선택 순서까지 정확히 일치했다. 첫 질문은 필요한 자료0→1·명시무관0, 둘째는 필요한 자료1 유지·명시무관1→2, 셋째는3건 모두 관련성 미판정으로 보존했다. 셋째의 전국 여론 직접 근거 부재를 모든 반환 자료의 무관함이나 세상에 조사 자체가 없다는 뜻으로 확대하지 않았다. 필요한 자료를 지정한 positive2문항의 family recall은0.5→1.0이고, 전체 반환5→7 중 판정 relevant1→2/irrelevant1→2/unjudged3→3·판정분모의 micro precision0.5→0.5다. 작은 고정 corpus의 비교이며 전체 검색 품질/중립성·답변 의미 품질 통과가 아니다.

## 질문·근거 후보 관련성 선택 · 완료 SDK 기반

질문·제공 인용을 함께 읽는 재사용 선택기 `evidence-relevance-v1`을 agents SDK로 구현했다. 정확한 모든 후보에 retain/exclude/uncertain을1회씩 받고, retain+uncertain은 원래 순서로 보존하며 exclude만 제외한다. 실제 후보 UUID enum/전체 coverage·원문 전체 인용·question/prompt UTF-8 hash·불변 결정/사용량과 raw/합산 검증을 적용한다. strict preflight 전에는 기본 key/model/Agent를 초기화하지 않는 lazy handle이다. 제목/metadata만으로 관련성을 증명하거나 관련성을 진실·독립 사실 검증·정치적 동의로 대신하지 않는다.

실제 요청의 source는 `384608d`이며 캡처용 주입 모델과 호출자 소유 클라이언트를 사용했다. 이후 `50f0552`는 기본 생성 클라이언트의 수명 관리만 수정했고 지침·모든 후보 수의 raw/normalized schema·prompt·예산과 합성 결정 결과의 동일성을 확인했다. 기본 경로의 성공·실패·생성 오류 정리와 주입 클라이언트 소유권은 합성 회귀로 검증했으며 실제3요청을 새 source로 재표기하거나 유료 재실행하지 않았다.

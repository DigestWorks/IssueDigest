# 최종 생성 입력 v2: 근거를 유지하고 중복 제거

2026-10-28 KST. 스토킹 자료3건의 실제 Astra 분석은 모두 완료됐다. 최종 v1 프롬프트23,380바이트·전체 요청 예산32,264가 기존20,000 한도를 넘어 마지막 호출 전에 중단됐다. 분석 명제17개와 정확 참조·전체 인용의 반복이 원인이다. 분석3회를 재호출하거나 한도를 올리지 않는다.

## 계약

- 새 model-facing `question-briefing-source-v2` 입력만 추가한다. 최종 출력은 기존 QuestionBriefingProposal/QuestionBriefing와 generation-v1 결과 계약을 유지한다. DB 컬럼/제약 변경은 없다.
- 모든 원문 인용·명제·조건·시점·부정·의존성·불확실성을 보존한다. 동일 참조는 자료별 catalog로 묶고, 원문은 참조 경계의 텍스트 조각으로 한 번만 전달한다. 모델이 Unicode 문자 수를 세지 않아도 조각 범위로 정확한 문구를 읽게 한다. 명제의 반복 필드명은 열 이름과 행으로 정리한다.
- 역변환은 canonical v1 입력 전체와 정확히 일치해야 한다. 사실/조건 삭제·텍스트 잘라내기·숫자 변환·인용 약화는 허용하지 않는다. 입력/출력 예산과 공급자 재시도0을 유지한다.
- v1 프롬프트·지시·네이티브 출력 도구 JSON bytes는 그대로다. v2 지시는 별도 해시로 고정한다. 신규 접수는 입력 형식을 명시하고, pending 실행은 저장된 알려진 지시 해시로 버전을 선택한다.
- 완료 재열람은 결과 input_format과 저장 지시/프롬프트 해시의 정확한 조합을 검증한다. 미지 해시·형식 혼합·같은 요청 ID의 버전 교체를 거부한다.
- 저장소/서비스 기본은 v1이며 개발 환경만 검증 후 v2를 명시 선택한다. 새 프로그램은 v1/v2를 읽지만 이전 strict v1 프로그램은 v2 결과를 읽지 못한다. v2 저장 후 복귀는 v2 읽기를 지원하는 새 프로그램의 v1 쓰기 설정을 사용한다.

## 검증

- 합성 round-trip: 반복/중첩/겹침·Unicode·비어 있는 값·명제와 인용 전체 보존, 잘못된 참조/범위/내용 거부.
- 기존 v1 요청 bytes·pending/완료 재열람 보존. v2 접수·실행·완료 해시·형식 결합과 잘못된 조합/중복 요청 거부.
- 기존 실제 분석3건을 읽기 전용으로 재사용해 v2 역변환/전체20k 예산을 확인한다. 전체 회귀·독립 검토 후에만 최종 생성1회를 새 승인에서 실행한다.
- 해당 최종 SQL 저장/재열람/추가호출0 및 원문 대비 AI 개발 검토를 기록한다. 격리 검증은 사용자 세션의 HTTP/화면 검증이 아니다.

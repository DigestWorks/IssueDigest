# 수집본의 검토·버전·검색 편입

2026-10-18. M2의 다음 단계다. 정책뉴스 journal의 특정 성공 원본을 기사별 검토한 기존 PolicyJob으로 편입한다. 원문·표시·검색·편입 receipt를 원자 저장하고 이후 승인 원본은 의미가 같으면 기존 snapshot을 재사용한다. OpenSpec root=null, 초기화하지 않는다. 현재 앱의 질문/인용 여정과 R2/R3/R6·D019~D022를 따른다.

## Global Constraints

- 출처 확대/새 HTTP/모델/DBOS/공개 게시/웹·API·OpenAPI·의존성 변경은 없다. 시간당 수집기는 기존 pinned source/config/주기를 유지하며 raw 확보만 수행한다. intake는 특정 성공 attempt와 정확 원본 hash·시각·기사별 권리/사진·외부 저작물 제외·원문 인용을 승인한 명시 private CLI에서만 실행한다. 수집 성공을 사용자·공개 승인으로 승격하지 않는다.
- config는 기존 PolicyCollectionConfig를 재사용한다. URL/실제 DB명·불변 config 결합·성공 terminal·capture/report bytes/SHA·정확 기사 집합·원본 시각을 재검증한다. latest 대신 UUID4 attempt_id를 고정한다. 실패/중단/running·다른 channel·unknown attempt·SHA/보고서 변조·원문/권리 불일치는 쓰기 전에 고정 오류다. 저장된 journal 원본/terminal은 바꾸지 않는다.
- 기존 PolicyJob/parse_policy_job·capture parser·policy change 검증·정확 인용 추출을 재사용한다. 새 승인 envelope는 schema_version=정수1, workspace_id(UUID4), collection(기존 config), attempt_id(UUID4), approval(기존 PolicyJob)만 포함한다. 전체 최대256KiB, 엄격 UTF8/중복JSON/비유한/extra/불리언 정수/forged model 우회 거부, 기존 소유400/600 절대 regular 파일과 경로 guard를 재사용한다. 기사1~2개·기사당 인용1~10/각2,000자 등 기존 bounds를 유지한다.
- 새 source에는 source_id/news_id와 공식 URL이 정확히 대응해야 한다. 같은 workspace/provider/source_id의 기존 SourceDocument는 동일 document_id/payload를 사용하고 다른 문서 ID로 재등록하지 않는다. 최초 추적은 현재 원본의 검증된 기준 버전을 만들며 옛 raw/의미 metadata가 없는 기존 버전과 같다고 추정하지 않는다. 이후 마지막 승인 receipt의 의미 fingerprint(기존 compare의 이미 계산된 after_fingerprint SHA256)와 승인 인용 selector 배열(순서 포함, UUID 제외)이 모두 같으면 기존 snapshot을 재사용한다. 인용 선택이 바뀌면 같은 본문이어도 새 승인 버전이며 선택을 버리지 않는다. 본문·제목·발행 주체/일자·권리·parser profile 변화는 새 버전이며 A→B→A도 새 버전이다. 시각/장식만 다르면 중복 EvidenceBundle/인용/outbox를 만들지 않는다.
- 새 버전은 문서만 유지하고 version/raw_object/representation/snapshot/citation UUID4를 새로 사용하며, 승인 수집 시각은 해당 문서의 마지막 승인 receipt 및 기존 canonical version보다 엄격히 나중이어야 한다. 원래 버전/인용/브리핑·고정 검색 근거는 덮거나 삭제하지 않는다. 같은 attempt의 재적용은 같은 승인 요청 hash에서만 재사용하고 다른 ID/승인/내용으로 바꾸면 거부한다. 이미 뒤의 원본이 편입된 뒤 새롭게 과거 attempt를 편입하지 않는다. terminal receipt는 append-only이며 DB 소유자 직접 변조를 막는 trigger/권한 시스템을 주장하지 않는다.
- 저장은 기존 PostgreSQL의 분리된0009 receipt 테이블과 기존 EvidenceRepository._save·기존 표시/검색 투영을 이용한다. 한 READ COMMITTED transaction에서 원문·정확 인용·outbox·SourcePresentation·검색 투영·receipt를 함께 commit/rollback한다. intake 전용 nonblocking transaction advisory lock(104704,3)은 수집/연구 잠금과 별도다. DB명/원래 backend/잠금·current scope를 쓰기 및 commit 전에 확인하고 commit 불명확 시 재시도/실패 덮어쓰기를 하지 않는다. --check는 일관된 READ ONLY 검증이며 행/잠금 쓰기/HTTP/모델 없이 예상 new/reused 집계만 반환한다.
- receipt는 workspace_id/attempt_id/news_id를 unique identity로 사용하며 channel FK와 정확 성공 attempt, document/version/representation/snapshot의 기존 복합 관계·capture 시각·capture/report/request/fingerprint SHA256·created/reused 결정을 보존한다. 모든 UUID4/상태/시각/해시/9자리 ID/관계 제약은 migration/runtime schema에 일치한다. fingerprint_sha256은 기존 report의 이미 계산된 after_fingerprint digest를 그대로 사용한다. worker는 기존 parser/compare로 의미를 재검증하고 storage는 같은 저장 report의 해당 source/after_fingerprint와 정확 대조한다. approval/request hash만 검증한 model의 JSON값을 json.dumps(ensure_ascii=False,sort_keys=True,separators=(",",":"),allow_nan=False)로 UTF8 인코딩한 SHA256이다. storage에 connector/worker 의존성을 추가하지 않는다. storage는 bounded JSON envelope·원본/보고서 hash·scope/시각·bundle graph/provenance를 검증하고, HTML의 본문/권리/metadata 재추출은 worker의 기존 parser가 담당한다. storage에 별도 HTML/text 추출기를 만들지 않는다.
- 새 질문의 제한 한국어 variant_candidates는 intake가 있는 문서에서 마지막 승인 receipt snapshot만 검색한다. 해당 최신본이 미색인/질문 불일치여도 구판으로 fallback하지 않는다. legacy/다른 문서·workspace는 그대로며 보호 literal 검색/정확 원문 reader는 역사 버전도 읽는다. 이미 고정한 run/일반 후속 부모/과거v2/v3/v4 prompt·유료 checkpoint/공개v1·세션/권한/예산은 그대로다. lexical profile question-topics-ko-v2의 정규화/점수·한도는 바꾸지 않는다. 조회 자체는 receipt/원본/표시/색인/모델을 만들지 않는다.
- 출력·예외/log는 고정 오류 또는 schema_version/outcome/sources/new_versions/reused_versions/receipts_created의 집계 allowlist만이다. 기사/attempt/collection/workspace/문서/인용 ID·원문·제목·URL·경로·DSN·계정은 출력하지 않는다. check와 실제 적용/이미 적용/busy를 구분한다. CLI는 private_engine_lifecycle 정리 후에만 출력한다.
- 하위 구현자는 subagent를 만들지 않고 실제 서버/키/자료/외부 HTTP를 쓰지 않는다. 전용 합성 PostgreSQL만 사용하고 fixture reset을 동시에 실행하지 않는다. controller는 전체/독립 검토·실제 백업/복원·권한·검토한 고정 기사1건의 명시 개발 적용·가능한 API/worker 안전 갱신·Draft PR·Sites를 맡는다. 기존 데이터/로그인/공개 게시·main/운영 유예(D013)와 사용자 탭을 보존한다.

## Controller 인수·운영 경계

전체 검사/작업별·전체 독립 검토를 통과한 뒤 실제 서버를 읽는다. 현재 hourly collector의 수정 후 실제 상태/시도와 old app source·활성 run을 확인한다. 사전/직전 백업과 별도 복원에서0009/최소 app SELECT·승인 한 건의 --check/--apply·같은 승인 재실행·정확 원문/검색·새 질문 최신본/old fixed citation·전체 보존을 확인한다. 실제의 새로운 내용 변경을 만들거나 기사가 바뀌었다고 합성하지 않는다. 첫 추적 기준 버전과 실제 내용 변경 관측을 구분한다. 실제 source/approval/IDs/설정/원문은 private 보관한다.

기존 개발 권한으로 가능하면0009·기존 app의 해당 receipt SELECT만 부여하고, 명시 승인 자료1건을 편입한다. 새 질문의 storage 필터는 활성 작업0·기존 실행 정리/안전 재시작 절차 후 개인 API/연구 worker만 갱신한다. 기존 HTTPS 정적 UI·계정/세션·공개 게시·과거결과·시간당 collector source/환경/한도와 main은 보존한다. 중단/다른 권한/자료 부족이 있으면 코드 완료와 실제 적용을 분리해 이유를 기록한다. 마일스톤M2·tasks/progress·Draft PR(이전PR38 기반)·Sites와 이전 계획판을 갱신한다. 사용자 브라우저는 열거나 이동하지 않는다.

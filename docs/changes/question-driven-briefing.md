# 질문만으로 시작하는 브리핑

2026-10-16. 사용자 요청: 나중에 제거할 사용자용 체크포인트를 만들지 않고 최종 제품의 경로로 개발한다. 하단 자료 범위·수동 선택과 그 전제의 요청·AI 지침·불필요한 페이지를 제거한다. 기준은 D016~D018과 제품 경험 인터뷰다.

## Global Constraints

- 사용자 입력은 질문과 선택적인 이전 브리핑 맥락이다. 자료 선택 화면·사전 목록·클라이언트 추천·자료 ID 입력을 요구하지 않는다. 근거 열기는 결과의 정확 인용을 통해 제공한다.
- 서버가 현재 접근 가능한 실제 색인에서 관련 자료를 찾는다. 임의 최신 자료나 전체 카탈로그를 기본 선택하지 않는다. 현재 저장 색인의 제한된 검색을 웹 전체 탐색·의미 검색 완료라고 표현하지 않는다. 이 요청/검색/인용 경로는 운영에 이어갈 계약이며 임시 사용자 도구를 추가하지 않는다.
- ResearchRequest는 request_id·question·parent_run_id만 허용한다. snapshot_ids와 다른 임의 필드는 거부한다. ResearchRun.snapshot_ids는 서버가 실제 찾은 근거의 기록이며0~5개, 완료 결과는1개 이상의 유효 근거를 포함한다. 과거 저장 결과는 그대로 읽는다.
- 새 run은 queued·빈 근거로 저장한다. worker가 권한 확인과 run 잠금 뒤 검색·최대5개 근거 ID 고정·retrieving 전환을 한 트랜잭션으로 수행한다. 재시도/복구에서 이미 고정한 근거를 다시 선택하지 않는다. 현재 권한·취소·원문/색인 무결성·동일 요청 재시도·예산 한도·모델 결과 검증을 유지한다.
- 검색은 기존 검증된 search_evidence와 원문 로더를 재사용한다. 질문에서 의미 있는 단어를 제한적으로 추출하고 단순 한국어 조사 변형을 보조하되 질문 전체를 그대로 검색어로 쓰거나 임의 자료로 대체하지 않는다. 최대8개 검색어, 최대5개 자료로 제한하고 일치도·동률 순서를 결정적으로 처리한다. 출처 본문/인용을 생성하거나 변형하지 않는다.
- 새 질문에서 근거를 못 찾으면 insufficient_evidence로 끝내고 모델을 호출하지 않는다. 자료 선택을 요구하지 않는다. 일반 후속 질문처럼 유효 검색어가 없고 완료된 부모가 있는 경우에만 부모의 실제 근거를 재사용한다. 명시적인 새 주제의 검색 실패에 부모 근거를 임의 적용하지 않는다.
- 현재 월 예약/실행 제한과 모호한 과금 응답의 재호출 방지를 유지한다. 무근거 종료는 실제 모델 호출0회지만 기존 보수적 예약/요청 한도 정책은 유지한다. 예산 재설계·공개 가입·운영 main 병합은 이 작업에서 하지 않는다.
- 모델 지침에서 법안 전용·사용자 선택 자료 전제를 제거하고 질문과 서버가 찾은 근거에 기반한 시사 브리핑으로 정리한다. DBOS workflow/agent 버전을 v2로 구분한다. 실제 개발 적용 전에 이전 활성 run/workflow가 없는지 확인하며 진행 중 작업을 임의 폐기하지 않는다.
- 사용자 자료·세션·개인 이메일·키를 공개 기록에 넣지 않는다. 보안/저장/복구 동작은 TDD와 전용 실제 PostgreSQL로 검증한다. 낮은 영향 문구/CSS 삭제에는 구현을 되풀이하는 새 테스트를 쓰지 않는다.

## Task 1: 질문 전용 계약과 서버 근거 검색

- [x] ResearchRequest에서 snapshot_ids와 선택 검증을 제거하고 공백 질문·엄격한 필드 검증은 유지한다. ResearchRun의 서버 근거0~5개와 완료 결과의 유효 근거 계약을 검증한다. API의 수동 연구 자료 카탈로그 GET /research/sources와 전용 ResearchSource/Catalog 공개 모델을 제거한다. 저장소 list_sources가 전용 카탈로그 외에 실제 소비자가 없으면 함께 삭제한다. SourcePresentation·검증 원문·독립 보호 검색/인용 API는 유지한다.
- [x] submit은 질문/부모/요청 ID의 멱등 해시와 빈 근거 queued run을 저장한다. worker_load에서 현재 권한·부모·색인 무결성을 검증한 서버 검색으로 자료를 고정한다. 검색 전용 모듈을 두어 운영 검색 전략을 같은 인터페이스 안에서 개선할 수 있게 한다. 기존 선택 seed→추가 자료의 이중 경로를 제거한다.
- [x] queued일 때만 검색하고 근거 고정과 retrieving 전환을 원자적으로 수행한다. no-hit은0토큰 insufficient_evidence로 종료하고 재조회/취소/복구가 일관되게 동작한다. 기존 저장 run의 ID·인용·결과는 변경하지 않는다. 새 DB 스키마가 불필요하면 만들지 않는다.
- [x] AI prompt의 사용자 선택 ID/법안 요약 전제를 제거하고 서버 근거와 이전 해석의 관계를 정확히 표시한다. 현재 최대 입력/출력·정확 인용·주체/날짜·중립/불충분 지침은 유지한다. agent/workflow v2와 실제 DBOS 중단/재시작에서 근거·모델 결과 재사용을 검증한다.
- [x] TDD: 질문만 제출·수동/타공간 ID 주입 거부·관련/무관 자료 분리·한국어 조사·검색 실패/0호출·일반 후속/새 주제·검색 결과 고정·현재 권한/취소·동시 요청/예산·실제 DBOS 복구·구 결과 읽기. 과거 수동 선택 전용 테스트는 새 제품 동작에 맞춰 바꾸거나 전용 제거분만 삭제한다. 가짜 주제와 실제 색인/인용을 사용하는 fixture로 의도를 유지한다.
- [x] 전체 Python 린트·타입·테스트와 계약 생성 후 커밋한다. 이 작업에서는 생성된 OpenAPI/schema.d.ts만 갱신하고 수동 TS transport·웹은 Task2가 맡는다. 실제 서버·키·Sites는 변경하지 않는다.

## 과거 완료 결과의 정확 인용 호환

v1 저장 실행의 snapshot_ids는 선택한 seed만 포함할 수 있다. 현재 권한을 확인한 완료 결과 읽기에서 기존 ID와 결과 순서를 유지하고, 결과 본문의 workspace/document/version/representation 전체 연결과 재검증한 EvidenceBundle이 같은 기존 원문만 최대5개까지 해석해 응답의 snapshot_ids에 포함한다. 저장 실행·이벤트·시각·Canvas·원문은 수정하지 않는다. v1의 seed 포함 요청 해시와 기존 해석 버전을 확인하며 새 v2 provenance 불일치는 보정하지 않는다. 누락·손상·다른 본문·다른 권한 범위는 거부한다. 일반 후속 질문의 새 실행은 이렇게 확인한 부모의 실제 근거 전체를 고정하며 새 주제의 검색 실패 정책은 유지한다. 별도 카탈로그·선택 화면·API·재생성은 추가하지 않는다.

## 최종 검증과 적용

컨트롤러가 전체 검토·전체 검사·실제 PG/HTTP/모바일·PC의 질문 전용 생성·인용·무근거·로그인/권한·복구를 확인한다. 준비된 개인 개발 환경에서 이전 활성 작업이 없음을 확인한 뒤 웹/API/워커를 함께 갱신하고 HTTPS·모델의 제한된 실제 실행을 검증한다. 자료나 사용자 세션을 임의로 생성하지 않는다. Sites는 현행 계획을 요약하고 이전 계획을 보관한다. main/운영 병합은 하지 않는다.

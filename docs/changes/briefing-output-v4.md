# 최종 생성 출력의 구조 단순화

2026-10-28 KST. v3 공급자 스키마는 수용됐으나 응답 중 연속 공백이 제한을 초과해 생성이 중단됐다. 원응답과 실패 작업은 보존한다. 날짜 필드와 생성 중단 사이의 인과관계는 확정하지 않았다.

## 범위

- 공백 안전장치·인용 검증·원문·명제·사용량 제한을 유지한다.
- 새 v4 입력과 새 출력 도구에서 필수 요약과 선택 상세(비교·타임라인)를 구조로 구분한다. 요약·비교의 주장에는 날짜 필드를 받지 않고, 타임라인만 날짜를 받는다.
- 자료 참조는 입력 순번으로 받고 서버에서 실제 자료 식별자로 변환한다. 범위를 벗어난 순번과 추가 필드는 거부한다.
- 중복 열 이름·상태 표기를 공유하되 원래 입력으로 정확히 복원해야 한다. 사실·조건·숫자·불확실성을 삭제하지 않는다.
- 기존 v1/v2/v3 읽기와 기본 v1 설정은 보존한다. 저장 계약과 앱 출력은 변경하지 않는다.

## 실행 제한

실제 분석 3건을 재사용하고 최종 생성은 새 요청으로 최대 1회만 더 검증한다. 앞선 실패 최종 v2·v3를 포함해 실제 공급자 요청은 이번 검증 전체 최대 6회다. v3 중단 요청의 확정 사용량은 없으므로 0으로 간주하거나 예약을 환급하지 않는다. 추가 실험을 자동 반복하지 않는다.

- [x] 손실 없는 입력·출력 구조·기존 경로 보존 테스트와 독립 검토.
- [x] 전체 검사 및 실제 요청 크기 제한 확인.
- [x] 새 최종 1회, 저장·재열람 및 원문 대조.
- [x] 검증 결과에 따른 개발 API 반영. 계획판 기록은 후속 기록에 명시한다.

개발 API에는 제품41c8e53을 v4 opt-in으로 반영했다. main/운영 배포는 하지 않았다.

전체11,056개(Python10,138·프론트918), 린트·타입·빌드·OpenAPI와 독립 검토를 통과했다. 고정된 실제 입력의 전체 요청 크기는19,861/20,000이며 원래 입력으로 정확히 복원된다. 검토 중 발견한 기존 지시와의 충돌 및 비정규 중복 메타데이터 수용을 수정했다. 최초 전체 검사 실행은 이 수정 전에 중단했고, 수정 후 전체를 새로 실행한 결과다.

## 실제 결과와 개발 반영

새 최종1회가 성공해 요약·비교4개 주장이 SQL에 저장됐다. 동일 결과 재열람·완료 작업 재접수에 추가 요청0을 확인했다. 원문 대조에서 정의·처벌·제안문 귀속·시행본 표시를 확인했다. 2027년 예외 조항을 설명하지 않은 결과이므로 모든 조문의 시행 시점을 인증하지 않는다. AI 개발 검토이며 독립 인간 사실 인증은 아니다.

이번 전체 실제 요청은6회(분석3·실패 최종2·성공 최종1)다. 성공 최종 입력3,790/출력484토큰이며, 알려진 전체 소계는 입력14,174/출력6,270토큰(5회)이다. 중단 v3 1회의 사용량은 미확정으로 보존했다. 모든 호출의 비용 확정이나 월 결제 상한 강제를 주장하지 않는다.

개발 전환 때 기존 작업이 없음을 확인하고 요청을 잠시 차단한 뒤 교체했다. 질문·분석·최종 행의 전후 hash가 일치했고 실제 프로세스의 새 코드 경로/v4 설정과 외부 home/login/health200을 확인했다. 초기 외부 확인 도구가 잘못된 health 경로2개를 조회해404였으며, 기존 정식 /health/live로 재확인했다. DB 스키마·계정·세션·정적 화면·main·Actions 변경과 배포 검증의 유료 호출은 없다. 실제 로그인 사용자의 HTTP 질문/화면 생성은 대신 실행하지 않았다.

# 질문·브리핑 개인 개발 적용

2026-10-26. 검증된 질문 전송·생성·읽기 코드(9170e06)를 개인 개발 환경에 적용한다. main/공용 checkout/운영 게시·DNS/TLS·OAuth 초대·기존 수집기/cron·과거 결과를 변경하지 않는다. 별도 새 제품 기능이나 API 설계 변경은 없다. 이미 검토된 기존 마이그레이션0010~0012와 명시 DBOS migration, 기존 배포 절차를 사용한다. 접속·역할·키·실제 원문/질문·백업은 비공개에 둔다.

## 적용 조건

- 현재 실행과 DB를 읽기 전용 점검한다. 기존 schema0009, 활성 research/workflow0·앱 DDL 권한 없음과 개발자의 기존 소유 역할 가정을 확인했다.
- 서버 밖 full/app archive와 별도 PostgreSQL18.6 복원에서 기존23앱 테이블의 row hash/count 일치를 확인한다(기존 감사 규칙대로 auth_sessions.last_activity_at만 비교에서 제외). 기존 DB에 downgrade/drop/truncate를 수행하지 않는다.
- 분리된 소스/locked 환경/정적 출력을 준비한다. 기존 실행 명령·설정·웹 자산을 복귀용으로 보존한다.
- 기존 앱 스키마0012와 별도 `issuedigest_question_briefing`을 명시 준비한다. 앱은 기존 역할로만 실행하고 새 앱 테이블에 필요한 DML, 별도 DBOS schema의 SDK 권한만 부여한다. DB/public CREATE는 부여하지 않는다. 기존 DBOS journal과 collector는 유지한다.
- 실제 계정의 모델 사용 가능 여부를 확인한다. 모델 조회403은 키의 model.read 부족으로 확인됐으며 지원 모델 부재로 단정하지 않는다. 실제 생성·유료 자동 복구는 이번 준비 검사에서 실행하지 않는다.
- 전환 직전 활성 작업을 다시 확인하고 기존 자신의 API/worker만 정상 종료한다. 새 단일 executor와 API를 같이 시작하고 HTTPS/public/보호 경계·세션 설정·SPA 자산을 확인한다. 실패 시 이전 실행/웹으로 복귀하며 마이그레이션·예약 이력을 파괴하지 않는다.

# 실행·이벤트·화면·사용량 계약

상태: 구현 중 · 2026-10-11 한국 시간. 기준 cb8bebb, 선행 Draft PR #5. 사용자 다음 진행 요청으로 승인된 P1/R4~R6 부분 구현이다. 조사 문서의 §3~5를 제공된 객체와 이력에 대한 실행 가능한 계약으로 옮긴다.

## Global Constraints

- 기존 원문/인용/연구 계약·두 상태 HTTP 경로·웹 UI를 보존한다. Python → 실제 OpenAPI components → 생성 TS/public aliases가 원본 경로다. 새 제품 HTTP/SSE·UI 렌더러·DB/메모리 저장소·워커·AI/유료 호출·Neo4j·인증·공급자 스키마 어댑터를 만들지 않는다. 순수 함수의 이력 재생·예산 판정은 운영 저장·원자성·복구·권한의 구현 증거가 아니다.
- 새 모델은 frozen/extra-forbid, 중첩 tuple 불변, UUID4 내부 ID, NonBlank 원문 보존 문자열, strict schema_version=1, 태그 union이다. 모든 새 count/seq/token/revision/attempt 정수는 bool/숫자 문자열을 거부하고 0..2**53-1(양수 필드는1 이상)로 제한하여 JS 숫자 전송 정밀도를 지킨다. 기존 타입/버전/정수 정책은 변경하지 않는다.
- 새 시각은 aware datetime 또는 ISO datetime 문자열만 받고 UTC 정규화한다. epoch 숫자·숫자 문자열·bool·date-only·naive를 거부하고 정규화 범위 오류는 ValidationError로 처리한다. 공유 값/검증은 contract_values.py에 둔다. 모델 검증 생략 construction/copy는 입력 경로가 아니다.
- 검증 대상은 제공된 데이터·이력이다. 입력된 검토/가격/사용량/저장 표시는 인증·사실·청구서·DB 기록을 증명하지 않는다. 이력의 seq는 순서 기준이며 UTC occurred_at은 run.created_at 이상만 요구한다(벽시계의 엄격 단조 증가를 요구하지 않음).
- 확정 스택·월 전체 운영비 10만 원 상한을 유지한다. DB/검색/실행기/인증/json-render 제안을 채택하지 않는다. 신규 의존성·외부/유료 호출·비공개/운영 자료 사용 없이 합성 fixture로 검증한다.
- 파일 책임: contract_values.py 공통 값, canvas_modules.py 허용 모듈/액션, execution.py 입력/실행/이벤트/재생, canvas.py draft/revision/근거 검증·승격, usage.py 가격/예약/사용량/예산, execution_bundle.py 전체 참조. modules는 execution에 의존하지 않고 execution은 modules를 사용한다. canvas/usage가 execution을 사용해도 역 import cycle이 없어야 한다. 새로운 공통 base class/타입별 payload 내부 클래스는 공개 alias로 모두 내보낼 필요 없다.

## C1. 입력 고정·중복 제출·순번 이력

- ExecutionVersions: model_config_version, prompt_version, tool_registry_version, execution_engine_version (NonBlank), ontology_version=issuedigest-relations-v1, ui_schema_version=issuedigest-canvas-v1. 설정/엔진 버전 기록이며 엔진/모델을 선택·실행한 증거가 아니다.
- RunInput: question NonBlank, selected_version_ids(unique UUID4 tuple, 빈 선택 허용), base_revision_id nullable UUID4, versions ExecutionVersions. 선택한 원문 version_id를 고정한다(파싱 representation pin은 후속). 자료 순서를 입력 의미에 포함하며 순서를 임의 정렬하지 않는다.
- RunSubmission: workspace_id, requester_id UUID4, submission_key NonBlank, input RunInput. Run: schema_version, run_id/request_id/trace_id UUID4, submission, input_sha256, created_at. request_id/run_id/trace_id를 구분한다.
- hash_run_input(input) -> str: validated RunInput의 JSON-compatible model_dump, JSON sort_keys=True/ensure_ascii=False/separators=(',',':')를 UTF8로 SHA256. Run은 입력 해시를 실제 재계산하여 불일치를 거부한다.
- assess_submission(existing: Run|None, submission:RunSubmission) -> SubmissionAssessment. 범위(workspace,requester,key)가 다르거나 existing=None이면 create + existing_run_id=None. 같은 범위와 같은 실제 RunInput이면 reuse + 기존 ID, 다른 입력이면 conflict + 기존 ID. 결과 action/create와 nullable ID 조건을 모델에서도 검사한다. 해시만 믿어 입력 충돌을 감추지 않는다. 실제 unique/동시 제출 처리는 후속 DB 트랜잭션이다.
- RunEvent: schema_version=1, workspace_id/run_id, seq(strict 양수), occurred_at, payload(kind discriminator). payload.kind가 단일 이벤트 종류이며 SSE type/id 포맷은 후속이다.
- payload 종류/필드: run.accepted(추가 필드 없음); stage.changed(stage=search|tools|validation|composition); module.ready(revision_id UUID4, module 완성 CanvasModule); run.cancel_requested(없음); run.awaiting_reconciliation(attempt_ids nonempty unique UUID4 tuple); run.reconciliation_resolved(attempt_ids nonempty unique tuple); run.succeeded(revision_id UUID4); run.failed(error_code=validation_failed|provider_refused|incomplete_output|tool_failed|internal_error|budget_exceeded, retryable strict bool); run.cancelled(없음). 원시 예외·임의 진행률·내부 추론문 필드는 없다.
- RunHistory: run + events tuple. 빈 이력 허용; 그 외 첫 event=accepted/seq1, 전체 seq1..N 연속·한 run/workspace·시각>=created. 중복 accepted/seq, gap/foreign event, 알 수 없는 payload/필드를 거부한다.
- replay_run(history) -> RunSnapshot: 불변 이력을 결정적으로 fold. Snapshot은 workspace/run_id, status(queued|running|cancel_requested|awaiting_reconciliation|succeeded|failed|cancelled), accepted strict bool, last_seq, last_event_at nullable UTC, stage nullable 위 enum, base_revision_id/current_revision_id/pending_revision_id nullable UUID4, cancel_requested strict bool, unresolved_attempt_ids unique tuple를 가진다. 초기 queued/accepted=False/seq0, 현재 정상 revision은 input.base_revision_id다.
- accepted는 첫 접수만; stage.changed는 queued/running에서 running; module.ready는 running에서만 pending_revision_id 갱신. cancel_requested는 queued/running/awaiting에서 취소 의도를 고정하고 cancel_requested 상태. awaiting는 running/cancel_requested에서 새 unresolved attempt들을 보류(기존 pending과 중복/이미 해소된 ID 재등록 거부). resolved는 pending의 지정 subset만 제거하며 모두 해소되면 취소 의도에 따라 cancel_requested 또는 running. subset 해소 후 pending이 남으면 awaiting_reconciliation이며 cancelled 상태였다면 그대로 cancelled다. cancelled 후 resolved는 비용 확인용으로 허용하되 화면/상태를 되돌리지 않는다.
- succeeded/failed는 queued/running이며 unresolved 없음, 취소 의도 없음인 경우만. succeeded는 current_revision_id를 승격하고 pending 제거. failed는 기존 정상 revision 유지·pending 제거. cancelled는 queued/running/cancel_requested/awaiting에서 취소 의도=True·pending 제거·정상 revision 유지하며 미확인 attempt는 보존한다. 최종 상태 이후 resolved-on-cancelled 이외 이벤트는 거부한다. stage는 마지막 단계를 보존하고 phase 순서로 가상의 진행률을 만들지 않는다.
- Snapshot 자체도 accepted↔seq/last_event_at, running이면 stage필수/queued이면 stageNone(최종 상태는 마지막 stage 보존), 취소 상태↔의도, 미접수 초기 상태, terminal pending=None/실패·취소 current=base/성공 current non-null, awaiting은 unresolved필수, queued/running/succeeded/failed는 unresolved없음, unaccepted면 완전 초기 상태 등을 검사한다. 원래 이력 없는 결과가 이력 재생과 같다고 인증하지 않는다.
- may_start_paid_step(snapshot) -> bool: accepted/running, 취소 의도 없음, unresolved 없음만 True. 외부 실행이 아닌 순수 허용 규칙이다.
- events_after(history, after_seq:int) -> ReplayBatch: bool/string/음수/unsafe/현재 seq보다 앞선 미래 커서 거부, validated 전체 이력의 cursor 이후 이벤트+latest_snapshot 반환. ReplayBatch는 workspace/run, after_seq<=snapshot.last_seq, 이벤트 ID·seq 연속/끝 seq=최신을 검사한다. gap/충돌이 있는 이력을 정렬·무시하지 않는다. 이벤트 저장·SSE·실시간 합류·보존 만료 커서는 후속이다.

## C2. 허용된 화면과 정상 결과 보존

- 액션 태그: open_evidence(citation_id), select_document(document_id), ask_question(question NonBlank), sort(field=source_date|title,direction=asc|desc). UUID4 참조, tuple. 임의 URL/스크립트/CSS/도구/쓰기 액션은 스키마에 없다. ask_question은 후속 사용자 동작의 제안이지 자동 호출·권한이 아니다.
- 공통 모듈: module_id UUID4, kind, title NonBlank, span=half|full, citation_ids(nonempty unique), actions(tuple). title은 제공된 표시 문자열이며 의미 검토/텍스트 안전 렌더링은 후속이다. module.kind union: evidence(별도 데이터 없음), summary(claim_ids nonempty unique), comparison(claim_ids 최소2 unique), timeline(claim_ids nonempty unique), graph(relation_ids nonempty unique), chart(observation_ids 최소2 unique, chart_type=bar). 구조화된 props만 있고 자료 내용/수치를 직접 덮어쓰는 값이나 HTML/CSS/URL 실행 필드는 없다. 원문 표시는 기존 인용/주장/관측에서 가져온다.
- CanvasDraft: schema_version=1, draft_id UUID4, outcome=answer|insufficient_evidence|clarification_needed|provider_refusal|incomplete_output, modules tuple, message nullable NonBlank. answer는 nonempty modules/message=None, 다른 outcome은 modules=empty/message필수. 모듈 ID unique. Draft는 정규화된 내부 제안이며 workspace/run/검증·생성 시각 권한 필드는 없다. 공급자 전용 스키마/ID 부여 어댑터는 후속이다.
- CanvasRevision: schema_version=1, revision_id/workspace_id/run_id UUID4, revision_number strict 양수, parent_revision_id nullable UUID4, selected_version_ids unique tuple, draft, validated_at UTC, validation_policy=issuedigest-canvas-v1. 실패(refusal/incomplete)는 revision으로 승격하지 않는다. parent=None이면 revision_number=1, parent=self 거부. 표시는 입력 검증 마커이며 인증된 서버 저장을 증명하지 않는다.
- CanvasBundle(research ResearchBundle, revision CanvasRevision): 같은 workspace·선택 version 실제 존재; 모든 module 인용은 선택 version에 속하고 실제 존재. claim/relation/observation IDs 실제 참조; 해당 모듈의 citation_ids 집합은 참조된 기록 인용의 합집합과 정확히 같음(evidence는 자체 인용). timeline은 claim.valid_period 알려져야 함. chart는 값 모두 존재하고 assess_comparison(...).status=same_context만 허용, 수치 복제 필드·pie/100% 합산 없음. 이 조건 일치도 통계 인증이 아니다.
- 모듈 액션 open_evidence는 그 모듈의 인용 subset, select_document는 선택 version 문서 subset. 같은 action 완전 중복 거부; 의미적으로 다른 ask_question/sort 조합 허용. 실제 접근 권한·행위·AI 호출 없음.
- promote_revision(current:CanvasRevision|None,candidate:CanvasBundle,expected_revision_id:UUID4|None)->CanvasRevision. 입력 current ID=expected, 새 parent=current ID/number+1, 같은 workspace 및 서로 다른 revision ID. current=None은 expected/parentNone,number1만. 불일치 ValueError; 성공은 candidate.revision을 반환하며 current 객체/저장소는 바꾸지 않는다. 이 함수는 후보 근거와 revision 충돌만 검사하며 실행 성공/취소 적격성은 이력으로 별도 확인한다. 실제 CAS·동시 변경은 후속이다.

## C3. 유료 호출·정밀 예약·예산

- CallAttempt(execution.py): attempt_id/workspace_id/run_id/step_id UUID4, attempt_number strict 양수, authorized_after_seq nonnegative safe int, provider/operation NonBlank, model nullable NonBlank, paid strict bool, status=prepared|dispatched|succeeded|failed|outcome_unknown|cancelled_before_dispatch, created_at UTC, dispatched_at/finished_at nullable UTC, result_id nullable UUID4, provider_request_id/provider_idempotency_key nullable NonBlank, supports_query/supports_cancel strict bool. prepared와 cancelled_before_dispatch는 dispatched_at/result_id=None; prepared finished=None, cancelled_before_dispatch finished>=created. dispatched는 dispatched_at>=created, finished/result=None. succeeded/failed/outcome_unknown는 dispatch필수·finished>=dispatch; succeeded만 result_id필수, 나머지는 result_id=None. 입력된 결과/지원 기록이지 공급자 확인 증거가 아니다.
- MoneyMicrowon: strict ASCII nonnegative integer 문자열 '0' 또는 [1-9][0-9]*, 최대128자·whole-match. 1원=1,000,000 microwon. bool/float/지수/공백/선행0/음수/숫자 입력 거부, 계산은 Python int. 가격/환율은 bounded strict ASCII nonnegative decimal string, whole-match; fx는 양수. Decimal의 context 반올림을 비용 합계에 사용하지 않는다.
- PricingSnapshot: snapshot_id UUID4, provider/operation NonBlank, model nullable NonBlank, pricing_version/exchange_rate_version NonBlank, captured_at UTC, currency=KRW|USD, unit_price 위 소수 문자열, unit_quantity strict 양수, fx_krw_per_currency 위 양수 소수 문자열(KRW는 정확한 수치1). 단가/환율·추정 비용의 의미 일치나 실시간 요금 조회/변환 계산은 후속이다.
- BudgetWindow: workspace_id, period DateInterval(Asia/Seoul 기준 완전한 달: 첫날~그 달 마지막날), timezone=Asia/Seoul, limit_microwon 양수 Money (최대100000000000), committed_other_cost_microwon Money. 월 10만 원은 전체 운영비이며 다른 서버·DB·저장·세금·같은 키 외부 비용 입력을 별도 반영한다. 실제 외부 지출 집계는 후속이다.
- UsageReservation: reservation_id/workspace_id/run_id UUID4, period DateInterval, reserved_microwon Money, status=held|settled, pricing_snapshot_ids nonempty unique UUID4, created_at UTC, settled_at UTC nullable, settled_microwon nullable Money. held는 두 settled값None; settled는 두 값필수/시간>=created. 실제 비용이 예약을 넘은 경우를 버리지 않는다.
- UsageEntry: entry_id/workspace_id/run_id/reservation_id/attempt_id/pricing_snapshot_id UUID4, provider/operation NonBlank, model nullable NonBlank, input_tokens/output_tokens nullable nonnegative safe int, charge_status=confirmed|estimated|unknown|not_charged, cost_microwon nullable Money, provider_usage_ref nullable NonBlank. confirmed/estimated는 비용 필수, unknown은 null 또는 보수적 추정값 허용, not_charged는 정확히 문자열 '0'. 취소·실패는 환불이 아니다.
- UsageBook: window, pricing_snapshots/reservations/entries tuples. 각 ID·entry의 attempt_id unique, 같은 run 예약은 하나. 모든 예약/entry workspace=window, period일치, 참조 가격·예약 실제 존재, entry.run=reservation.run, provider/operation/model=price, 가격 captured<=reservation.created. 예약 created_at의 서울 날짜는 예약 달 안이며 정산 시각은 다음 달에도 가능하다. settled 예약은 unknown/estimated entry를 거부하고 settled_microwon=sum confirmed/not_charged 비용과 같아야 함. 빈 entry+settled0 허용. 이 snapshot은 수정 가능한 DB ledger나 완전한 청구 내역 증거가 아니다.
- assess_budget(book:UsageBook,requested_microwon:str)->BudgetAssessment: used=othercost + 각 settled 실제비용 또는 held max(예약금, 알려진/추정 entry비용 합). 결과 limit/used/requested/remaining/overrun Money, allowed strictbool, policy_version=issuedigest-budget-v1. remaining=max(limit-used,0),overrun=max(used-limit,0),allowed=(used+requested<=limit). 결과 모델 자체도 이 식/상한을 검증한다. unknown에는 held 최대를 유지, 알려진 retry비용은 각 attempt 모두 합산, 초과 실제 비용을0으로 만들지 않는다. 새 예약을 실제 추가하거나 동시성/원자성을 보장하지 않는다.

## C4. 전체 참조·순서·생성 계약

- RunExecutionBundle: schema_version=1, history RunHistory, research ResearchBundle, revisions tuple CanvasRevision, attempts tuple CallAttempt, usage nullable UsageBook. 모든 주어진 대상 workspace=run workspace. research는 비어도 됨. run의 selected_version_ids 실제 존재, base revision 실제 존재/다른run/sameworkspace. revisions ID unique, 부모 실제 존재/number=parent+1/같은 workspace(숫자 증가로 cycle 거부). 기존 run의 ancestor revisions를 포함할 수 있음; 그 인용도 research에서 검증한다. 현재 run의 revision 선택 tuple=RunInput tuple, 최초는 base를 부모로, 후속은 현재 run revision을 부모로(다른 run 부모는 base만). validated_at>=run.created_at는 현재 run revisions만 요구.
- 모든 revision을 CanvasBundle로 검증한다. module.ready의 revision은 현재 run에 속하며 payload module이 그 revision의 module과 정확히 동일. ready revision number는 이벤트 순서에 따라 뒤로 가지 않음. succeeded 참조도 현재 run이며 그 revision의 모든 모듈은 동일 revision의 ready event로 발표됐어야 한다(정상 정보 부족/확인 요청의 empty modules는 허용). 실패·취소의 snapshot은 마지막 정상 base를 보존한다. 기존 ancestor의 run history 전체는 요구하지 않는다.

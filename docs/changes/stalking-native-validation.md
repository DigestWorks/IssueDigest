# 스토킹 브리핑의 격리 실제 검증

2026-10-28 KST. 검색된 근거가 실제 분석·최종 생성·저장으로 이어지는지 확인한다. 실제 개발 앱에는 현재까지 새 자료를 사용한 사용자 질문이 없다. 사용자의 로그인·세션을 대신 만들거나 공유 DB에 검증용 질문을 넣지 않는다.

## 실행 범위

- 검토한 공식 자료 3건의 원문/인용 내용은 보존하고, 자료·workspace·사용자 식별자는 별도 합성 ID로 바꿔 전용 격리 DB에 적재한다.
- 새 질문 계획→실제 Astra/v5 분석 최대3회→최종 생성 최대1회→SQL 저장·정확 재열람을 검증한다. 단계별1달러씩 최대 합계4달러의 SQL 예약만 허용한다. 이는 실제 공급자 청구액을 강제하는 결제 한도가 아니며 실제 사용량·청구액과 구분한다.
- 공식 OpenAI HTTPS Responses 목적지·모델·store/stream·요청 수·시간/입력/출력 제한을 고정한다. 자동 재시도와 실패한 유료 단계의 재실행은 하지 않는다. 외부 호출 전에 실행 의도를 보존한다.
- 시작 전 소스·도구·입력을 고정하고 별도 검토한다. 원응답·사용량·실패·격리 DB 증거는 private에 보존한다.
- 공유 앱의 자료·질문·세션·계정·배포·모델 기본값·공개 게시를 바꾸지 않는다. 네이티브 생성/SQL 검증을 실제 사용자 HTTP/화면 검증으로 부르지 않는다.

## 품질 기준

1. 근거가 충분할 때 최소 요약을 포함한 브리핑이 생성되고 정확 인용으로 원문에 연결된다.
2. 법안의 제안 당시 설명과 현재 시행 법률을 섞지 않는다. 두 제안문의 제안을 현행 규정으로 단정하지 않는다.
3. 시행일을 설명할 경우 2026-10-02 시행본과 제17조의10제2항의 2027-04-22 시행 예외를 구분한다. 자료에 없는 최신 사건·정치적 입장·여론을 만들어내지 않는다.
4. 부족·실패는 그대로 기록하고 추가 생성으로 정답을 맞추지 않는다. 최종 문장 검토는 AI 개발 검토이며 독립적인 사실 인증이나 인간 검토가 아니다.
5. 저장 결과와 재열람이 일치하고 완료 작업을 다시 읽어도 추가 공급자 요청이 없어야 한다.

## 첫 실행의 도구 오류

첫 실제 모드 실행은 공급자 요청 intent 기록 이전에 검증 도구의 `EvidenceJob.reservation_usd` 접근에서 중단됐다. 해당 DTO는 예약액을 노출하지 않는데, 모의 객체만 사용한 보호 검사에서 이를 놓쳤다. 실제 격리 SQL 작업과 결제 없는 SDK 모의 전송으로 같은 AttributeError를 재현했다. 외부 전송 intent 0건·보호 transport count0이며, 서비스의 생성 오류로 분류하지 않는다.

기존 실패 작업·예약·실행 의도·준비 파일은 보존한다. 현재 권한을 검증한 뒤 실제 SQL 행의 예약액을 검사하도록 보완하고, 실제 DTO를 사용하는 무호출 통합 검사를 추가한다. 새 격리 환경/새 승인에서만 재개하며 기존 실패 작업이나 불명확한 유료 요청을 재호출하지 않는다.

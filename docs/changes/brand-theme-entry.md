# 브랜드·테마·로그인 진입 정리

2026-10-16. 사용자 요청에 따른 후속 UI 작업. 기준은 B2C 제품 경험/D016과 [이전 브리핑 연결](briefing-experience.md)이다. 공개 브리핑 저장·게시 기능이 구현되지 않은 개발 환경에서 로그인 안내의 반복을 제거하고 명시적 동작으로 인증을 시작한다.

## 수용 기준

- 이미지 생성 도구로 만든 독창적인 투명 PNG 로고를 앱 자산으로 보관하고 홈·로그인·원문 화면의 브랜드와 favicon에 연결한다. 워드마크는 실제 텍스트 IssueDigest로 유지한다. 생성 프롬프트와 도구 방식을 기록한다.
- 명시적 밝게/어둡게 전환 버튼이 홈·로그인·원문 화면에서 보이고 현재 상태와 다음 동작을 접근 가능한 이름으로 알린다. 선택을 기기에 보존하고 새로고침·화면 이동에도 유지한다. 선택 전 시스템 선호를 따른다. 저장 접근 거부/SSR에서도 동작하며 첫 표시 깜빡임과 hydration 불일치를 피한다.
- 밝은/어두운 테마가 조사 입력·생성/실패·저장 결과·브리핑/비교/차트·검색·인용/원문 창과 로그인까지 읽기 좋은 대비로 일관되게 적용된다. 320px 모바일에서 넘침·버튼 잘림이 없다.
- 우측 상단 계정 메뉴 안에 명시적 로그인 항목을 둔다. 인증된 경우 같은 메뉴에서 로그아웃한다. 메뉴는 키보드, Escape/바깥 클릭, 포커스 복귀로 사용할 수 있다. 테마 버튼은 계정과 별도로 항상 보인다.
- 정상 비회원 홈은 ‘로그인이 필요합니다’, 초대된 계정 안내, 로그인 CTA 반복을 제거한다. 질문 입력과 기본 탐색/테마는 사용할 수 있다. 실제 공개 브리핑이 없다는 상태를 짧게 표시하며 가짜 콘텐츠를 만들지 않는다.
- 비회원 질문의 ‘질문하기’ 제출 시에만 기존 유효기간/크기 제한 sessionStorage 질문 초안을 보존하고 /login으로 이동한다. 빈 입력은 제출하지 않는다. 저장 실패는 해당 위치에 피드백한다. 로그인 후 질문을 편집 상태로 복원하되 자동 AI 호출은 하지 않는다.
- 비회원의 저장한 조사·비공개 자료 탐색은 해당 행동 시 /login으로 이동한다. /?view=saved 또는 sources 직접 진입도 인증이 확인된 뒤 로그인으로 연결하며 보호된 API를 먼저 호출하지 않는다. 로딩/네트워크/접근 거부를 비회원으로 오판하지 않는다.
- 실제 Google 로그인 화면의 필요한 안내와 OAuth 오류는 보존한다. 네이티브 POST·중복 제출 방지·고정 callback을 보존한다. 질문 임시 보관/실패 보존, 기존 근거·조사 취소·권한·latest intent·자동 저장 흐름을 회귀시키지 않는다.

## Global Constraints

- 프론트엔드와 로고 자산 범위다. 백엔드·API 계약·DB·개인 세션·운영 비밀값·main은 변경하지 않는다. 실제 모델/공급자 호출을 검증용으로 실행하지 않는다.
- 기존 비공개 자료를 공개하지 않는다. 비회원 공개 브리핑 제공은 후속 게시 계약이 필요하다. 현재는 실제 준비 상태를 정직하게 표시한다.
- 기존 질문 초안 helper의 sessionStorage·30분/1500자 제한과 명시 실행을 유지한다. 로컬 스토리지는 비민감 테마 선호에만 사용하며 인증·질문을 옮기지 않는다.
- 새 라이브러리·웹 폰트·외부 이미지 요청 없이 현재 의존성과 자산으로 구현한다. 장식·설명 문구를 늘리지 않고 편집형 디자인을 유지한다.
- 사용자의 브라우저 탭을 열거나 이동하지 않는다. 독립 headless QA만 수행한다. 개인 개발 HTTPS 웹 반영과 Draft PR은 기존 승인 범위이며 main/운영 배포는 유예한다.

## Task 1: 로고·명시 테마·계정 메뉴와 동작 시 로그인

- [ ] 구현·검증·작업 독립 검토 완료.

위 수용 기준과 Global Constraints가 요구사항이다. 기존 파일 root.tsx, routes/home.tsx, routes/login.tsx, evidence 읽기 경로, styles.css/research.css/search.css/reader.css와 packages/ui 스타일의 실제 사용을 먼저 확인한다. 필요한 공용 Brand/Header/ThemeToggle을 만들되 과도하게 분할하지 않는다. 헤더의 어두운 테마 버튼과 계정 메뉴는 모바일에서도 명확해야 한다. 재사용 UI 패키지 기본 색은 유지할 수 있으나 앱의 dark scope에서 모든 생성 모듈을 덮어쓸 수 있어야 한다.

컨트롤러가 이미지 도구로 생성한 `apps/web/public/brand/issuedigest-mark-v1.png`를 제공한다. 준비될 때까지 나머지 UI 작업을 진행하고, 파일 제공 후 실제 로고를 연결한다. 임의 SVG/텍스트를 최종 생성 로고로 대체하지 않는다. 컨트롤러가 생성 프롬프트/자산 설명을 기록한다.

TDD: 먼저 실패하는 실제 동작 테스트를 추가한 뒤 구현한다. 기존 tests의 문구 변경은 새 동작에 맞게 갱신하고 보안/초안 assertions를 약화하지 않는다. 테마 저장·시스템 초기값/거부 저장·SSR 안전성, 계정 메뉴 키보드·닫기, guest 정상 홈 중복 로그인 없음, 질문 보존/로그인 이동, 비공개 navigation 클릭/직접 URL 인증 경계와 네트워크 실패 구분을 검증한다. 테스트마다 같은 구현을 복제하거나 CSS 문자열 검사만으로 동작을 통과시키지 않는다. CSS 전체 대비·320/390/desktop과 생성 Canvas/원문 창 시각 검증은 컨트롤러의 독립 브라우저 QA로 보완한다.

검증: Node24.21.0/npm11.19.0에서 전체 JS tests, eslint, workspaces typecheck, build, contract:check를 실행한다. 새 dependencies/lockfile/API 변경은 필요하지 않다. 원격 서버·DB·개인 키·실제 OAuth 흐름·모델 호출은 구현자 범위가 아니다.

독립 작업 리뷰 후 필요한 수정도 같은 구현자가 수행한다. 자신은 서브에이전트를 만들지 않는다. 커밋은 현재 feature branch에만 하고 푸시하지 않는다. Task 완료 체크는 실제 요구사항 구현과 증거가 마련된 뒤 한다.

## 컨트롤러 마무리

독립 작업/전체 리뷰와 headless 테마·로그인 전환·화면 대비 QA 뒤 개인 개발 HTTPS 정적 웹에 반영한다. Draft PR과 저장소 진행 기록, Sites 요약을 갱신한다. 실제 Google 계정 로그인을 대리하거나 공개 자료가 생겼다고 표시하지 않는다.

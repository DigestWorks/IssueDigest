# 브랜드·테마·로그인 진입 정리

2026-10-16. 사용자 요청에 따른 후속 UI 작업. 기준은 B2C 제품 경험/D016과 [이전 브리핑 연결](briefing-experience.md)이다. 공개 브리핑 저장·게시 기능이 구현되지 않은 개발 환경에서 로그인 안내의 반복을 제거하고 명시적 동작으로 인증을 시작한다.

## 수용 기준

- 이미지 생성 도구로 만든 독창적인 투명 PNG 로고를 앱 자산으로 보관하고 홈·로그인·원문 화면의 브랜드와 favicon에 연결한다. 워드마크는 실제 텍스트 IssueDigest로 유지한다. 생성 프롬프트와 도구 방식을 기록한다.
- 명시적 밝게/어둡게 전환 버튼이 홈·로그인·원문 화면에서 보이고 현재 상태와 다음 동작을 접근 가능한 이름으로 알린다. 선택을 기기에 보존하고 새로고침·화면 이동에도 유지한다. 선택 전 시스템 선호를 따른다. 저장 접근 거부/SSR에서도 동작하며 첫 표시 깜빡임과 hydration 불일치를 피한다.
- 밝은/어두운 테마가 조사 입력·생성/실패·저장 결과·브리핑/비교/차트·검색·인용/원문 창과 로그인까지 읽기 좋은 대비로 일관되게 적용된다. 320px 모바일에서 넘침·버튼 잘림이 없다.
- 우측 상단 계정 메뉴 안에 명시적 로그인 항목을 둔다. 인증된 경우 같은 메뉴에서 로그아웃한다. 메뉴는 키보드, Escape/바깥 클릭, 포커스 복귀로 사용할 수 있다. 테마 버튼은 계정과 별도로 항상 보인다.
- 정상 비회원 홈은 ‘로그인이 필요합니다’, 초대된 계정 안내, 로그인 CTA 반복을 제거한다. 질문 입력과 기본 탐색/테마는 사용할 수 있다. 실제 공개 브리핑이 없다는 상태를 짧게 표시하며 가짜 콘텐츠를 만들지 않는다.
- 비회원 질문의 ‘질문하기’ 제출 시에만 기존 유효기간/크기 제한 sessionStorage 질문 초안을 보존하고 /login으로 이동한다. 빈 입력은 제출하지 않는다. 저장 실패는 해당 위치에 피드백한다. 로그인 후 질문을 편집 상태로 복원하되 자동 AI 호출은 하지 않는다.
- 비회원의 저장한 조사·비공개 자료 탐색은 해당 행동 시 /login으로 이동한다. /?view=saved 또는 sources 직접 진입도 인증이 확인된 뒤 로그인으로 연결하며 보호된 API를 먼저 호출하지 않는다. 보호 원문 직접 URL/열기에서도 실제 인증401이 확인되면 고정 /login으로 연결하고 본문에 별도 로그인 CTA를 두지 않는다. 403은 기존 접근 불가 오류로 구분하고404·네트워크·서버 오류는 해당 오류/재시도를 유지한다. 자료 목록·검색 행동의 실제401도 고정 /login으로 연결한다. 로딩/네트워크/접근 거부를 비회원으로 오판하지 않는다.
- 실제 Google 로그인 화면의 필요한 안내와 OAuth 오류는 보존한다. 네이티브 POST·중복 제출 방지·고정 callback을 보존한다. 질문 임시 보관/실패 보존, 기존 근거·조사 취소·권한·latest intent·자동 저장 흐름을 회귀시키지 않는다.

## Global Constraints

- 프론트엔드·프론트 공유 클라이언트의 오류 구분과 로고 자산 범위다. 백엔드·HTTP/API 스키마·DB·개인 세션·운영 비밀값·main은 변경하지 않는다. 실제 모델/공급자 호출을 검증용으로 실행하지 않는다.
- 기존 비공개 자료를 공개하지 않는다. 비회원 공개 브리핑 제공은 후속 게시 계약이 필요하다. 현재는 실제 준비 상태를 정직하게 표시한다.
- 기존 질문 초안 helper의 sessionStorage·30분/1500자 제한과 명시 실행을 유지한다. 로컬 스토리지는 비민감 테마 선호에만 사용하며 인증·질문을 옮기지 않는다.
- 새 라이브러리·웹 폰트·외부 이미지 요청 없이 현재 의존성과 자산으로 구현한다. 장식·설명 문구를 늘리지 않고 편집형 디자인을 유지한다.
- 사용자의 브라우저 탭을 열거나 이동하지 않는다. 독립 headless QA만 수행한다. 개인 개발 HTTPS 웹 반영과 Draft PR은 기존 승인 범위이며 main/운영 배포는 유예한다.

## 구현·검증 기록

- 구현 기준2c56571: 실제 생성 PNG를 공용 헤더와 favicon에 사용한다. 로고 원본은1254×1254 RGBA이며 브라우저에서 바깥과 중앙 빈 공간의 alpha0을 확인했다. [자산·최종 프롬프트](../../apps/web/public/brand/README.md)를 보존한다.
- 전체 웹 검사510개/26파일·eslint·workspaces 타입·생산 빌드가 통과했다. 계약 변경 검사는 통과했으며 API/DB·의존성·lockfile은 변경하지 않았다. Python 회귀는 PR CI의 합성 PostgreSQL18.6 환경에서2047개를 함께 통과했다. 전체2557개 및 린트/타입/빌드/계약 검사가 성공했다.
- 독립 headless에서320/390/1440px 비회원 홈의 양 테마·계정 메뉴 키보드/Escape/Tab/바깥 클릭·질문 제출→로그인 초안·테마 재접속·비공개 메뉴 클릭/직접URL 진입을 확인했다. 비회원 보호 자료 요청은0이었다.
- 합성 로그인 응답으로 편집 가능한 질문 복원·자동 실행0, 저장된 요약/비교·원문 인용 창·독립 원문 화면을 확인했다. 로그인 화면의 계정 확인과 로그아웃 실패 보존/성공 후 같은 URL에서 메뉴·초안 정리도 확인했다. 실제 사용자 세션이나 유료 모델을 대신 실행하지 않았다.
- 측정한 본문/보조 문구/강조/주요 버튼/오류 텍스트 토큰 대비는 밝은 테마 최소5.42:1, 어두운 테마 최소6.02:1이다. 모든 화면의 자동 접근성 인증을 의미하지 않으며 실제 주요 경로 시각·키보드 확인과 구분한다.
- 독립 작업 검토에서 로그인 페이지의 잘못된 비회원 고정과 같은 URL 로그아웃 후 상태 잔류를 찾아 회귀 검사와 함께 보완했다. 전체 변경 검토와 최종 수정 범위 재검토를 통과했다. 보호된 원문·자료 목록·검색의 실제401은 /login으로 이동하고403은 기존 접근 불가로 남긴다. 개인 개발 웹은ace770f 기준으로 반영했고 [Draft PR32](https://github.com/DigestWorks/IssueDigest/pull/32)에서 검토한다. Sites v53 요약 게시를 마쳤다.

## 남은 범위

공개 브리핑 게시/읽기·최근 이슈·개인화·중요 변화 알림·고정 공유본은 이전 계획의 후속이다. 이번 변경은 실제 공개 자료가 존재하는 것처럼 표시하거나 기존 권한을 완화하지 않는다. 질문은 로그인 후 확인해 직접 실행한다. 기기 저장 접근이 거부되면 현재 화면의 테마는 바꿀 수 있지만 새로고침 이후 명시 선택의 영구 보존은 보장하지 않는다.

## 개인 개발 웹 반영

[개발 앱](https://dev.issuedigest.projects.ai.kr/)의 사용자 전용 정적 웹을ace770f 기준으로 교체했다. 정적17파일·이전 해시 자산21개를 유지했고 외부 HTTPS에서 새 해시 자산6개와 생성 로고가 로컬 빌드와 일치했다. 홈/로그인/헬스/상태200, 비회원 세션/보호 자료401과 no-store를 확인했다. 사용자 브라우저 탭을 열거나 이동하지 않았다. API·워커 재시작, DB 쓰기, 시스템 프록시·TLS·main/운영 배포는 수행하지 않았다. 소스2c56571 이후는 검증·인계 문서 변경이다.

배포된 HTTPS를 독립 비회원 브라우저로도 확인했다. 생성 로고 로드, 홈 반복 로그인 문구 부재,390px 다크 전환/새로고침 보존, 계정 메뉴, 질문→로그인 초안과 고정 네이티브 OAuth POST 폼을 확인했다. Google 제출은 하지 않았다.

[제품 기준ace770f 전체 CI](https://github.com/DigestWorks/IssueDigest/actions/runs/38855551075)가 통과했다. [Sites v53](https://lawdigest-rebuild-plan.ijaesinii.chatgpt.site/#brand-theme-entry)은 검증 기록e065769를 요약하고 v52를 보존한다. 원문 직접 URL에서 로그인으로 연결한 경우 OAuth의 기존 고정 홈 callback을 유지하며, 원래 원문으로 자동 복귀하는 별도 의도 저장은 추가하지 않았다.

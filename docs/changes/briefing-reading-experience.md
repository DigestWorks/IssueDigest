## 개발 적용

제품bb6134f의 정적24파일을 private 개발 Nginx에 반영했다. 이전 root/자산을 보존하고 단계 전후 API PID·시작 시각·명령·cwd/설정·수집기/cron이 동일함을 확인했다. 별도 standalone worker는 현재0개로 관측됐고 그 상태를 유지했다. 이는 worker의 정상 실행을 인증하는 증거가 아니다. 질문 실행은 현재 API 경로를 유지한다. 외부 정적24파일이 새 생산 빌드와 byte일치한다.

최초 stage는 별도 worker가 있어야 한다는 도구의 잘못된 가정으로 전송 전에 중단됐다. 관측한 집합을 고정하는 방식으로 보완했고, 알려진 서버 pidfd 함수 미노출은 호환 경로/자기 프로세스 signal0 사전 검사로 처리했다. 실패 로그도 보존했다. 정적 웹 외의 API/DB/세션·키·모델 설정은 변경하지 않았으며 유료 호출0·main/운영/Actions 변경0이다.

# 질문 응답 대기 중단

2026-10-28 KST. 질문 접수 뒤 응답을 기다리는 동안 현재 화면은 입력·제출을 잠근다. 사용자가 응답 대기를 명시적으로 중단하고 질문을 보존해 다시 확인할 수 있도록 한다. OpenSpec root=null이며 초기화하지 않는다. 기존 승인된 취소·재접속·중복 실행 방지 여정을 따른다.

## Global Constraints

웹 QuestionComposer와 해당 CSS/행동 테스트만 수정한다. 기존 SSE AbortSignal과 서버 caller 취소 처리를 재사용하며 API·DB·AI·버전/권한·예약/사용량·클라이언트 parser는 변경하지 않는다. 원래 요청ID와 질문·사용자/범위 분리·로그아웃/권한 상실 정리는 유지한다. 사용자 브라우저·세션을 대신하지 않으며 실제 유료 호출은 하지 않는다.

중단은 응답 대기 연결의 중단이다. 이미 전송된 모델 호출의 취소·과금 환급·서버 작업 종료 완료를 보장하지 않는다. 새 유료 요청을 자동 생성하지 않는다. 명시 재확인은 동일 질문/동일 request_id를 사용하며 사용자가 질문을 바꾸어 제출할 때만 새ID다. 중단 직후 늦게 도착한 진행/완료/오류가 화면·이동·질문을 되돌리면 안 된다. 중단 후 질문 편집과 같은 요청 재확인을 허용한다. unmount/권한 오류와 명시 중단을 구별한다.

기존 디자인에 작은 텍스트형 중단 버튼과 실제 상태 설명만 추가한다. 반복 로그인 유도·가짜 단계/진행률·예시 결과·추가 모달/기능 홍보는 넣지 않는다. 44px/초점/키보드·두 테마·모바일을 유지한다.

## 구현·검사

현재 요청의 소유권을 먼저 해제한 뒤 AbortController를 중단한다. 같은 요청의 늦은 진행/성공/실패/finally는 무시하고 원래 질문과 요청ID를 보존한다. 중단 후 입력에 초점을 복원하며 재확인은 명시 동작만 허용한다. 질문을 바꾸면 새ID다.

집중 테스트는 최초6개 실패/기존11개 통과에서 시작했고 최종21개가 통과했다. 전체 웹930개·린트·타입·빌드·OpenAPI와 독립 검토를 확인했다. 생산 빌드 합성 브라우저320/390/1440·두 테마에서 Enter 중단·초점 복원·질문 보존·동일ID 재확인/수정 질문 새ID·가로 넘침0·페이지 예외0을 확인했다. 실제 계정의 모델 실행과 구분하며 추가 유료0이다.

정적 배포 도구는 이전 검토된 프로세스/설정 고정을 재사용한다. 추가 독립 검토에서 외부 설정 변경을 덮어쓸 수 있는 복구 경로를 보완했고 실제 복구 코드의4개 격리 시나리오를 검사했다. 현재 설정이 이 도구가 설치한 값일 때만 복구한다. 파일 비교+교체는 원자적 CAS가 아니므로 외부 동시 설정 변경이 없는 전제가 남는다.

## 개발 반영

제품10611bc의 정적24파일을 개발 사이트에 적용했다. 외부24파일이 빌드와 byte일치하고 실제 HTTPS 비회원 홈 입력·대기 중단 숨김·쿠키0/쓰기0/가로 넘침0을 확인했다. 기존 API 프로세스·명령/cwd·설정·수집기/cron과 별도 worker0개 관측값을 단계 전후 보존했다. 이는 별도 worker 정상 동작 검증이 아니며 현재 API 내부 질문 실행을 변경하지 않았다. 이전 정적 root/자산을 복구용으로 보존했다.

DB·세션·키·모델·사용량/예약·main/운영/Actions를 변경하지 않았고 실제 모델 호출0이다. 서버에서의 실제 유료 요청 중단·환급은 검증하지 않았으며 UI도 이를 보장하지 않는다. 실제 로그인 사용자의 전체 생성 완료는 별도 확인 대상이다.

# 측정 그룹 출력 · 다음 설계 제안

2026-10-21. 상태: 제안·미구현. [실제 인수](../research/shared-context-acceptance.md)에서 공유 범위 중복/미사용 보고 사건으로3건이 전체 거부됐고 반환1건도 필수 범위를 누락했다. 원래 실패는 그대로 보존한다.

## 검토 방향

모델이 임의 context/event ID와 공통·개별 범위를 동시에 채우는 부담을 줄인다. `groups`에 공통 측정 역할·범위·보고 내용과 비어 있지 않은 수치 members를 함께 받고, 서버가 순서에 따라 내부 ID를 부여하는 별도 provider 경로를 제안한다.

- 각 그룹은 동일 대상·기간·값 상태·범위·조건/목적/근거/기준을 공유하는 수치만 명시 포함한다. 서로 다른 범위/역할이면 별도 그룹이다. 범위는 그룹 한 곳에서만 받고 수치별 범위 배열을 없애 중복 입력 경로를 줄인다.
- 보고 내용은 그룹 안에 직접 넣고 별도 임의 보고 사건 ID를 모델에 요구하지 않는다. 그룹은 최소1개 member를 가져야 한다. 서버는 그룹 순서에 따라 context/event ID를 만들어 기존 순수 계약에 명시적으로 전달하며 원문·인접 문장/metadata에서 의미를 추정하지 않는다. 같은 보고 내용을 자동 합치거나 새로운 보고자를 추정하지 않는다.
- member는 현재 candidate_id와 상태 근거 문장 ID만 선택한다. 후보의 중복/합계 상한·다른 인용·정확 anchor·알려진 상태/보고 시제·분리 목적·직접 관계 검사는 유지한다. 모델 입력의 모든 역할·범위 선택이 의미상 맞는지는 별도 평가다.
- 새 raw 그룹과 서버가 파생한 공유 입력/기존 전체 frame을 함께 저장·재구성한다. 기존 v1의 거부 응답을 지우거나 새 계약으로 변환해 성공으로 세지 않는다. 임의 후처리로 중복/unused를 삭제해 원래 실패를 통과시키는 방식은 도입하지 않는다.
- 기존 단일 요청/20,000·출력2,500/무재시도·비용/실패 경계와 SDK/실제 응답은 동결한다. 새 schema/원문 전체 요청·출력 용량·합성 검사/독립 검토 후 새 사전 기준으로 의미 인수한다. 그룹 수·member 합계·관계 상한과 ID 생성 규칙은 구현 전에 확정한다.

대가: 범위가 다르면 그룹이 늘어 공통 역할/보고 내용이 반복될 수 있다. 기계적 ID 오류가 줄더라도 범위/상태의 의미 오류를 해결한다는 보장은 없으며 새 계약·출력 용량 검증이 필요하다. 이번은 설계 제안만이며 앱/생성 코드는 바꾸지 않았다.

이번 관측은 고정된 기존 snapshot의 소표본이며 최신 모델 전체의 한계나 새 계약의 필수성을 입증하지 않는다. 구현 전에 같은 계약의 모델 비교와 계약 단순화의 비용/효과를 구분해 검토해야 한다.
